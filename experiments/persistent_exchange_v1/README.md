# 持久化双向记忆交换实验 v1

> 发布范围（2026-11-06）：本分支公开报告、代码、聚合统计和科研图表。新增商业模型的逐条输入/输出、来源记忆及运行记录尚未纳入发布，等待具体公开授权。报告中的完成数量指本地实际实验，不表示原始材料已全部公开。


本目录保存 2026-11-05 本轮实验的代码快照、合成夹具与离线测试。源端和接收端分别由真实 WorkBuddy HY3 与 DeepSeek Harness Flash 执行；当前实验的记忆存储由项目拥有的独立 SQLite 数据库实现，不是商业应用私有记忆库的直接互通。

本轮有 12 个独立合成项目、两个方向、四种方法，共 96 个主条件。合法任务得分按项目等权为：合法原文 100%、整体删除 20.83%、全部重建 86.46%、固定分块选择性重建 77.72%。当前固定来源 ID 哈希分块未达到预设优势门槛；拟议的权限变化与语义联合分组 D1 没有在本轮接受检验。96 个条件和 768 条回答不能作为 96 或 768 个独立统计样本。

## 从公开材料复算

[公开结果包](../../benchmarks/persistent_exchange_v1_public_20261105/README.md)包含合成来源、冻结评分参照、96 份真实回答及接收正文、132 次源尝试的公开投影、完整核心评分和审计汇总。原始客户端历史、凭据、队列租约、SQLite 数据库和供应商私有传输目录不在公开包中。

在仓库根目录使用 Python 3.11 或更新版本运行：

```sh
python -I -B -S scripts/export_persistent_exchange_public.py --verify
```

该命令使用标准库和本目录未改动的 `evaluate.py`，逐字段核对核心评分、每题/每项目结果、资源指标及配对项目 bootstrap 区间。它不登录客户端、不访问网络、不调用模型，也不重新证明未公开的原生执行记录。来源工具合规的配对补充分析是原本机审计的公开汇总，不冒称在公开包内重新执行了原生审计。

## 离线机制与模拟回归

公开测试入口从仓库根目录执行：

```sh
python -I -B -S scripts/run_persistent_exchange_offline_tests.py
```

入口按完整模块名加载并按测试 ID 去重；不要直接使用 `unittest discover -s experiments/persistent_exchange_v1`，这些测试采用包内相对导入。公开入口阻断真实原生模型、SDK 调用、网关和出站网络，仅允许固定的标准库接收库读取程序启动 Python 子进程。实际 SQLite 机制与明确标注的 MOCK 模型结果分开验证，MOCK 不替代本轮真实模型证据。

发布审查时，以下七个核心模块在 Windows 上独立完成 74 项离线测试，全部通过：

- `test_store`：授权、原始依赖、不可变交付、原子导入和重放拒绝。
- `test_data`：合成数据、来源隔离、冻结分母和预先固定的分块。
- `test_evaluate`：项目等权、失败分母、保密值精确命中和费用未知值。
- `test_read_receiver`：真实关闭重开、只读 SQL 和独立读取子进程。
- `test_source_registry`：原始失败证据保留和一次恢复的严格登记。
- `test_source_registry_audit`：历史登记后出现的额外产物仅作审计、不换入交付。
- `test_security_probes`：权限检查及真实批准交付包副本上的隔离攻击。

其他恢复与原生接收封装测试使用模拟接口。公开测试入口对本机执行器路径、外部 helper 和账户目录的模拟适配不修改已封存的实验源码；最新完整组合测试结果以相应 CI 或测试输出为准，不把单独的通过结果相加冒称一次全套跨平台运行。

## 原生执行的环境边界

原生驱动代码按产生本轮记录时的字节保存，仍含原机器的 Python、Node、WorkBuddy 安装位置和配置目录默认值。这些默认路径不是凭据；账户文件、会话原始记录及其内容不随源码发布。不能把当前快照称为通用平台上的一键原生复现。

真实重跑需独立准备并重新验证：

1. 官方 WorkBuddy 5.9.3 与已经登录、具备相应 HY3 权限的账户。本轮后续付费线路为 `hy3-x`，原始模型 ID 和模型族分开记录。
2. 官方 DeepSeek Harness 0.2.1-rc.3 的 SDK/客户端与合法登录。Flash 适配器的用量字段与该版本绑定。
3. 与当前仓库同级、独立合法获取的 `codex-workbuddy-gateway-windows`，包括原生 RPC 适配器、创建源会话的 helper、付费零工具接收 helper 及已安装应用模式核验 schema。
4. 当前目录之外的本项目依赖：`experiments/revocation_grouping_v1/lifecycle_host.py`、`sdk_adapter.py`，以及 `memory_migration_study` 中的 SDK、原生协议和权限模块。
5. 新的本机路径配置、独立资格会话、明确的模型调用预算和全新运行目录。原始 `results/` 中的资格 envelope 不能由公开汇总伪造替代，也不能通过重置历史意图或预留状态来自动重发未知请求。

外部 gateway 的 `UPSTREAM.md` 对其上游授权边界有说明；本研究发布不复制或重新授予该项目、商业客户端或其 `dist` 文件的许可证。外部 helper 的存在与合法取得是实时运行条件，不是公开重评分条件。

配置或代码发生变化后，应建立新的冻结与资格记录。不要修改原有实验的哈希、回执或源结果，使其看起来符合新环境。fresh run 的随机模型输出不应被期待与本轮逐字节相同。

## 结论与证据范围

- 首次交付边界是接收 SQLite 的导入提交；本机可信权限库与控制器是前提，不主张撤回已经被对方看到的明文或证明跨主机分布式原子性。
- 当前完整输入依赖是保守来源边界；源模型读取的是经核验的原始事实投影。不能把它表述为已解决任意模型内部知识的完整溯源。
- 精确保密值零命中不是所有语义推断泄漏为零，也不是统计学上的普遍安全证明。
- 源初始产物先形成不可变文件，派生行在撤权后的交付阶段进入 SQLite；不声称初始派生行早于撤权登记入库。
- 132 份源结果记录包含失败和恢复；98 次接收端外层尝试对应 96 个最终有效条件。本地回核不计为新模型调用，另一次未采用的原生续跑独立列账。
- WorkBuddy 实际扣分与供应商物理调用数保持未知；Flash 价格估算不是供应商实际账单。不能根据公开汇总宣称总金额优势。

公开包支持无需 API 的重评分与结果检查；完整原生执行审计仍需未公开的本机账户/执行相关证据。原生 API、账单、系统提示和第三方应用内部行为的可观测边界在结果包中继续保留。
