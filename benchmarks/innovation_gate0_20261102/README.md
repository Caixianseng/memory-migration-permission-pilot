# Gate-0 与完整消息强基线：公开元数据复算包

日期：2026-11-02。本包包含固定开发诊断的匿名数值、用量和哈希，不含来源原文、个人资料、问题、参考答案、模型回复、账户信息或原生请求正文。

## 可以复核什么

- `gate0.json`：4个已知开发故事、8次历史合法完整原文调用的长度、输入限额和既有整次调用usage；最高完整请求8068字节，低于本实验适配器24000字节上限。
- `role_baseline.json`：同4故事在真实32768字节记忆文件上限下的两种完整消息选择策略；每臂保留24条消息，4故事两臂载荷哈希均相同。
- `reproduce.py`：检查`seal.json`中的文件哈希，并从匿名数值行重算上述计数、长度极值与声明的一致性。

## 运行

在仓库根目录执行，Python标准库即可；不需要模型账号或额外依赖：

```console
python -I -B -S benchmarks/innovation_gate0_20261102/reproduce.py
```

脚本只读本目录文件，输出JSON摘要，不联网、不写文件、不调用模型。封存哈希支持文件一致性检查，不是签名、外部真实性认证或防管理员篡改证明。

## 复核边界

这是**计数及元数据一致性复算**，不是语义结果复现：没有原文就不能重新核查消息引文、说话者归属、来源真实性、授权正确性或回答效果。引用完整率是原诊断记录，本包只能检查其分子分母一致，不能独立验证原文引用本身。

`whole_call_vendor_usage`是供应方既有回执中的整次调用用量，包含其他请求上下文，不能当成单独记忆文本的token数。独立记忆token仍为`null`，没有按字节估算。Token用量不是账单或已结算金额。

两种选择策略的完整保留与相同载荷，不表示模型答对、论文方法有效或新颖。当前四故事完整原文能够放进既有真实请求限制；这不能推导更大工作负载永远不需要压缩，也不能通过人为调低上限创造已证实的自然容量瓶颈。

实际适配脚本`experiments/source_role_baseline_20261102/adapt_existing.py`依赖项目本机的固定来源投影与冻结材料；私有载荷只在本地results目录中。**全新克隆仅能运行本公开计数复算与选择器工程测试，不能据本包重跑私有适配诊断或真实客户端模型实验。**

角色基线只使用冻结开发授权参照，不进行在线身份认证；真实交付仍须主机核验当前权限。本包不提供原生会话重放、供应商隐藏上下文证明或普遍安全保证。
