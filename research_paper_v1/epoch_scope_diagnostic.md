## 研究判断

原宿主采用全局 epoch，在任何权限/来源登记更新后拒绝旧封装。这满足其原有保守合同。若换成更细的“本次交付所依赖的来源与接收方授权在整个区间内保持有效”合同，存在可减少的合法拒绝。**本次只诊断差异，未实现替代算法，不把更细合同偷偷替换为旧实验判分规则。**

## 实际运行

在仓库根执行：

```powershell
& 'D:\python3.11\python.exe' -I -B -S -X utf8 experiments/paper_v1/epoch_scope_probe.py --output research_paper_v1/evidence/epoch_scope_probe.json
```

退出码 0。7 个手选合成边界案例，4 个按新诊断合同仍可交付，其中 3 个被旧宿主拒绝；3 个不应交付的案例均被拒绝。它们不是 7 个独立随机项目，不估计生产发生率。

| 事件 | 当前来源/授权检查 | 原宿主导入 | 更细合同下是否允许 |
|---|---|---|---|
| 没有变化 | 通过 | 允许 | 是 |
| 另一接收者的授权变化 | 通过 | 拒绝旧 epoch | 是 |
| 无关来源更新版本 | 通过 | 拒绝旧 epoch | 是 |
| 相同授权集合重新写入 | 通过 | 拒绝旧 epoch | 是 |
| 相关授权被撤销 | 不通过 | 拒绝 | 否 |
| 相关授权先撤销再恢复 | 通过 | 拒绝 | 否，旧尝试不可复活 |
| 相关来源更新版本 | 不通过 | 拒绝 | 否 |

## 可迁移技术与最近邻

普通读集版本校验、相关授权的单调撤销代数/代次，以及事务内最终核验可以作为工程候选。仅重新检查当前允许集合不能保持撤销后恢复时“旧尝试仍失效”的合同。

但 [When Evidence Changes，附录 A](https://arxiv.org/html/2610.03902v1#A1) 已明确逐节点读集校验，并包含无关写入不阻断提交的 H2 检查。因此，全局 epoch 改为读集这一点不构成我们的独立学术新增。论文中的门控也明确不检查事实支持或来源权限；若继续探索，须与“普通读集验证＋相关授权代次”组合强基线直接比较，而不是仅与保守全局 epoch 比较。

结论：**可列入工程改进清单，暂不列为论文主创新，不据此扩增付费模型实验。**
