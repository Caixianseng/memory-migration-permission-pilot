# 跨域算法迁移与路线取舍（2026-11-05）

> 发布范围（2026-11-06）：本分支公开报告、代码、聚合统计和科研图表。新增商业模型的逐条输入/输出、来源记忆及运行记录尚未纳入发布，等待具体公开授权。报告中的完成数量指本地实际实验，不表示原始材料已全部公开。


本轮的最直接结果是：成熟图可达性可以可靠完成完整依赖 DAG 的撤权传播，但它与现有依赖集合求交等价，尚未产生研究增量。迁移成熟算法可以是工程方法，论文贡献仍需来自新的问题边界与对照证据。

## 四条路线与可迁移部分

| 路线 | 传统领域方法 | 本项目接口 | 当前能确认什么 | 必须避免的主张 |
|---|---|---|---|---|
| A 动态撤权 | 访问控制、污点/依赖传播、事务提交 | 来源依赖 + 当前权限 → 交付/拒绝 | NetworkX 在完整 AND DAG 上与 oracle 一致；已有 SQLite Host 可继续复用 | 把闭包、版本检查、提交核验本身称新算法 |
| B 部分可观察来源 | 有限模型检查、SAT/SMT 反例诊断、补证查询 | 可见证据 + 明确的可能世界约束 → 必然允许/必然拒绝/歧义 witness | Z3 源码/许可核验完成，运行资格未过；尚无诊断效果实验 | solver 能自动恢复未建模渠道、模型自报等于真实因果 |
| C 增量失效 | 数据库 IVM、物化视图维护、反向索引 | 关系化来源/权限变化 → 受影响项 delta | DBSP 理论与现代代码存在；当前仅静态审查 | 缓存/增量重算即创新；自由文本天然服从关系差分代数 |
| D 生命周期验证 | 状态机、差分测试、property testing、shrinking | 事件序列 → 最短反例与受测契约覆盖 | Hypothesis 角色明确，但未运行；现有测试仍需按资产审计核实 | 测试工具等于研究算法；生成样例等于全称证明 |

## 优先迁移什么

**近期优先使用 L1 单 Host 事务与现有来源绑定，L2 NetworkX 作为独立可复核图基线。** 这两项最小、接口明确，不需要重建 Agent 框架。对于原始来源并集已完备保存的场景，保留原有集合求交即可，NetworkX 主要提供独立实现交叉验证。

如路线 B 经相关工作审查仍有空间，可考虑用成熟反例诊断思想建立“相同可见证据、两种真实状态”的成对案例，强制系统指出缺失的证据，而非把缺失静默填为允许。此时 Z3 可以产出两种合法 completion 的可审阅 witness，后续补证只针对两模型分歧项。**这是待验证问题及工具适配建议，尚未实现的新算法，更没有优势数据。** 简单有限域枚举应是同等信息和预算的强基线；若集合规则已能分类，就不使用 solver 增加复杂度。

若两个现实世界在系统可见输入上完全一样，但正确交付标签不同，任何只依赖这些输入的确定性判定器都不能同时正确。增加模块不会自动越过这个信息边界；必须允许拒绝、声明歧义或取得新证据。闭合世界、可枚举来源域和可验证补证都需写成假设，而不是当作商业平台已具备的事实。

## 本轮资格如何影响研究判断

NetworkX 的 3200 个查询是 100 个合成图内的计算一致性检查，不是 3200 个独立项目，不进行项目级显著性检验，也不用于声称泄漏率 0。删边负对照说明只要来源图不完整，正常可达性也会漏报；它并没有测量真实 Agent 的语义泄漏。Z3/Hypothesis 没有运行，因此没有任何 witness 成功率、缩减率、Host 状态机覆盖率可报告。

DBSP 适合在关系化规模和更新频率使全量重算明显受损后再接入。当前额外 Rust/编译器维护与授权语义适配，容易挤占两名硕士的验证时间。Cedar 适合复杂 ABAC、实体层级和策略分析的对照；若实验仍是逐来源允许/撤销，集合 ACL 是更公平、成本更低的基线。

## 下一步最小开发契约

1. 从现有受控 Host 抽出不可变“可见证据/真实读取/当前权限/提交结果”数据契约；商业端不可见字段单列 unknown，不能猜补。
2. 用现有来源并集 + 集合判断建立完整证据 oracle，并用已运行 NetworkX 作独立一致性对照；先定位缺证差异，而非替换正确旧代码。
3. 只在获得新的可核验证据会改变判定的场景上设计路线 B pilot；人工设定缺失世界只能作为受控 Ground Truth，不称商业端真实观测。
4. 路线 D 后续环境恢复后再运行 Hypothesis；保持其“检验契约”的工具定位。路线 C 不以引入 DBSP 为阶段验收目标。
5. 若同信息强简单基线达到相同安全与效用，收缩或更换问题；安装库和通过工程资格不能抵销负结果。
