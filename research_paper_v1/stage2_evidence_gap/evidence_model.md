# 证据模型与安全合同

> 发布范围（2026-11-06）：本分支公开报告、代码、聚合统计和科研图表。新增商业模型的逐条输入/输出、来源记忆及运行记录尚未纳入发布，等待具体公开授权。报告中的完成数量指本地实际实验，不表示原始材料已全部公开。


日期：2026-11-05。本文件依据第二阶段用户指令、第一阶段审计及原 `persistent_exchange_v1/store.py` 接口建立。性质：资格试验的规范，先于结果判读；不是新算法、商用平台内部可观测性或全局安全证明。具体运行参数、代码版本与实际覆盖以本阶段配置和原始输出为准。

## 1. 研究对象与可证明边界

研究受信本机 Host 控制下，一次派生记忆在**首次交付提交前**的证据资格。原始来源仍正确但接收者许可变化、记录丢失/损坏、可用性变化均可发生。保护合同采用保守输入使用规则：旧产物的所有受控历史输入必须符合此次交付要求，不能仅凭存在某个合法替代支持集合追认旧产物。合法来源重新生成的是新产物、新尝试。

“受控生成提供过/读取过的来源”“文本的必要因果支撑”“事后重现同样答案的来源”分别处理。当前资格不推断任意自然语言因果，不证明语义泄漏为零，不覆盖商业 Agent 隐藏提示、历史上下文或未中介读取。

### 三类证据

- **Expected Evidence，E**：由独立实验生成清单、可信输入边界记录或可信宿主任务计划确定的预期证据义务。它说明应有哪种记录，不能来自模型自报引用。
- **Observed Evidence，O**：Host 在指定观察边界内实际获取并留存的记录；保留缺字段、冲突和重复原件。已收到不等于已验证，缺少记录不等于事件未发生。
- **Supplemented Evidence，S**：本次合法补证操作新取得的记录，包括可信历史回执、独立审计、仍授权来源的当前读取或可确定性重算证据。必须标记证据种类与适用的时间/产物范围，不能统一视为历史来源证明。

评分器独占的完整生成轨迹记为 G。各方法收到相同公开投影 P、O、权限事件、操作目录与预算。P 可以包含受信的预期义务 ID 和绑定信息，因为研究的是清单已知后的缺证；**不能一方面把完整 E 给方法，一方面声称发现了未知隐藏来源**。对于不在可信观测范围中的渠道，G 可以在受控测试中知道其存在，但该信息不投喂方法，其方法状态仍为 UNVERIFIABLE。

## 2. 记录身份与来源链

建议证据义务键由以下字段共同决定，而不只用裸来源 ID：

`(artifact_id, generation_attempt_id, source_id, source_version, evidence_kind)`。

记录可附 `source_digest`、`artifact_digest`、`recorder_id`、`receipt_id`、`event_position`、`permission_epoch`、`coverage_scope` 与获取时间。字段是否真实存在由接口决定；缺字段保留 unknown，不伪造签名。若使用本机可信数据库而没有公钥验签，表述为“可信存储记录”，不能称密码学签名验证。

多层派生沿记录的父版本递归展开；同一来源由多个产物共享时，不同尝试/版本绑定仍须正确。可共享的是**同一可验证命题**的证据，不能把 A 尝试的回执挪给 B 尝试。图闭包正确不保证所有真实输入已被记录，完整性条件由可信边界承担。

### 本轮冻结实现的具体绑定

`dataset_v3.json` 与 `code_freeze_v4.json` 把上述义务拆为两层可信记录。根来源 acquisition receipt 绑定项目输入批次、来源 ID、版本、摘要和历史读取类型，并包含来源正文副本；不同节点可以合法引用同一次 acquisition。每个派生节点另有唯一的 `node_receipt`，绑定节点/尝试 ID、产物摘要、直接 acquisition 引用，以及父节点的 ID、版本与产物摘要。验证器展开这些引用，检查展开后的根集合与可信清单一致，不能用单条项目级来源回执代替各节点的执行记录。

节点产物由该节点的直接输入正文及父节点产物通过声明的确定性函数生成；没有一个隐含的“读过全部来源的模型上下文”。这使按节点区分输入成立，但结论仅覆盖受控数据流，不能外推为对任意 LLM 文本因果依赖的恢复。主实验提供全部节点回执，在多层图上注入根来源回执缺项；中间节点回执缺失只属于边界探针，不能把主实验的 `multilayer_missing` 解释为全面测试任意中间血缘断裂。

来源 ID 别名仅按受信 alias 表规范化。模型猜测两个相似名称是同一来源不允许进入安全判断。完全相同的重复记录可以幂等去重；相同键而绑定不同的记录必须保留冲突证据，不能采用“最后一条覆盖”隐藏问题。

本轮冲突的权威关系明确：Observed 是可能损坏的缓存副本，独立 canonical receipt 数据库是每个键唯一的可信历史记录。合法重新取回该权威记录并复核全部绑定与正文摘要，可以解除缓存冲突；所有补证方法具有同一能力。初始冲突仍留在诊断与日志中。该场景不包含两个同等权威出具者之间无法裁决的矛盾；不能据此宣称解决一般证据冲突。

## 3. 状态采用独立维度，避免强行互斥

| 标签 | 严格含义 | 不应混淆 |
|---|---|---|
| VERIFIED | 所需类型/身份/绑定/完整性证据充分，且相关权限与版本在最终检查有效 | 不是“有一条记录”或“哈希格式正确” |
| MISSING | 可信独立清单证明某义务应存在，但在已声明完整覆盖的观测集合中找不到该项记录 | 不表示来源被撤权，不包括未被可信清单覆盖的隐藏渠道 |
| REVOKED | 可信权限状态或相关撤销事件证明对应权限已失效 | 不表示记录丢失；存在完整历史回执也不能复活权限 |
| CONFLICT | 相同义务存在不一致的身份、内容/版本绑定、签名/校验结果或矛盾记录 | 无效但存在的记录不能简单改称“从未记录” |
| UNVERIFIABLE | 缺少可信覆盖边界、可接受绑定或可获取的判定信息，当前不能决定 | 不自动归类为MISSING，更不能作为VERIFIED |

这些标签是可共存的诊断维度。例如某预期回执缺失且来源已撤权，可同时记录 MISSING 与 REVOKED；交付决定仍拒绝。方法可以另输出一个展示用主状态，但必须保留全部原因，不用优先级覆盖来提高定位分数。

原始缺项集合为 `E_visible - keys(O)`，其中 `E_visible` 是方法依法可见的受信清单。无效记录集合和冲突集合分别计算。若先将无效记录从 O 删除再做差集，应称“未满足义务集合”，不能报告为纯粹缺失定位。所有方法共用规范化、可信性和冲突检查，避免把基础验证能力只给候选方法。

当前版本与历史版本也分开：历史回执正确可能仍对应过期来源；当前重新读取也可能缺乏旧产物的历史绑定。至少记录 `current_version_valid` 和 `historical_binding_valid` 两个事实。

## 4. 补证操作及其作用

每个操作公告可请求的证据义务/类型、所需权限、已知固定开销或估价及接口限制，实际返回成功、缺项、失败或未知时再记入 O∪S。除非调用前存在可验证状态，目录不能泄漏评分器中的真实成功率或实际可用性。

| 操作 | 可以增加的证据 | 不能推出 |
|---|---|---|
| 读取可信历史工具回执/审计分片 | 过去某尝试、输入与产物的可验证绑定 | 当前仍有授权，或未记录渠道必然不存在 |
| 当前合法来源重新读取 | 当前内容、版本、访问结果 | 旧产物曾读取该来源，或未读其它来源 |
| 获取来源签名/权威记录 | 该记录被相应权威出具及其绑定 | 签名之外的来源完整性、当前新鲜度 |
| 人工确认 | 明确范围内人类确认的事实，附身份/时间/依据 | 通用真值；未经实施不能报告实际审核时间 |
| 确定性重算 | 给定输入与代码版本的新产物和新执行证据 | 旧执行历史被改写；LLM重生成不是确定性重算 |

原始来源不可重读但合法可信历史回执仍可取得时，是否足以交付取决于合同是否仍要求当前来源状态与有效版本。不得把“当前不可读取”一概等同撤权，也不得假设回执可以绕过当前权限约束。

### 操作前授权与批量读取

Host在加载受保护内容/证据正文**之前**检查相应读取授权。批量接口应仅返回获准行，或按公开接口契约整体拒绝；禁止先读取全部敏感行再在客户端过滤。已撤权来源的历史证明即使可合法查看，也不能授权旧内容交付。

冻结运行器在 SQLite 中先查询当前权限，再读取回执载荷，能够检查串行调度和预定注入点上的撤权。但这两个 SELECT 没有共同事务，因此仍存在真实并发撤权落在两者之间的窗口。本轮不把这段实现称为并发读取的原子授权，9 项边界探针也不是全面 TOCTOU 证明；生产读取要另行建立并验证原子授权边界。

每个成功、失败与部分成功操作都进入成本账本。取得新证据后重新检查其绑定，而非仅依据目录声称覆盖。未成功覆盖的义务继续存在，不用预期覆盖充当实际补证。

### 版本与提交

补证期间可发生权限变化。最终提交应在受控原子边界内重核相关权限、来源版本和尝试状态；若采用原宿主全局 epoch，必须保留其保守拒绝语义。任何更细粒度版本合同单独披露，不改旧实验规则。

相关来源曾撤权再恢复时，已封存旧尝试不自动复活。新授权可以允许新的读取、补证或生成，但需要新的可验证尝试绑定。记录当前允许值相同不能抹去中间撤销。

冻结运行器的最终交付使用 `BEGIN IMMEDIATE`，在同一 SQLite 写事务内重查相关权限、来源版本与本次快照 epoch，再写入提交记录。撤权和撤权后恢复的探针在补证后、提交前顺序注入，验证旧 epoch 的此次尝试被拒绝；这支持本机 SQLite 的交付提交边界，不证明跨平台交付与商业 Agent 内部使用原子化。主矩阵没有途中并发事件；`stale_permission` 测试旧缓存权限与已更新权威状态的分离。

## 5. 最终交付判据与评分真值

每条记忆单独判定：所需证据均已验证、没有未解决冲突/不可验证渠道，相关来源及授权满足最终合同、尝试未失效、nonce/接收者等已有交付约束成立，才能允许。另一个产物不可判，不应无故删除不共享该问题的合法产物。

G用于评分时生成两类独立标签：真实是否越权；在声明证据/接口范围内是否有合法恢复路径。后者不能由被测方法自己的成功结果定义。预算不足与天然不可恢复分别报告；低成本方法少恢复不能被记为便宜且同等功能。

只把已恢复且通过核验的产物计入合法恢复。系统拒绝、返回无正文和模型拒答不是同一结果。本阶段无模型问答，评价的是受控记录级交付，不报告语言任务准确率或一般语义泄漏率。

本轮 `source_reads=0` 仅指没有从原始来源库重新读取正文。补证回执包含正文副本，回执查询仍发生内容访问、字节传输和摘要校验，必须单列 receipt 查询/返回行/实际序列化字节；不能把该字段解读成“没有重新读取任何来源内容”。人工审核未实施，时间为 null；付费模型调用为 0，商业内部成本未知。

## 6. 对真实Agent约束的定位

本阶段可实测的约束是：历史生成绑定与当前读取不能互换；异构接口证据覆盖和权限不同；多层/共享来源需要按尝试和版本去重；撤销在补证与提交间发生；部分渠道永久不可观测。它们使实验合同更具体，但并不自动建立独立创新。若标准集合、批量查询、读集检查或加权集合覆盖已满足该合同，应报告成熟方法足够。
