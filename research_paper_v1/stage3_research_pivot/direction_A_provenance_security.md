# 方向A：部分可观测来源的可信性资格

> 发布范围（2026-11-06）：本分支公开报告、代码、聚合统计和科研图表。新增商业模型的逐条输入/输出、来源记忆及运行记录尚未纳入发布，等待具体公开授权。报告中的完成数量指本地实际实验，不表示原始材料已全部公开。


日期：2026-11-05。使用nature-academic-search与scientific-brainstorming。独立初判先于检索保存在 [A_independent_brainstorm.json](evidence/A_independent_brainstorm.json)，文献核验字段与访问失败见 [A_literature.json](evidence/A_literature.json)。

**方向结论：来源自报不足是真问题，但本轮没有找到超出传统完整中介、可信输入包络和按执行上下文传播标签的新算法缺口。方向A目前不通过新算法开发准入。** 可保留为所有方向必须遵守的信任边界与测量条件。

## 1. 统一比较合同

| 比较项 | 本方向的具体定义 |
|---|---|
| 研究对象 | 同一次生成尝试的文件、SQL及工具结果输入，及其随后首次跨Agent交付的来源绑定 |
| 真实问题 | 自洽来源图与正文哈希只证明提交材料内部一致；证明实际输入范围需要可信观测。现有工程已明确隐藏上下文不可见，而不是已有完整生产捕获 |
| 攻击者能力 | 扩展威胁模型：产物生成方可伪造/省略声明、提交另一尝试回执；不能改可信Host事件、权限库和接收端。原store将调用者列为可信，本轮故障注入刻意改变这个前提 |
| 安全目标 | 保守输入使用策略：当前尝试接触的输入，其共享许可均须允许接收者。它不等于某句的必要因果来源或禁止推断所有秘密 |
| 现有方法 | 完整中介、可信provenance capture、保守taint传播、上下文敏感标签、来源认证与参考监控器 |
| 最强基线 | 可信Host按attempt收集输入包络，并在覆盖不完整时保留UNVERIFIABLE；与相同当前权限检查组合 |
| 失效条件 | 未经中介的通道不在Host观测内；或可信记录者被破坏。集合、签名及优化器本身不能从相同观察区分相反隐藏历史 |
| 唯一机制候选 | 按生成尝试绑定跨工具输入包络；检索与实验均表明它属于已有上下文敏感跟踪适配，目前不命名为原创机制 |
| 区分实验 | 9个手选场景，同一可见输入分别给现有store接纳接口、进程级包络、attempt级包络；独立实际读取轨迹评分 |
| 停止条件 | 成熟attempt级基线已安全处理所有可观测场景，剩余差别依赖无法取得的真值；或只能击败自报/删检查对照 |

本轮产物是固定的受控文本，任务功能指对象交付可用性；没有模型生成、语义影响测量或语言问答，因此不报告“零语义泄漏”。跨工具local_tool是本地回调夹具，不能当作调用了真实远程API。

## 2. 现有工程证据与没有证明的部分

代码位置均相对仓库根，数字为当前文件一基行号：

- `experiments/persistent_exchange_v1/store.py:217` 的add_memory接收调用方提供的source_ids；`:223`查询这些已存在来源并固定版本摘要，`:230`展开父依赖。它不会从任意产物文字推断隐藏输入。这是明确的可信调用者边界。
- `store.py:122`将额外provenance压成摘要；它不把模型自述转成可信工具观测，也没有凭该摘要证明完整性。
- `store.py:453`的lineage验证会校验声明图闭包；`:485`封装与`:510`导入对声明来源做权限、版本、封印及事务检查。自洽图内没有出现的真实输入，无法由图闭包发现。
- 更高层原实验并非任由模型编写来源：`experiments/persistent_exchange_v1/run_mechanisms.py:145`构造冻结sources与实际父对象的业务输入并核对输入哈希；`:282`与`:316`由控制器传入初始/重建source IDs。`finalize.py:397`核对source_actual_input_ids，`:1084`说明模型读的是控制器投影的sources.json，而不是直接到SQLite检索。
- `finalize.py:1089`至`:1091`明确商业内建记忆迁移及WorkBuddy完整远端请求证明未完成；审计只涉及外层产物、显式Read/Write、读取工具回执与可获得命令足迹。`:1140`将额外未批准工具访问定义为协议失败，而非自动接受其来源声明。

因此，本轮发现的store API漏报接受**不是既有论文威胁模型内的真实安全漏洞，也不是已经发生在商业Agent中的事实**。它回答“若把原可信调用者换成不可信来源申报者会怎样”。原有12项目仍有控制器业务输入包络；本轮没有证明其隐藏平台输入完整，也没有发现历史日志中确定漏读的一条秘密来源。

|---|---:|---:|---:|---:|
| 原store声明入口 | 5 | 0 | 8 | 0 |
| 传统进程保守包络 | 0 | 2 | 1 | 2 |
| 传统attempt保守包络 | 0 | 1 | 2 | 2 |

三种方法共27记录，9个手选场景不构成随机独立项目，不估计真实系统攻击发生率，不做P值。原store信任调用者，而扩展威胁允许调用者说谎，所以5次误放是信任前提诊断；不能将其声称为创新算法战胜完整强基线。

A08/A09的可见view经实际相等断言，完整truth安全标签相反。拒绝A09的功能损失在此观察信息下无法由选择更聪明的来源恢复算法消除；必须增加合法可观测性、改变合同或保留不确定性。未知不等于缺失。

全部7个可观察场景中attempt级成熟基线无误放/误拒。进程级误拒只说明需要已有的上下文隔离；不证明新的Agent因果归属算法。所有实际输入接触按保守合同处理，没有声称读取某输入等于其为自然语言必要因果支持。

## 6. 反方审查与方向处置

独立初轮曾预测“按attempt包络能减少进程过度污染”；实验支持该工程差别，但对照传统上下文敏感跟踪已能解释全部收益。不能把同进程不同任务当Agent独有的新问题。FORGE和CONTINUITY的直接近邻进一步否定“首次把来源、任务和交付连起来”的宽泛主张。

未能解决的部分是可信观察边界本身。若商业平台不能提供真实完整工具轨迹，只能研究可见边界和不确定性；把模型解释当真值会使评价失效。当前没有独立证据证明平台内真实存在且现有成熟方法无法处理的新失效类。

方向A的后续必要条件是一个**现实可复现、具有独立输入真值、在标准完整中介/attempt包络下仍失败**的约束或功能缺口。没有该证据时，不开发新的来源可信性算法；保留输入记录规范作为其它方向的实验底座。
