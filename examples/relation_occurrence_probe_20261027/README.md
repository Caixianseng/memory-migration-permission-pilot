# 关系与出现位置小型开发 probe

日期：2026-10-27。仅新写 12 条合成开发正文，英文、中文各 6 条；每条应用 strict_customer_relation 与 any_specific_organization 两个已冻结 profile，每臂 24 cells，其中 22 个确定参考、2 个 strict 未知待审。它不是正式独立 64 题，不用于一般 P/R 或算法创新声明。所有名称与写法均在本任务中新写；未读取未开放 fresh64/heldout 或旧 gold，未复用旧 16 条文本、名称或参考。

## 输入与评分严格隔离

- runtime.json 仅含 schema_version 和 texts 字符串数组，没有 ID、题型、答案、候选、允许事实标记或参考位置。真正 detector 输入仅为当前正文、宿主可信 policy，以及相应实验臂自己产生的候选；实际 runtime 不能读取 evaluation.json 来裁剪或补齐候选。
- evaluation.json 仅由预测关闭后的独立 scorer 读取，以 text_index、正文哈希和 runtime 文件哈希关联；包含两 profile 的 decision、精确完整组织名 start/end/category、仅供出口评分的 must_mask_values，以及一个 allowed_fact 槽。所有位置是 Unicode code-point 的零基半开区间，引用不含外部引号。
- allowed_fact 是正文中真实出现且不带组织名的格式/材质事实句，每文恰一槽。它只用于实际可发送载荷的精确子串保留率；不能作为模型提示、提取候选或下游问答答案输入。它不证明回答效用。
- must_mask_values 也只是关闭后评分参考，禁止把它注入 runtime registry、候选词典、prompt、labels 或 NLI hypothesis。独立可信 registry/签名标签的实际配置由实验宿主冻结，不从答案反推。

## 可见语义和覆盖

每种语言各覆盖客户与非客户混合、肯定历史但当前非客户、明确从未客户、具体组织关系未知、纯角色泛称、同词的组织名与普通用法。中英文独立撰写，不是逐句翻译。每文真实具体组织不超过两个；这不保证系统候选数不超过两个，超限必须按预冻结策略处理并保留损失，禁止读 gold 后筛选。

strict 只保护可见文本明确肯定为本业务客户、client 或 buyer 的具体组织，当前及肯定历史均保护；纯 not/never 证据可不标 CUSTOMER。已出现组织但客户关系缺失时必须 needs_review，空跨度不算安全阴性。broad 保护任何具体组织全名，不要求客户关系。泛称、类型、定义及普通词普通用法不因词形成为组织名。not_sensitive 不是公开或整体安全分类。

## 同词位置和出口保护是两种评分

同词材料只在组织名的实际出现位置给实体跨度；另一普通位置不属于精确实体 gold。相应登记名同时是必须保护的完整原值，因此现有同值传播可以在最终出口把相同普通词也遮蔽。不能用“普通位置应不标实体”要求放宽原值出口规则。检测位置 FP、准备层同值传播、实际可发送载荷中的原值漏泄和整条待审损失应分别报告。

主实验是合法本地主体读取记忆，而云端模型按策略只能收到代号；仅本地构造并审计拟发送载荷，不要求任何客户端/云调用。未知错误放行另计，不冒称已确认敏感原值泄漏；无可发送载荷时条件保留率写 N/A。正确未知待审也不计为有效载荷交付。
