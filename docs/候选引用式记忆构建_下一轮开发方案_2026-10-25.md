# 候选引用式记忆构建：下一轮开发方案

日期：2026-10-25。本文保留最初方案；**现已实现并完成五条件本地开发对照**，最新证据见[实现与真实结果](引用式构建_实现与五条件真实结果_2026-10-25.md)。编号和原文选择均8/8构建成功、32/32题保留事实；严格格式修复后两者同29/32正确、27/32联合成功，仍未达整体目标。下文设计与原3/8失败记录按提出时点保留，不将新成绩回填旧实验。

## 1. 作用与边界

本方案仍服务于“Agent A 生成记忆，经权限与来源校验交给 Agent B，B 合法使用并在输出前再次核权”的主线。它只改进 A 端事实构建方式，不替代迁移授权、敏感检测、原文证据、生命周期或 B 端任务评测。

核心改变是：**事实选择与敏感字段归属分开；模型选择事实编号，主机取回精确原文，再独立验证当前事实内部的字段。** 这是标准工程改进候选。编号可以减少复制定位错误，但不能单独解决字段挂错父事实、事实丢失或模型主动待审；它不保证覆盖、标注、权限安全、任务成功，更不构成已成立的论文创新。

旧实验及本轮真实构建均为3/8成功、12次生成。本轮完整原答证明：`dev_en_02` 两次把客户名 finding 挂在另一条状态事实下；`dev_en_03` 把更长字段挂在截短事实下；`dev_zh_03` 是明确的复制错字；`dev_en_04` 把客户名挂到状态和页脚事实下。修复常删掉其他事实，只留下客户。另4条结构合格原答主动返回 `needs_review`，但没有原因字段。因此不能笼统称为“抄写不准”，更不能只替换 `fact.quote` 就宣称解决。[零模型复盘](真实交接对照_输入同构与构建失败复盘_2026-10-25.md)保留全部原答索引。

## 2. 最小数据流

原文与主机授权 → 固定规则生成事实候选池 → 本地模型选择候选编号 → 主机还原连续原文事实 → 独立敏感标注与主机校验 → A 签发记录与访问范围 → JSON 持久化/交接 → B 按当前用户和 Agent 核权 → 同一迁移/脱敏流程 → 同一回答模型 → 原有完整恢复与撤权检查。

这里的“事实候选”是待选择的原文片段，不是已经证实的事实，也不是已经认定敏感的实体。现有 `candidate_proposals.py` 的实体候选池不能直接改名当作完整记忆事实池。

## 3. 最小接口

### 3.1 主机生成候选

建议新增的概念接口为 `propose_fact_pool(source, config)`。本文件只规定设计，不表示代码已经存在。

主机侧候选池至少保存：

```json
{
  "source_id": "host-source-id",
  "source_sha256": "...",
  "segmentation_version": "...",
  "pool_sha256": "...",
  "complete": true,
  "candidates": [
    {"fid": "F0001", "start": 0, "end": 24, "text_sha256": "..."}
  ]
}
```

候选按事先冻结的句、行、字段或连续结构块边界产生，每个候选必须是同一来源内精确、连续的原文。上下文不足的表格行不能只剩孤立数值或名字；必要时把连续的表头与表格块作为整体候选，并完整计入大小。不能跨原文拼接，制造看似连续的事实。

编号在当前池内唯一，池绑定原文、位置、配置和版本。预算不足、过长文本或无法完整建立候选池时明确待审，不能静默截断。限制值须在执行前冻结，不能根据评分答案调整。

### 3.2 模型只选择当前编号

本地模型可看到当前候选的编号、原文和必要原文上下文，以及事先声明的通用记忆用途，例如保留身份、业务关系、状态和事件信息。它不接触授权密钥、访问授权对象、评分标签、参考答案、事后审计值或本轮实际评测问题。

最小输出为严格 JSON：

```json
{"status": "ok", "selected_fids": ["F0001", "F0003"]}
```

编号必须来自请求中的有限枚举；拒绝重复、未知编号、额外字段、权限声明和格式异常。模型不返回可覆盖原文的字符串、源位置或 ACL。响应不能单独证明来源，主机使用当前请求保存的候选池完成绑定。

`needs_review` 仍是待审，不自动改成成功。空选择也不能被算作“全部隐私已保护”。如以后采用逐条待审，须另外规定记录何时能入库/交接；不能为了保留成功率，给未通过标注的事实签发空敏感标签。

### 3.3 还原事实并独立标注

主机验证候选池绑定后，把选中编号转换为现有构建结果所需的 `text/source_start/source_end`。敏感字段采用同一独立检测与校验流程，仅允许来自当前事实的字段编号或当前事实文本内的精确片段。无受限值的状态事实允许空 findings，不能把另一条事实的客户名复制过来；错误字段也不能简单删除后跳过重新验证。候选被选中不表示其敏感，不赋予读取、共享或转授权权限。

事实选择和敏感标注应分别记状态与失败原因。状态、关系等公开但有用的信息不能因为“不敏感”就一律丢弃；同样，已通过原文定位的候选不能仅凭定位正确就视为语义标注正确。

仅合格事实进入 `MemoryLabelAuthority.build_record`。用户、源 Agent、接收 Agent、读者范围、策略版本和生命周期均由主机给定。继续使用现有 `prepare_labeled_transfer` 和 `restore_labeled_answer`，不绕过其对全部传入记录的签名、来源、当前权限和撤权检查。

## 4. 公平对照

首先只改变构建器，不同时增加新角色分类器、改变提示词或放宽恢复规则。

| 条件 | 做法 | 用途 |
|---|---|---|
| 全保留候选强基线 | 同一候选池全部保留，再走相同标注/授权/迁移流程 | 判断选择记忆是否优于简单保真保存 |
| 候选编号选择 | 本地模型从同一池选择有限编号 | 评价复制错误、事实覆盖与下游使用之间的取舍 |
| 原有自由 quote 构建，可选 | 保留现有 `LocalMemoryBuilder` | 区分编号协议收益与模型能力/预算差异 |

现有 `CoverageMemoryBuilder` 也应保留为源保真参考。若其分块粒度与候选池不同，要明确披露，不能把粒度差异藏在“同一强基线”下。

选择条件必须报告模型调用；全保留条件不需要选择模型，不能给它添加无用调用来制造费用相等。两种模型构建可使用相同的模型、上下文和最大生成/修复预算，分别报告实际尝试、失败和 token。检测器的版本、缓存条件、主机权限与 B 端处理保持可比。

已暴露的8个开发故事有32道合法题、8道越权题。两构建器至少保留80条任务结果；构建失败、记忆缺失、预算阻断、UNKNOWN和恢复失败都保留在原分母。若加第三个构建器，相应完整增加条件，不能只挑选成功故事。

## 5. 先看主线指标

- A 构建：原文/位置完整性、实际成功与待审、所需事实保留、状态/关系丢失、复制定位错误。
- A→B 安全：合法访问保留、越权用户与错误 Agent 的实际拒绝、来源/签名篡改、撤权后旧请求/旧记录重放。标准权限护栏是共同强基线，不能把其已有作用归功于编号选择。
- B 使用：合法任务正确率、事实存在时的 UNKNOWN、协议错误、恢复阻断，以及正确且无已注册遮蔽缺口的联合成功率。
- 隐私：真正发出的文本、完整/部分/未遮蔽跨度及额外遮蔽。未提取的事实不能被当作新的隐私保护收益。
- 代价：实际生成与编码、输入/输出 token、时间、保留事实字符、完整记录 JSON 和原始来源副本体积。

目前每个签名记录可能附带整段来源文本。不能只统计选中的 `fact_chars` 就宣称总记忆存储压缩；也不能把受控主机保存原文等同于跨系统最小披露协议。若将来改变来源存储或证明方式，必须单独设计与验证，不能在本轮顺便更改。

## 6. 何时执行与如何表述

本轮真实对照已完成，零模型复盘确认A端构建仍是主要损失；当前边界模块在这批故事上没有改变最终span、出站语义或恢复来源，不能把23→24当作机制收益。是否执行本候选方案仍由完整冻结结果决定，本轮不再调用模型。后续须先冻结候选粒度、选择上限、失败策略、模型/提示词/预算、共同隐私管线与评分方法；评分标签只在机制结束后使用，旧开发材料不能充当新的独立验收集。

如果只是减少复制错误，应如实称为工程稳定性改进；如果事实覆盖、合法任务或安全联合指标没有改善，应保留负结果。发表所需的完整主线、独立验证和创新度仍需另有证据，本方案不预先承诺。
