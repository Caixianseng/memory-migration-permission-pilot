# D1补充：真实源任务、审计兼容性与客户端资源

日期：2026-11-02。本报告补充已发布的[P1完整对照](七天冲刺_D1_完整对照结果与研究裁决_2026-11-02.md)，不修改旧失败、旧评分或原始回执。

**P1的12格对照已经完成；P2新增一个真实HY3源任务，尚未取得新故事的Harness回答。新方法优势仍未成立。** 当前新确认的阻碍是原生工具审计兼容性与资源计量，不能将其归咎于权限算法，也不能把修复它们称为论文创新。

## 1. 新故事发生了什么

首个新开发故事完成了一次真实WorkBuddy HY3逻辑任务，原生记忆文件、输入与会话绑定核验通过。随后，封存前的工具审计发现两条未识别的PowerShell语法，按冻结规则停止本链：

|项目|本次记录|
|---|---:|
|真实HY3逻辑任务|1|
|已核验的原生记忆文件|1|
|按本链规则成功封存|0|
|Harness请求|0|
|新增Harness费用预留|0|
|自动重发|0|

独立语法树与路径复核确认，这两条命令分别是登记工作区的创建/存在检查，以及登记输出文件的长度/格式/存在检查。未发现这两条命令读取额外文件内容。这是审计器窄语法覆盖不足，不是模型政策拒答、业务评分失败或已证实的数据泄漏。

修复采用新版本，只允许已核实的有限操作；任意Shell、其他文件读取与未知操作仍不放行。对旧28行快照的补充诊断不能恢复已停止的链，不能倒填“已成功封存”。后续新增6行与原快照构成完整字节前缀关系，增补观察单独保留。

## 2. 为什么暂不直接扩大正式模型实验

对P1沿用的8份源产物进行只读校准：7份满足本审计入口的原生回执要求，另1份继续保留原失败回执和同attempt迟到核验路径，不伪造accepted。在可审的7份中，v2审计器仅兼容2份（2/7）；以全部选定产物计为2/8。

其余5份共有10条未识别语法，没有据此认定这些操作安全或已经泄露。**这是接口兼容率，不是安全率、模型正确率或算法成功率。** 此时继续投放正式新案例，容易再次被与研究假设无关的运维写法拦截。

下一步先核查现有WorkBuddy原生接口能否将记忆生成与文件保存、队列运维分开：模型生成真实记忆文本，宿主完成确定性保存与校验。若使用宿主保存的原生回复，会明确标注来源，不能冒充WorkBuddy原生Write或Auto-Memory。接口必须由实际代码与原生记录确认；截至本报告，这条简化路径尚未实现或调用。

## 3. 找到了此前缺失的HY3用量字段

原生会话记录包含分步`rawUsage`及两份重复映射。交叉核对数值一致后只累计一份，不能相加三次。

|限定观察的任务|唯一usage步骤|记录输入token|记录输出token|
|---|---:|---:|---:|
|本次新四来源M|7|247,703|7,166|
|此前一份单来源缓存|7|231,654|5,481|
|此前四来源M|6|225,119|9,681|
|此前三来源R|12|430,970|9,759|

表格是四个具体任务的客户端观测，不是受控方法均值，不能据此断言三来源通常比四来源昂贵。输入包含怎样的系统提示、工具上下文和缓存影响，尚未逐项因果分解。也不能跨模型直接用token相加替代人民币成本。

本次新M在原审计截点只有5条usage，输入168,196、输出6,450；后续收尾增加2条usage，输入79,507、输出716。因此必须同时固定“记忆就绪”和“会话观察截止”等截点，不能选择较早、较低的数字冒充完整过程成本。

`usage.requests`有明示数值，但仍不等同经过网络审计的供应商物理请求次数。`credit=0`缺少币种和结算依据，不能理解为免费。供应商物理请求次数及人民币实付继续保留为未知。

已新增独立后处理提取器，处理重复、字段冲突、缓存与思考token，按指定会话快照输出数值和哈希。7项定向测试通过，四会话及旧截点重算一致。该脚本不进入源模型生成链，不提供题目或参考答案。

## 4. 对研究路线的影响

1. 完整合法原文、惰性生成、全量重建和单源缓存仍须公平比较。不能只比较摘要长度，遗漏客户端多轮生成与收尾资源。
2. 当前生成分组候选尚未通过强基线资格，不因为补到了更多usage字段就升级成新方法。
3. 先收敛真实调用路径和观测边界，再运行新故事的完整时序对照；不通过扩大调用量掩盖仪器误阻。
4. 已提供输入不含评分答案，与模型全部工具/隐藏上下文都已隔离，是不同结论。P1公开元数据已补充此限制，原有数值评分不变。

用户随后清除了持续目标，本轮不再启动新模型批次；第二个新故事尚未prepare或调用。[七天完整方案](权限变化记忆迁移_创新验证与落地执行方案_2026-11-02.md)与待办保留，不能说七天任务已经完成。交付目标仍是可复核的结果与继续/终止裁决；环境修复完成也不意味着方法优势或论文录用已经成立。

只读接口核查找到一条后续候选路线：现有桥接可向新原生会话发送自定义prompt，再从绑定会话转录提取最终助手回复。但尚无现成的最终回复读取接口，也未做真实资格调用；必须核对原生包装、会话和回复关联、工具使用及停止状态，不能写成“已经打通”。
