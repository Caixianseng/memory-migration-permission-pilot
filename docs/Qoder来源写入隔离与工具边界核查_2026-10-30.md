## 2. 保留登录、关闭无关上下文的候选做法

保持既有默认配置根，让原生客户端自行使用既有登录；**不读取、复制、打印或传递认证文件内容**。用`--setting-sources project`与本轮显式设置限定行为配置，而不是复制用户配置到新根。先前客户端能够继承登录，不表示新适配器已经认证成功；新实验须单独保留认证状态，失败不能自动转为复制凭证。

本机静态记忆发现代码依据`allowedAgentSources`决定是否调用user静态记忆扫描。`project`来源配合新建且已验证无链接的Git根，是阻止用户级AGENTS和父目录项目指令进入本轮的代码依据。以下还要作为运行前条件核查：

- 新目录没有`AGENTS.local.md`、rules、外部导入、额外工作目录或预置源端记忆；开始时`AGENTS.md`不存在。`.git`必须是本轮新建的真实目录。
- `context.fileName="AGENTS.md"`、`context.memoryBoundaryMarkers=[".git"]`、`context.loadMemoryFromIncludeDirectories=false`。不启用`--add-dir`。
- 清理传给子进程的环境白名单，分别设置`QODER_MEMORY_HEADLESS=false`、`QODER_MEMORY_PROJECT=false`、`QODER_MEMORY_USER=false`；兼容旧前缀时也显式设对应`QODERCN_`变量为false。不要把宿主完整环境原样继承。
- 显式`autoMemoryEnabled=false`、`autoMemoryUserScopeEnabled=false`；不用SDK memory接口、不恢复既有session、不使用`--continue`或`--resume`。
- 禁用技能、Agent、插件自动更新，严格空MCP；仅暴露本轮所需的写工具。已有无工具读取包装器的限制不能直接放松，应另建有限写入适配器。

上述设置只限定本轮模型上下文和工具入口，**不表示原生客户端完全不读取任何用户级运行元数据**。保留登录本来就需要客户端使用原生认证机制；本次没有跟踪其所有系统调用或证明进程级文件隔离。

## 3. 层级A的最小工具与路径许可

建议从一个新合成故事、一项源端生成任务开始。模型只需把给定的合成事实写成静态项目记忆，不需要浏览文件、联网、搜索、shell或子Agent。

工具集合限定为：

```text
--tools Write
--permission-mode dont_ask
```

路径许可放在**本轮新项目**的`.qoder/settings.json`，这样`/AGENTS.md`明确相对于该项目根，不依赖`--settings`内联来源的根目录推断：

```json
{
  "permissions": {
    "allow": ["Edit(/AGENTS.md)"],
    "deny": ["Bash", "PowerShell", "WebFetch", "WebSearch", "Agent"]
  }
}
```

模型可见工具仍只有Write；deny列表是额外限制，不能代替`--tools`集合。**不加`permissions.deny=["Read"]`**：Write原生实现会做内部读取核权，这可能错误阻断所需写入。也不用`--allowed-tools Write`这种不带路径的广泛自动批准，不使用`accept_edits`、`auto`或`bypass_permissions`扩大自动许可。

官方[工具说明](https://docs.qoder.com/cli/sdk/tools)确认Read/Edit/Write等是底层CLI工具名；本轮以本机注册schema核实Write的真实参数，并不引入自定义MCP来冒充原生写入。

路径规则是候选配置，尚未执行实际Write。必须再加受信主机准备的本轮`PreToolUse`门禁，并在模型调用前用合成事件对门禁进行本地资格测试。门禁仅针对Write事件：

1. `tool_name`必须严格为`Write`，输入字段仅为`file_path`与`content`，类型合格；接收会话、当前工作区与登记请求须绑定。
2. 仅接收少量预登记的等价路径拼写，例如`AGENTS.md`及已冻结的绝对目标路径；含`..`、UNC、设备路径、ADS、保留设备名、非标准前缀等直接拒绝，不能先宽泛归一化后默认放行。
3. 目标解析结果必须等于本轮新项目根下的唯一`AGENTS.md`；逐级核查无symlink/junction/reparse point；现有目标不能覆盖。
4. 限制内容字节数，拒绝外部`@path`导入；内容只属于本轮合成材料。记忆文字不能改变源端外部授权表。
5. 合格输入返回`permissionDecision:"ask"`，让后续原生路径许可继续判定；不合格输入返回`deny`。这里的`ask`不是要求用户确认：在正常路径被显式allow时原生判定应允许，否则headless拒绝。
6. 错误、无效JSON、无法确定路径时输出明确deny。Hook自身超时或加载失败的行为仍需核实，不能只凭脚本写了try/except就声称整个调用链自动失败关闭。

输出结构由本机代码识别，形式为：

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "outside_frozen_source_output"
  }
}
```

该门禁脚本由主机部署在模型不可写的登记位置，命令固定，不由模型拼接。项目设置中的`hooks.PreToolUse`只登记这一组，本轮开启Hooks时不得同时设`disableAllHooks=true`。用户设置来源排除后，仍应核对是否存在策略管理或其他自动加载Hooks；不能声称配置字面值已证明有效配置。

官方[Hooks说明](https://docs.qoder.com/cli/hooks)提供PreToolUse的结构和阻断机制。本文没有部署Hook或冒充已拦截越界调用。Hook与路径规则也不是OS沙箱：可信宿主、单任务、无并发改名/换链是当前合同前提，不能宣称已经解决任意进程竞态或恶意宿主问题。

## 4. 需要什么执行证据

新写入适配器可以使用`--print --output-format stream-json`，限制会话轮数和输出token，重试为0，并关闭会话持久化。官方[脚本运行说明](https://docs.qoder.com/cli/run-in-scripts)给出该输出格式；本机也包含相应事件实现。一次源端任务可能包含“模型提出Write→执行工具→模型确认”多个模型轮次，不能把一个CLI任务记成一次底层HTTP请求。

最低合格证据同时包括：

| 证据 | 最低核对 |
|---|---|
| 起点 | 启动前登记目录、输入、CLI/Node哈希、配置、预算；AGENTS不存在 |
| 原生调用 | assistant的`tool_use`：name为Write、id唯一，路径与内容哈希匹配登记输出范围 |
| 原生结果 | 对应同一id的`tool_result`没有错误；不能只看模型最后说“已保存” |
| 实际文件 | 退出后确实有新AGENTS，UTF-8可读、无外部导入，文件内容哈希与Write输入一致 |
| 范围 | 项目内其他已登记文件没有变化；没有意外工具、未知写入或自动追加重试 |
| 后续源适配 | 读取的源对象就是该产物或可验证字节副本，记录路径、哈希和确切片段；主机不得悄悄修正源文件以通过评分 |
| 迁移使用 | 在同一故事上完成保护、迁出、目标加载、回答、再核权恢复，登记源端专用事实和缺失事实对照 |

若只有文本输出、工具调用被拒、工具有成功回执但没有文件、或者文件由主机补写，均不能登记层级A成功。这里没有新增任何成功事件。

因新写入项目需要`.qoder/settings.json`，当前冻结的`qoder_native.py`会拒绝把它作为原有干净问答工作区。后续应使用独立写入适配器，并从退出后产物进入主机迁移；不能修改旧包装器放过额外项目配置。如另测Qoder新会话读取，应另立干净工作区/副本关系或明确配置清理证据，不混入旧封存批次。

## 5. 层级B：项目Auto-Memory还缺什么

官方[CLI Memory](https://docs.qoder.com/cli/memory)当前将Auto-Memory描述为交互功能，并区分项目根与用户根。它还给出`QODER_MEMORY`开关。但本机1.1.77字符串中没有`QODER_MEMORY`这个完整标识，实际有通过前缀构造的`MEMORY_HEADLESS/PROJECT/USER`，并有SDK专用消费和生成状态。**这是一项版本或实现路径差异，不能用网页中的单一环境变量替代本机运行核验。**

本机交互分支在`resolveInteractiveAutoMemoryScopes()`中直接使用`autoMemoryEnabled`和`autoMemoryUserScopeEnabled`覆盖运行默认。因此TUI项目限定候选为前者true、后者false，并继续排除用户静态AGENTS；不要同时开启用户Auto-Memory。headless/SDK内部路径存在，不表示其公开支持、行为与TUI等价，也不据此扩大本轮实验。

本机存储实现为：

```text
storage.getProjectMemoryTempDir()
  -> getGlobalConfigDir()/projects/getProjectIdentifier()/memory
```

scope枚举函数`zI`依据当前启用的scope决定是否包括项目目录和用户目录。后续应通过本轮原生`/memory`入口或受控运行时路径证据定位新项目的实际根；不要扫描其他项目主题文件或猜slug再大范围读取。

尚待独立解决的前置条件：

- `--config-dir`换成空新根可能丢失既有登录；本轮未找到并验证“不复制认证材料但把Auto-Memory目录独立重定向”的公开配置。不能因此替用户复制`.qoder`或认证文件。
- 保持默认根时，项目Auto-Memory位于用户配置目录下，而不是项目内。必须在实际实验时记录仅本轮新项目目录的访问/写入范围；本轮没有创建该目录，不能声称目录隔离已验证。
- TUI默认可能保存会话并有后台记忆处理；`--no-session-persistence`帮助注明只适用于`--print`。不能把headless设置直接当作TUI无持久化证明。
- 新项目生成后，需要退出并开新会话，核对真实记忆文件或读入事件与回答。不能恢复同一会话后说跨会话记忆起效；问题中不得复述待检事实值。
- 生成零条记忆是可能的观测。必须保留零产物与失败位置，不反复提醒直到出现一个好样本。

所以目前层级A有具体待运行入口，层级B仍有隔离、目录定位、持久化和事件证据缺口。二者都不能直接推出原生ACL、在线撤权、隐私识别正确率或新算法优势。

## 6. 建议的执行顺序

先固定独立Write适配器和门禁的输入输出合同，做无模型的路径正反例检查；确认不会改旧原型或全局配置后，再按一次有限源端任务的预算执行层级A。合格后只把真实产物白名单交给当前迁移链，源ACL由独立合成授权表附加，正文不得自授权限。

若研究主张明确要求原生Auto-Memory，则另外登记层级B并解决上述前置条件；不能用层级A的AGENTS产物改名顶替。最小可行性成功也仍只是补足真实源接口，不是新方法优于普通文件适配的证据。
