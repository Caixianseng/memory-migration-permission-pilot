# DeepSeek Harness 与 Qoder：当前代码验证结果

日期：2026-10-27。本轮依据用户“再用deepseek harness 和qoder 在进行验证”的要求，实际启动了本机两套客户端。基线提交为 `c8254d9bcba124dd68e841cc41855e93c68c3f7e`，运行时包含当前未提交修复，具体94份源码/材料/资产哈希已冻结，不把基线提交号当成全部受测源码身份。

**本轮24次真实客户端调用全部完成，24份回答均符合本轮开发题参考。** Qoder与Harness各12次，合法问题16/16正确，缺少信息的8次均返回UNKNOWN。156项本地主机权限控制全部通过。这个结果支持当前受控互通流程的稳定性；它只有一个已暴露故事、三道不同问题，不代表通用成功率达到100%。

源事实由可信主机预置，客户端实际加载本机工作区的AGENTS.md。没有让源Agent自主生成这些记忆，也没有模拟厂商的自动长期记忆。测试材料是公开自编合成内容，没有发送用户真实私有数据。

## 3. 权限与接口究竟验证到了哪里

本轮156项控制覆盖源/目标撤权、未知授权故障、跨用户、跨Agent、错误受众、源专用记录导出拒绝、到期、旧包、跨题恢复与伪造候选等。24份回答能力关闭后，重放均被拒绝。

这些权限由本地 `NativeAgentBroker` 与 `CurrentMemoryAuthority` 执行。静态AGENTS.md本身不提供厂商原生逐次ACL或在线撤权；已经被客户端读取的明文，也不能因为主机后来撤权就被强制遗忘。本轮没有验证跨机器网络、企业身份系统或分布式原子撤权。

Harness每次回执均核对原生加载事件中的SHA-1与文件/包装器的SHA-256；每个位置允许1个SDK stream，合计12。Qoder核对文件前后哈希、包装器身份和回答；它没有提供同等级原生加载事件，证据强度分别说明。

Harness临时凭据复制与清理由现有包装器执行，回执要求原凭据不变、临时副本删除。凭据、恢复映射、完整客户端运行目录和原始响应不进入公开汇总。

## 4. 这次发现并修复的问题属于哪一类

真实客户端运行前，全量离线测试发现4个错误，均为 `registered_dependency_closure_changed`。新增 `sensitivity_contract.py` 后，source-card实验的固定依赖清单没有登记这个新导入，完整性审计因此阻断。

这是**实验执行器的依赖合同遗漏**，不是模型判断失败，也不是Qoder/Harness迁移协议不兼容。修复采用新版依赖合同v3：精确52项；旧v1的50项、v2的51项保持不变。没有删除审计、放宽哈希校验或修改旧实验计划。相关54项测试通过，四个原报错均已重跑成功；另有80项客户端相关离线测试通过。

第一次新预检计划在0次模型调用时封存，第二份计划重新冻结后执行。新批次总预算仍为24，没有因为重新冻结而增加调用上限。旧批次24次保持封存；两批语义复核累计48次，不是整个项目历史调用总数。

本次离线验证还保留了一次测试启动环境错误：根代理把TMP/TEMP指向含中文的项目目录，违反几个原生后端测试既有的ASCII系统临时状态目录要求，该轮1780项测试产生2个失败、14个错误。相同代码的默认临时目录对照通过，因此恢复系统默认TMP后重跑；没有据此修改产品守卫或测试真值。该失败轮及目录对照记录仍在本机保留。

**最终默认系统临时目录下，全量1780项测试通过，0跳过、0失败、0错误，耗时359.782秒。** 387份Python源码在运行前后哈希一致，也与前一次临时目录错误运行逐字节相同。五个受影响模块的59项定向测试及单项只改变TMP的配对验证均通过。完整回归新增模型与客户端调用为0。

## 5. 尚未验证的部分

新 `category_contract` 的严格客户关系检测有专门离线集成测试，但没有在这24次调用中启用。本批次关闭后另行完成了[本地检测对照](共同敏感类别合同_实测结果与问题归因_2026-10-27.md)，结果未达总体门槛；不能把本轮24/24作为它的效果验收。

另外，独立的单值 `native_privacy_gateway` v1接口目前不接受 `category_contract` 字段，会按未知字段拒绝。这是明确的接口能力边界；本轮走的多候选legacy reader没有使用该字段。下一步把严格检测接入真实客户端前，需要单独版本化这条接口并验证失败关闭，不能仅把字段加入白名单就宣布整条检测链已打通。

新独立64题、实际敏感检测的联合精确率/召回率门槛、历史向量空结果根因，以及相对完整强基线的论文创新仍未完成。本轮不修改这些目标，也不因两客户端表现正确而否认先前其他模型的失败记录。

原始DeepSeek API调用为0，使用现有官方客户端账户。账户实际费用未知。Harness报告的inputTokens=5150、outputTokens=84、totalTokens=7154，字段口径并不相加一致，原样记录，不换算费用。Qoder用量字段为0，也不能解释成免费。
