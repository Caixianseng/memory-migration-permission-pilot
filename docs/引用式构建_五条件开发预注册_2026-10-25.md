# 引用式构建：五条件真实开发对照预注册

日期：2026-10-25。上一目标轮完成了真实A→B对照、安全缺口修复及独立核验，改变了下一步决策，属于进展。该轮仍未达到整体效果与创新要求；本轮继续保持这些要求。

## 1. 问题与范围

上一轮真实模型构建仅3/8成功、32道合法题仅6题保留所需事实。完整原答显示事实与敏感字段混在一次输出中，会把客户名称挂到不含名称的状态事实下，并在修复时丢掉其他事实。

本轮检验：将“选择事实”与“在当前事实内部标注敏感字段”拆开，能否提高构建成功、事实保留与真实下游使用，同时维持原授权、外发与恢复检查。引用编号只是候选协议，不预先宣称是新算法或论文创新。

## 2. 固定材料与条件

采用已暴露的8个开发故事、4类模板，固定每故事4合法+1越权任务。五条件各40行，共200行，合法题各32。失败、待审、记忆缺失、预算阻断、UNKNOWN及恢复失败均保留在分母；不挑故事、不删失败、不改答案。

| 条件 | 构建与标注 |
|---|---|
| old_joint_quote | 原LocalMemoryBuilder联合输出原文事实与字段，保留其真实失败 |
| reference_id | 本地模型从当前候选池选择fid；主机取回精确原文，再用独立GLiNER标注 |
| reference_quote | 同一候选池、同一用途；模型返回候选原文枚举，再用同一独立检测器标注。它是简单两阶段强基线 |
| retain_all | 同一候选池全部保留，再用同一独立检测器标注；不增加无用选择调用 |
| coverage | 原CoverageMemoryBuilder保真分块参考，成本与粒度单独报告 |

候选采用完整非空行；连续pipe表格整体保留，超长块、跨行不完整结构或预算不足明确待审，不按评测答案拆分。当前8源无表格或跨行引用，共20个非空行，与原Coverage实际粒度一致。每故事只建立一次池，三种新条件共用并验证源、配置及池哈希；池不被修改。

编号/原文选择均最多8项、最多2次生成；错误、重复、未知引用及额外权限字段拒绝。原文枚举若在多个源位置出现，不能默默选最早位置。空选择与主动待审不能改为成功。事实和字段归属分别验证，状态事实可以没有敏感字段；模型不提供ACL。

## 3. 共同主线与预算

各条件由受信主机签发精确fact范围的原授权，经过真实JSON交接和同一`migration/legacy`流程，再使用同一LocalFactAnswerer。全部使用当前身份、来源、完整策略和撤权检查；不加意图模块，也不同时换边界算法或回答提示。

固定本地Qwen模型、摘要、运行版本、4096上下文、temperature=0、seed=42；构建最多1024、回答最多64输出token。最多160次回答生成，加8故事×3个模型构建器×2次=48次构建生成，物理POST总上限208。GLiNER调用独立计数，不冒充生成次数。零云端调用、零新增API费用，外部网络禁止。

每次真实POST执行前记入账本，保留失败尝试、完整合成请求/响应、实际usage、分阶段与分条件计量。JSON请求体字节按归档传输器的UTF-8序列化定义计数，不称HTTP原始报文字节。普通日志和研究工件均不保存密钥或恢复映射。

运行前冻结包、入口、模型、配置、材料哈希及顺序种子。构建和回答顺序按故事/任务交错。评分文件只读取字节供哈希，在全部模型/恢复操作结束后才解析；评分标签不提供给候选、选择、标注、授权或回答模块。

## 4. 主指标与验收

主指标：构建实际成功与失败、32题必要事实保留、原始模型回答严格正确、正确且无注册字符遮蔽缺口、越权阻断与越权输出。检测、处理、UNKNOWN、恢复阻断分别报告。较少提取不能当作隐私收益。

严格补括号继续只作同输出次要分析：只有当前请求完整代号的最外层括号可补回，后续仍完整核权恢复；原始输出与主成绩不覆盖。含秘密的拒绝、损坏nonce、错误来源和多代号拼接均不因此放行。

同时报告候选池、选择结果、事实字符、完整记录JSON字节、重复source副本、生成/编码量、实际输入/输出token及时间。全保留不是语义压缩；相同成本或性能应如实报告。若引用ID与简单原文枚举没有优势，不能把收益归于ID机制。

独立验收器自行重算全部分母、主/次成绩、账本、源/池/配置/代码绑定；实际遮蔽由独立原文—模型输入字面对齐核验，歧义明确失败。独立核验通过仅说明证据一致，不等于达到整体效果或创新门槛。

本轮仅开发对照，不替代原120条检测、原云端对照、新独立至少98%联合目标、原生跨后端验证与论文强基线要求。若结果不足，保留负结果继续定位，不围绕已暴露材料宣称泛化成功。
