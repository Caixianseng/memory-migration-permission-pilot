2026-10-26。只读审阅旧 v3、已有三步诊断、固定文本时序诊断及固定源码；本文是待冻结的实验合同，没有启动新后端、模型或查询，也没有修改已冻结 worker。该向量子目标已确认失败一次，四个 null 不是四次实验。

以上记录的是合同编制时点。后续已按唯一臂A执行，[结果另存](原生向量旧序列_无逐行追踪诊断结果_2026-10-26.md)：164次HTTP、21次本地嵌入，未复现，未自动运行B，旧失败仍未关闭。下文保留执行前的判断和停止条件。

## 旧失败仍是什么

`native_exact_fact_bridge_20261025_v3` 原标准为 25/29，整体失败。原生请求 #71/#98 的主体是 assistant，#136/#163 是 outsider；四个原始 `.bin` 均为四字节 `null`，HTTP 200，SHA-256 均为 `74234e98afe7498fb5daf1f36ac2d78acc339464f950703b8c019892f982b90b`。本次重新只读核对，原 `report.json` SHA 为 `d0879b96e57580e5f74fb2b5a8a3d072e33d3dab93fe6accfce39a2786cece52`。

| 同一数据库内的阶段 | owner 返回条数 | assistant 返回条数 | outsider 返回条数 |
| --- | ---: | ---: | ---: |
| 写入后首个完整 snapshot | 2 | 3 | 1 |
| 禁止新 export，已有副本保留 | 2 | **null** | 1 |
| 源 read 撤销、目标清理前 | 2 | **null** | 1 |
| 清理 owner/assistant 的两个 main 副本后 | 1 | 2 | **null** |
| 拒绝旧任务重建后 | 1 | 2 | **null** |

assistant 两次失败均在任何目标 delete 之前；outsider 从未删除自己的 resident。其合法 SQL 记录仍在。旧 HTTP recorder 没有逐 HTTP 时钟，只能用 RPC 起止区间，不能补造当次 search 的准确时延。

已有固定向量时序诊断每个新数据库只做第一次查询，两臂均开 `sys.settrace`：立即 6/6、500 ms 等待 6/6。它没有覆盖本表的重复 snapshot、原无追踪条件及删除序列，不能关闭旧四次空值。旧完整 trace-only 虽 29/29，但 resident 随机 nonce 与旧失败不同，也不是相同向量输入的严格配对。

## 建议冻结的一次最小诊断

先做一个 **target-only、同库完整生命周期、无逐行追踪** 的新隔离臂 A。它保持原目标调用序列，但不重复源端授权与 SDK 工作，故不是完整迁移验收。

1. 从旧 v3 原始 POST/结果提取六条逐字相同的文本、路径、写入顺序和逻辑角色；resident 的 nonce 也固定，不再随机。只迁入精确事实，不带 source-only canary 或完整源文。新身份和对象 ID 正常重建。
2. 保持原预写空账户 snapshot、六次写入、写后三次完整 snapshot、两个指定 main delete、删除后两次完整 snapshot。每次完整 snapshot 仍按 owner→assistant→outsider 执行原 list、词法、六个 known-ID、semantic 路由；不省略 SQL 读，也不额外增加向量 count/get。
3. query 仍为 `Customer service and delivery status.`、k=100、阈值0；固定 Open WebUI 0.12.3、Chroma 1.5.9、MiniLM 及原15项资产。保留所有合法 resident 和 assistant 的独立合法控制。
4. `sys.settrace` 全程关闭。仅在**新诊断沙箱中的原 search 异常处理块**增加一个记录钩子，随后仍返回原 `None`；另区分非异常 `return None`。不修改安装文件或生产 worker，不重试、不回退 SQL、不重索引、不改变正常调用、距离换算或返回对象。
5. 记录异常类型、消息 SHA、固定公开错误标记、固定源码行/堆栈、阶段、集合的逻辑主体及关联 HTTP 序号；不采集 locals、消息原文、凭据或令牌。若以 AST 生成诊断函数，执行前核对原 try 正常路径与新函数对应逻辑，明确它仍是诊断副本，并非逐字原函数。

向量摘要可在原 upsert/search **返回之后**观察现有参数，不增加 embedding、count/get 或 query；两臂使用同一记录方式。它仍有观察开销，不能声称完全无扰动。原有逐目标 RPC 间隙可从旧收据冻结并按相同规则调度；实际耗时必须另记，不宣称复刻了旧 CPU 调度。

A 若完全成功，以“本轮同库固定序列未复现”结束，不自动扩量。A 若观察到普通 null/异常但没有安全或仪器失败，可按预声明继续原定有限生命周期，保留所有首次失败，不追加查询；之后仅执行一个新库匹配臂 B，唯一额外干预为启用原 trace-only 异常观察。B 同样使用旧六条固定文本，不能换随机 resident。

| 原生 HTTP | 164 | 328 |

未触发 B 时不得为了取得更多成功再运行 B。出现越权 ID/文本、身份错配、资产变更、被禁止外联、记录钩子失败、401或后端执行中断，立即停止，不强行完成匹配臂。A/B 阴阳性比较只能描述该固定条件下追踪干预的关联；单次配对不能证明普遍因果。

## 什么才允许关闭旧问题

- **取得可复核故障机制**：在未逐行追踪的完整旧条件下，捕获相同 HTTP200+null，并把它关联到明确异常/分支、原始输入、固定源码和合法正控。仅另一次全绿仍是未复现。
- **针对机制修复而非改评分**：故障证据先冻结，再决定最窄修复。将 null 改报502只改进错误分类，合法记忆仍不能检索时不能通过；调小k、加重试、延迟或直接换SQL也不等于原合同修复。
- **回到完整源→目标验收**：修复后仍保留实际 Mem0 SDK 源、现行授权/精确事实投影、原k100、独立合法源控制、撤权、两个指定副本清理和旧任务重放，重新运行原29项，四个原失败阶段均需真正取得合法向量结果。target-only 成功不能替代该步骤。
- **保留结论分层**：旧失败永久保留。诊断修复与有限回归可关闭其已证机制；稳定性、跨样本泛化及论文创新仍需各自证据，不能从一个故事的29/29推出。
