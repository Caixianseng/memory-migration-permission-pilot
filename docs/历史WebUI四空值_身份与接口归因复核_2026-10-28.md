# 历史 WebUI 四空值：身份与接口归因复核

日期：2026-10-28。范围：仅重新读取既有计划、报告、四份响应字节、归档与当前源码，未启动后端，未执行 HTTP、原生向量查询、嵌入或生成模型，未访问认证数据库或输出凭据。没有修改原报告、评分器或厂商源码。

**结论：四格均是向量响应合同失败；同格的身份绑定、SQL 枚举与已知 ID 读取符合原受控预期。现有证据未发现探针发错用户、集合参数或请求字段，但历史后端的具体异常仍为 `unknown`。原 v3 的 25/29 整体失败及四个空值继续保留。**

## 2. 接口、用户与集合合同

原目标使用 Open WebUI **0.12.3** 的 FastAPI `TestClient`，在隔离子进程内通过真实 ASGI 路由运行；不是有固定监听端口的常驻 WebUI 服务。相对路径 `/api/v1/memories/query` 不代表现在有可探测的历史监听地址。本次没有发起 health 请求。

四次均为：

```json
{
  "method": "POST",
  "path": "/api/v1/memories/query",
  "body": {
    "content": "Customer service and delivery status.",
    "k": 100
  }
}
```

冻结版本的 `QueryMemoryForm` 接受 `content` 与 `k`。原探针没有误用词法接口的 `query` 字段。正常响应是 `SearchResult`，包含 `ids`、`documents`、`metadatas`、`distances` 四个二维数组；它不是 SQL `/memories/search` 的记忆行列表。

[原目标 worker](../scripts/native_exact_fact_target.py)依据当前逻辑主体选取内存中的独立用户凭据。[原生写入包装](../memory_migration_study/native_webui.py)在 `/memories/add` 后核对返回行的 `user_id`、内容和 ID。冻结 router 的写入和向量查询均由已认证 `user.id` 构造 `user-memory-{user.id}`；查询请求本身没有可让探针另填集合名的字段。异步适配器按原参数调用同步 `search(collection_name, vectors, filter, limit)`。

原代码和工件没有显示换错用户或集合映射。需要保留的限制是：旧运行没有逐次捕获后端实际 `collection_name` 或原始 Chroma 返回对象；集合归属在这里来自冻结代码路径及已有身份/SQL 证据，而不是一份新补写的历史后端 trace。

另有两个能缩小问题范围的现象：

- assistant 在前一阶段已用同一主体、相同查询和三个目标记录成功返回；源端禁导出、源撤权两个阶段未改写其目标副本，却出现两次空值。
- outsider 只有自己的 resident，目标未对它执行删除。它此前查询成功，最后两个阶段返回空值。不能把该变化直接解释成源撤权或目标清理删错账户。

## 3. 已证实的错误信息丢失路径

冻结的 `open_webui/retrieval/vector/dbs/chroma.py` 中，`ChromaClient.search` 的同一个 `try` 覆盖：

1. 获取集合；
2. `collection.query(query_embeddings=vectors, n_results=limit, where=filter)`；
3. 距离换算；
4. 构造 `SearchResult`。

其 `except Exception as e` 直接 `return None`，没有保留异常类型或阶段。另有集合对象为假时返回 `None` 的分支；既有持久化取证观察到真实 `Collection` 真值为 True，未观察到该非异常分支，不能据此补出历史分支证据。

router 收到 `None` 后未抛出错误，而是直接返回它；该路由没有强制非空 `SearchResult` 的响应模型，故可呈现为 HTTP 200 加 JSON `null`。因此，记录中的 `execution_error=None` 只说明 recorder 没收到向外抛出的请求异常；**不能推出底层没有异常。** `response_checked=True` 在 recorder 层表示安全保存并绑定响应字节，也不等于向量合同通过。

这条“内部错误被压成 `None`，再成为 200/null”的机制已有源码证据。没有历史异常类型、消息摘要、栈或阶段，仍无法区分上述四处究竟哪一处失败。不能把泛化的错误丢失机制当成已经找到某个 Chroma 索引错误、线程问题或 Pydantic 故障。

## 4. 当前项目是否已正确区分 null、空结果与拒绝

**已具备必要区分，本次不新增同类 auditor 或测试。**

| 现有位置 | 实际合同 | 对异常的处理 |
|---|---|---|
| [原 v3 `check_semantic_row`](../scripts/run_native_exact_fact_bridge.py) | 200 必须是四字段 `SearchResult`，结构、实际 ID 集合、文档和元数据均匹配 | `null` 不是 dict，直接判失败；不算空结果、合法拒绝或安全通过 |
| 原 v3 的空账户合同 | 仅接受明确 `404 / No memories found for user`，且独立 list 和预期集合均为空 | 不能把有三条/一条记录的 200/null 算成合格空读 |
| [当前 `actual_read`](../scripts/run_review_native_read_chain.py) | 200 原文必须有内容、长度合格、与注册原文哈希精确匹配 | 不匹配为 `raw_content_unknown`，相关格记作 `infrastructure_unknown` 并停止；不转成 `denied` |
| 当前 `actual_read` 的拒绝分支 | 仅接受 403/404 加结构合格的错误正文，并检查没有注册秘密 | 无法辨明的响应为 `raw_denial_unknown`；秘密出现在拒绝正文时单列安全失败 |
| [当前 API 交接的 `checked_trace`/`raw_read`](../scripts/run_native_api_read_handoff.py) | 绑定主体、授权头、无 cookie、状态、原始字节与哈希；合法读取校验原文，拒绝校验明确状态及错误正文 | 401、5xx、执行错误、未知原文或未合格拒绝不能计作授权拒绝 |
| [当前 WebUI projection worker](../scripts/native_webui_projection_worker.py) | recorder 忠实保存非认证响应；注册 `read_raw` 使用文件原文路由 | worker 不把通用 JSON null 自动解释为授权结果；语义判读由读取合同完成 |

当前原文读取是 `/api/v1/files/{id}/content` 配合 Note 的读 ACL，**没有复测旧向量接口**。原文文件的合法内容也可能恰为字符串 `null`，所以不能对所有 endpoint 统一使用“看到 null 即后端错误”的规则；必须按各端点的已声明合同及原文哈希判断。新原文链成功不能覆盖旧向量失败。

## 5. 哪些诊断已做过，为什么仍不能关闭历史根因

既有受限诊断包括纯 Chroma 12 次、目标 MiniLM 向量 12 次、完整同序 trace-only 15 次 search、固定文本配对计时 12 次、无逐行追踪完整生命周期 15 次，以及历史数据库副本 resident self-query 3 次；均未复现原四个空值。它们的输入、观测方式和状态分别记录，不能把次数合并成独立稳定性样本。

最近的[持久化取证](历史向量空结果_持久化取证_2026-10-27.md)确认 6 次 upsert、2 次指定删除、6 个历史存储向量和最终 4 条活记录一致。向量均为 384 维 FLOAT32、有限且范数正常，SQLite 完整性正常。三个 resident self-query 在原生恢复副本上正确返回最终集合；这是最终状态上的新查询，不是原查询重放。

仍缺失：

- 四次原查询的实际 embedding 数值、摘要和输入到后端时的形状/有限性证据；固定文本及模型资产不足以代替当时实际向量。
- 历史 `ChromaClient.search` 被吞异常的类型、栈、行号及所在阶段。
- 当时的临时内存索引/线程状态及原始 `collection.query` 返回值；打开持久化副本可能恢复内存状态。

旧 worker 的 stderr 未保存，且厂商 `except` 本就未输出异常。现存文件不能无损恢复这些历史信息。因此可以零调用复核“这四格实际违反响应合同”，也可以用受控故障说明 `None` 如何变成 200/null；**目前不能从现存工件原样重放并确定四次历史异常。** 不追加同一思路的无界重跑，不把未复现解释成修好了。

10-27 另有诊断器隔离编译导致的 Pydantic 异常：它已经通过不继承额外 future 编译选项完成零查询纠正。这是当轮诊断器缺陷，历史 v3 使用正常原生导入且已有同函数成功结果，不能把该错误套回历史根因。
