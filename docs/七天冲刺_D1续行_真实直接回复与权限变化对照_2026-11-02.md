## 1. 实际改动与流程

旧路线让模型处理文件与队列运维，工具语法审计阻断了首次正式故事。新适配器只向新WorkBuddy原生会话发送一次直接提示，核对HY3设置和原生转录；等待稳定空闲、核对同一请求和最终回复、拒绝可见工具调用，再由宿主原样保存文本。

新回执明确记录 `desktop_native_rpc / native_assistant_message / savedBy=host`，不能冒充模型原生Write、队列执行或自动记忆数据库。来源回执接纳换成v3；目标调用和费用账本直接继承旧实现。授权、来源依赖与发送前核权规则继续使用同一合同。

```mermaid
flowchart LR
  S[冻结原始来源] --> H[真实HY3新会话]
  H --> V[原生回复绑定与零工具核验]
  V --> M[宿主保存并封存记忆]
  M --> P[真实施加迁出权限变化]
  P --> G[选择合法来源或重建并再次核权]
  G --> D[真实Harness读取并回答]
  D --> E[独立载荷核验与逐题复核]
```

生成输入只包含登记来源和统一模板，未提供目标问题或评分参考。模型写出的来源标签、权限声明都不能改变宿主登记的实际输入依赖。零可见工具、新会话与提示绑定不证明供应商隐藏上下文完整隔离。

资格材料为独立合成文本，不占正式效果分母，但保守计入来源调用上限。原生记录显示1条完整助手回复、0可见工具，输入28,787、输出438 token。否定、计划、虚构归属保留；“未采纳”被附注成“rejected”的强化表达列为语义待审，不能把接口通过等同摘要完全忠实。

## 2. 正式设计与实际执行

正式故事 `personamem-dev-990` 沿用调用前冻结的源材料、问题、权限表和评测合同，来源为公开合成对话。四种方法在三种状态分别运行：

|方法|未变状态|撤关键来源S02|撤无关来源S01|
|---|---|---|---|
|B1 合法完整原文|合法原文|仅其余合法原文|仅其余合法原文|
|B2 权限状态确定后生成|新生成摘要|用合法来源生成|用合法来源生成|

10次正式来源任务均取得绑定原生回复并通过零可见工具检查；12次目标请求均取得合格真实SDK回执，自动重试0。另有资格1次，加上此前失败1次，P2a来源累计12/20，剩余8不自动变为另一个完整10源故事的额度。

Harness为官方SDK的Flash/Max/4096配置，工作区保存实际输入、回复和 `REAL_MODEL_RESULT.md`；这些不等同新增桌面聊天。WorkBuddy原生会话及宿主保存文件均有绑定记录。

## 3. 安全、合法任务与弃答分别计分

独立后验核验器不调用生产 `decision` 或broker函数生成授权真值，直接依据冻结权限表计算允许集合，再核对实际输入、生成依赖、分支事件、交付闭包及Harness读取证明。

**12/12分支保存证据一致，登记业务输入的交付依赖均为当前允许集合。** 原文、实际AGENTS载荷、发送guard和目标原生读取证明匹配。旧包拒绝来自真实运行记录；运行后密钥已销毁，后验检查不是独立密钥重放，也不是一般安全证明。

## 5. 研究裁决与下一步

本轮主要进展是环境路径已通过真实完整对照、授权结果具有独立后验参照，并定位到合法任务损失的具体环节。仍未发现这里完整强基线解决不了的机制问题，也未证明新算法优势。

- 原文与简单单源缓存已解决本故事登记任务，复杂生成分组候选尚未取得进入优势实验的资格。
- 混合摘要的遗漏在“权限未变”时也存在；不能将该摘要问题直接归因于撤权。该类错误已有近邻研究，应继续作为基线改进问题处理。
- 单源缓存避免本次任务遗漏，但源端仍出现归属污染，且增加生成工作；不能称它全面安全、最优或一般100%。
- 目前来源没有证明必须提前生成记忆、之后无法取回来源，或原文超容量。原文与惰性生成仍是必需强基线，不能人为删除它们制造优势。
- 接下来先完成人工复核、补充独立场景与明确的预生成需求证据，再决定继续权限变化的选择性重建，还是收敛为测量研究。扩充正式故事需新阶段配置，遵守现有调用计数与9元费用窗口。

七天方案尚未全部完成。没有扩大平台或将新算法效果预填为成功。公开阶段摘要见[结构化结果](../benchmarks/permission_partition_direct_v3_20261102/summary.json)。本机另备两份各24条的人工复核包，方法标签去除并分别打乱，评分保持全空；来源结构仍可能提示方法，不能称严格双盲，也未将AI结果代填为人工验收。
