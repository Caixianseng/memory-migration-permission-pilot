# Qoder真实源端写盘与交接补证

日期：2026-10-30。**本轮补齐了“Qoder原生Write工具实际产生静态源文件，再交给Harness使用”的有限工程证据。没有验证Auto-Memory，也没有建立新算法优势。**

## 实际做了什么

此前联合验收的源记忆由主机构造。新实验让安装版本Qoder CLI 1.1.77，仅通过原生Write工具，把四条预先登记的合成事实原样保存到新项目AGENTS.md。主机没有代写或修补这个文件；检测、原文定位和后续迁移读取的都是真实产物字节。

源事实是指定的精确抄写，不能称为自主学习、从自然对话抽取事实或原生长期记忆构建。Qoder官方区分静态AGENTS与Auto-Memory，后者需要另外验证写盘和跨会话复用。[官方Memory说明](https://docs.qoder.com/cli/memory)。

源端Qoder收到的是原始合成四行，包含登记邮箱与虚构口令。**本轮保护与披露指标针对后续目标Harness，不证明整个生成阶段“原文从未离开本机”。** 没有向源端发送真实私人材料；真实数据若要求源端供应商也看不到原值，仍需本地构建或另行验证的源端保护方案。

```mermaid
    A[冻结合成事实及外部授权表] --> B[Qoder原生Write]

```

## 三次源端登记均保留

三次使用同一组四条事实，不能计作三个独立故事。前两次没有运行Harness题目。

| 登记 | 源端实际结果 | 归因和处置 | Harness调用 |
|---|---|---|---:|
| joint_run01 / writer v1 | 提示已发送，未得到源文件 | 适配器把原生第二次system/init当异常；保留失败与v1源码快照 | 0 |
| joint_run02 / writer v2 | 唯一Write、成功tool_result、143字节真实文件均有证据，但整体未通过 | 工作区出现额外Windows缓存目录，严格额外文件门禁阻断；保留失败和v2源码快照，不把实际写盘改成完整验收成功 | 0 |
| joint_run03 / writer v3 | 源端全部校验通过，本轮无额外工作区文件 | 仅恢复必要Windows环境变量；Write、路径、内容、额外文件和调用限制不放宽 | 4 |

第一次属于原生客户端适配器状态机问题，不是迁移授权算法失败。本机CLI代码确认控制初始化与首个任务启动可分别发出init事件。v2只允许一个提示后的、工具执行前的额外init；每次仍验证同一工作区、Write-only、dontAsk、模型、版本及空扩展集合。不会重发用户提示，工具后和第三次初始化均拒绝。

第二次涉及运行环境。过滤后的进程漏了SystemDrive、ProgramData、ALLUSERSPROFILE、ComSpec。Windows API说明找不到变量时保留原字符串；本机对照也显示旧环境保留字面相对路径、新环境展开为绝对路径。[微软说明](https://learn.microsoft.com/en-us/windows/win32/api/processenv/nf-processenv-expandenvironmentstringsw)。

**零模型的版本查询、初始化和Hook链对照均没有复现缓存生成，具体创建缓存的组件仍未定位。** 因而只能说恢复标准环境后的这次完整运行未再出现额外文件，不能声称已完全证明缓存的具体因果来源。旧封存包装器没有被静默修改；其相同环境白名单缺口保留为后续版本化核查事项。

所有Windows缓存只做路径和大小核查，不读取内容，不进入公开材料。修复前后保持一次性写入能力和同一工具权限，没有把额外文件加入允许清单。

## 最终源端证据

joint_run03中观察到2个合法初始化事件、1个用户提示、1个Write工具调用和对应成功结果。写入前Hook返回空对象，继续由原生许可执行，没有返回allow来绕过权限判断。一次性claim、事件中的内容哈希、实际文件和登记四行原文一致。

原生AGENTS长度143字节，SHA-256为：

```text
a7cb5bd91c0fcbd756ffbc40953547fa9f4efacee5b934ded5de7983355a4871
```

模型只暴露Write，不能借工具读取其他记忆、联网、运行Shell或修改许可。仅允许登记的新AGENTS路径；禁止已存在文件、链接、其他内容和重复写入。这是受信主机上的工具门禁，**不是操作系统级沙箱或整个客户端进程零副作用证明**。

读取、迁出、复制和恢复许可来自独立受信合成授权表。AGENTS自身没有原生ACL，因此本轮证明的是保持外附授权约束，不能说迁移了Qoder原本不存在的原生ACL。

## 费用与复核边界

目标预算上限0.5元，实际4个Harness调用的保守预留为0.242048元，每次最多64输出token、无工具、零客户端重试。账户前后观测差额为0，供应商账单未核验，不能解释为免费。

Qoder源端配置最多2轮、每轮128输出token。它返回aggregate output_tokens=0，但已有非空工具内容，所以实际用量保持未知，不能把0当实际token数或免费依据。Qoder额度与Harness人民币钱包分开处理。

公开材料提供原生源文件、脱敏目标输入、必要原生事件、冻结输入/代码哈希、关闭后的预测和参考、失败安全摘要及离线评分入口。账户原件、凭证、运行home、Windows数据库缓存及恢复映射均不公开。
