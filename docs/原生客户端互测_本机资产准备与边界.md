# 原生客户端互测：本机资产准备与边界

仓库现在包含本项目自写的请求限制器和去机器路径模板。它们解决旧运行器依赖 Git 忽略目录中的准备资产这一问题；不包含客户端安装包、模型、账户材料或历史原始运行数据，也不表示新机器已经完成实测。

公开资产位于 `examples/native_agent_probe_assets/`：

- `dsh_single_request_guard.mjs`：与已实测自写限制器逐字节一致，SHA-256 为 `dba2d87024b342ebc9fa54a91a2bb195223f6029d578ef12f2a91acad272f8ed`。
- `sdk_guard_metadata.patch.template.json`：JSON 格式的 YAML 兼容模板，保留单请求、64输出token、禁工具等约束；账户文件、会话目录及限制器路径使用占位符。
- `qoder_capabilities.example.json`：固定 Qoder 1.1.77 的待核验模板。`package_version_verified` 为 `null`，不能直接用于推理。
- `asset_manifest.json`：公开资产哈希。它证明当前文件之间的一致性，不替代代码审阅或可信安装来源。

在**干净克隆**中，只准备公开资产：

```powershell
python scripts/prepare_native_probe_assets.py
```

此命令不启动 Node、Qoder、Harness、模型或登录流程，不读取或复制凭据，不联网。输出为仓库中的 `results/native_agent_probe_20261026/`。目录已存在时直接拒绝，不删除、覆盖或追加历史证据。冻结 Harness 运行器和限制器对该目录都有约束，不能简单改成另一个输出子目录后声称兼容。

如果已经安装可信的官方 Qoder，可显式提供安装入口和 Node 路径。下面只是路径示例，需自行替换：

```powershell
python scripts/prepare_native_probe_assets.py --qoder-cli-entry "C:\Tools\qoder\node_modules\@qoder-ai\qodercli\bundle\qodercli.js" --node-executable "C:\Tools\nodejs\node.exe"
```

脚本只读取这些显式指定的安装文件并计算哈希，同时读取相邻 `package.json`，要求包名为 `@qoder-ai/qodercli`、版本为 `1.1.77`。可用 `--qoder-package-json` 明确指定同一安装布局的包文件。脚本**不会执行** `--version` 或查询模型目录，因此不能据此声称运行版本、账户可用性、模型选择器或费用已验证。Node 的实际运行版本也仍待独立检查。

生成的路径已适配当前克隆；`sdk_guard_metadata.patch.yml` 中的账户路径只是字符串占位用途，没有创建账户文件。真实 Harness 调用器会将其重新绑定到每次新建的隔离运行目录。`qoder_capabilities.example.json` 仍保持未合格；脚本有意不生成运行器默认读取的 `qoder_capabilities.json`。

## 独立元数据预检

提供安装路径后，`manual_metadata_commands.json` 会列出四组参数数组：Node版本、Qoder版本、Qoder帮助和模型目录。它们都没有执行；catalog 命令不包含问题或 `--print`。必须另行明确执行，不能把 bootstrap 的准备成功当作预检成功。

手动执行时应使用参数数组，保留 `--tools` 后的空字符串，并逐次注入文件中的进程级环境覆盖。不要直接拼成 shell 字符串，以免丢失空参数或改变转义。只核对版本、必要开关及 `DeepSeek-Flash` 选择器；账户失败不等于模型不可用，更不等于成功。

核验通过后，由操作者保存本机元数据证据，在独立副本中填写真实的 `package_version_verified`、Node版本和目录核验结果，再保存为 `qoder_capabilities.json`。需要同时确认入口哈希仍与本机文件相同。仅修改一个版本字段或重命名样例不构成元数据证据；冻结调用器本身也不会替操作者完成完整模型目录审计。

元数据查询可能访问服务端目录，但不应发送推理请求；准备脚本不会代为执行。真实问题调用必须是之后单独授权、限制次数和输出预算的步骤。当前没有可验证的 Qoder 货币硬上限，CLI返回0费用也不能说明免费。

## 尚未解决的跨机边界

- 本次未更改冻结原生核心。`deepseek_native.py` 的 `INSTALL` 常量、原主运行器显式传入的凭据源路径仍保留原执行机器布局。另一台机器应先核对这些限制，并在后续独立版本中支持显式路径配置；本准备步骤不能让旧运行器在任意机器自动可用。
- Harness 仍需合法安装并有可用的原生账户。准备脚本不安装、不登录，也不提供或复制 `.credentials.yaml`；显式运行的原生调用器与资产准备是不同阶段。
- 固定模板针对已测 Harness 0.2.1-rc.3 和 Qoder 1.1.77。其他版本的工具、插件和接口需要重新核验，不能通过改版本字符串扩大支持范围。
- `AGENTS.md` 是原生上下文，不是原生逐次ACL或即时撤权。统一交接包由外部可信主机校验；模板不将它升级为产品原生权限协议。
- 历史故事、原始响应、身份数据和本机安装资产不随 Git 克隆提供。四条件成功、失败、补测和成本边界以各次冻结实测报告为准，准备脚本没有产生新的效果证据。

仅运行假安装测试：

```powershell
python -m unittest discover -s examples/native_agent_probe_assets -p "test_*.py" -v
```

测试使用临时安装文件，并确认不启动客户端、未核验能力样例被现有运行器拒绝、错误版本和重复输出不会静默通过。它们不调用模型，也不代替原生客户端实测。
