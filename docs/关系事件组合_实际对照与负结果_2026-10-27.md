# 关系事件组合：实际对照与负结果

日期：2026-10-27。结论：本轮事件抽取方案未达到预先规定的推进条件，不替换默认方法。当前更有效的对照是简单的本地直接分类，但它也未达到项目验收。

## 1. 做了什么

实现 `relation_events.py`：模型从原文提出客户关系事件；程序检查双方位置、方向、肯定/否定、时间范围和来源绑定，再组合判断。与新跑的直接分类及固定规则进行同材料对照。

按 [预注册](关系事件组合_有界开发对照预注册_2026-10-27.md)，使用 12 条已曝光的中英文开发正文及同一封存自动候选池。三臂各 12 个观察位置，共 36 行；不是 36 个独立样本。两个候选超限的正文在所有臂中均保留为覆盖不足，没有截断候选放行。

实际使用 Ollama 0.40.8、`qwen3:4b-instruct-2507-q4_K_M`，固定完整模型摘要、温度 0、seed 42、4096 上下文、1024 输出上限。直接分类和事件法各调用 10 次，共 20 次本地生成；另外 4 次请求为本地版本/模型核查。总执行时间 37.25 秒。云端、付费 API、原生后端调用及修复重试均为 0。

## 2. 实际效果

| 指标 | 直接分类 | 固定规则 | 事件抽取＋组合 |
|---|---:|---:|---:|
| 确定案例精确完整正确 | **7/10** | 2/10 | 3/10 |
| 确定案例可准备脱敏请求 | **7/10** | 2/10 | 3/10 |
| 未知案例正确待审 | **2/2** | 2/2 | 0/2 |
| 未知案例错误当成非敏感放行 | 0 | 0 | **1** |
| 精确片段 TP / FP / FN | **4 / 0 / 2** | 1 / 0 / 5 | 0 / 0 / 6 |
| 片段精确率 | 100% | 100% | 无有效正预测，未定义 |
| 片段召回率 | **66.7%** | 16.7% | 0% |
| 模型输出校验失败 | 0 | 不适用 | **6/10 次生成** |

直接法四个成功准备的参考敏感片段均实际完整遮蔽；其余两处正例随请求阻断，仍计入漏检分母，但不能称为已经对外泄露。事件法没有成功准备的参考敏感正例，不能把“观察到零原值残留”解释为隐私表现更好。

事件法总计可准备 4/12，其中一个属于本应待审的未知案例，因此**合法确定案例可准备数只有 3/10**。表中避免把错误放行计为效用收益。

这里“可准备”指本地授权与脱敏层生成了载荷；没有让下游 Agent 回答任务，不能宣称拒答率下降或回答正确率达到上述比例。

## 3. 当前能定位的问题

直接法的三个确定案例失败可定位为：

- 两个候选池各返回 3 个候选，超过原先预定的 2 个上限。其中一条有真实机构与 `our company` 候选混合，另一条是三个普通角色词。它们是当前候选预算与表示方式的限制，不是文本本身无法理解的证明。
- 一条同时包含 `splice` 的普通词用法和组织名称用法。直接法识别了机构出现位置，却把另一个普通词出现位置留为未知，导致整条阻断。

事件法六次输出未通过校验。所有 20 次模型生成均返回 `done_reason=stop`，没有达到 1024 输出上限；本轮不能将失败归因于输出截断。具体结构、位置及语义错误另按封存原始响应核对，不修改原预测补成绩。

封存后只读重放得到以下诊断，未增加模型调用：

| 六条无效输出的首个校验错误 | 数量 | 正文序号（从 0 开始） |
|---|---:|---|
| 参与方不是当前候选＋业务主体 | 4 | 1、5、6、11 |
| 引文与数值位置不一致 | 2 | 3、7 |
| JSON 语法错误或生成截断 | 0 | — |

这些类别按首错互斥。进一步检查存在重叠错误：5/6 条共 7 处位置与引文不匹配。第 6 条的位置字串全部匹配，却把两个外部组织组成交易双方，遗漏“本公司”，说明只修数字位置仍不足。

未知案例的错误放行发生在第 9 条：自动候选只有“联盟”，完整原文名称是“雾稞仪表联盟”。事件模型将这一候选判为泛称，返回空事件，组合器于是放行。这是候选边界与实体语义联合错误，原文位置核对无法证明类别正确。

事件法的全部 4 条 `ok` 都来自 `not_specific`＋空事件，其中 3 条碰巧得到正确的最终负判定。本次没有一条非空客户事件通过校验并产生正确敏感预测，不能将 3/10 表述为事件推理已有部分有效收益。

当前三个模型或规则方案共享同一候选覆盖限制。将事件法与固定规则比较时，也必须保留更强的直接分类结果，不能选择较弱对照来宣称提升。

## 4. 消耗与方法比较边界

| 实际消耗 | 直接分类 | 事件抽取 |
|---|---:|---:|
| 生成请求 | 10 | 10 |
| 输入 token 合计 | 3,439 | 5,029 |
| 输出 token 合计 | 199 | 2,196 |

两臂的模型和预算上限一致，实际提示长度与输出消耗不同。事件法输出约为直接法的 11 倍，本次效果却更差。这个结果反对在当前模型与合同下继续增加抽取层，但不能推断所有事件抽取模型都无效。

本批材料、候选和提示形式不同于更早的自由抽取实验，因此不能把历史分数变化完全归因为某一条提示或单个组件。这里的核心比较是同批新跑的两个模型臂。
