# 引用构建对照：选择同构、格式与成本核对

核对对象：`results/reference_memory_development_20261025_v1`。只读取已保存输入、输出及账本，新增模型调用为 0，未修改原结果。独立脚本为 `scripts/analyze_reference_memory_mechanisms.py`，完整收据位于该运行目录的 `mechanism_analysis_v1/`。

## 1. ID 选择与整段引用选中了相同记忆

两种选择方式的 8/8 故事 `selected_fids` 相同，事实文本、来源连续位置、独立检测标签和记录中的源证据/ACL 均相同。40 对任务中遮蔽评分也完全相同。32 对合法任务均实际调用了回答模型；仅将合法请求代号中的随机 nonce 归一化后，32/32 的实际 outbound 与完整模型请求都相同，普通文本、类别、序号及消息结构没有被归一化。

相对 `retain_all`，两种选择方式仅分别丢弃中英文客服工单的最后一行：英文为账户标签保密提示，中文为账户名称内部保管提示。账户持有人及服务环节的独立源行仍保留。其余六个故事全部候选均保留，包括公开机构、承运商及含不可信便条的整行。这是根据 runtime 源位置所作的事后语义描述；分析程序未解析 evaluation 标签，不能据此声称实现了通用任务最优压缩或攻击过滤。

当前候选粒度主要是整行/结构块。无换行的长故事只有一个候选，模型不能在其中进一步选择或压缩事实；这也是本次大多数故事全选的重要解释。

## 2. 27/32 与 26/32 不代表 ID 选择提高了任务效果

原始主成绩分别为 27/32、26/32。两臂只有 `dev_zh_04/private` 的主正确性不同：ID 臂返回完整带括号的当前请求代号，quote 臂返回完全匹配的裸代号，后者被原恢复规则阻断。严格序列化修复为裸代号补回外层括号后，该题也能通过同一完整核权恢复。

Secondary 均为 29/32，逐题正确性完全一致。剩余共同失败为：

- `dev_en_02/paraphrase`：两臂模型均返回 `UNKNOWN`。
- `dev_zh_02/private`：检测只遮住组织后缀，模型输出未遮住的名称前缀。原值未被完整保护，合法回答也不完整。
- `dev_zh_02/paraphrase`：ID 臂返回只对应组织后缀的代号；quote 臂返回 `UNKNOWN`。两者均未得到完整合法答案。

本轮选择内容、标签和回答输入的结构相同，原始一题差异可直接定位为回答代号的序列化格式差异。随机 nonce 的 token 化、调用顺序或本地推理数值变化未被固定 nonce 的重复实验分离，不能声称已证明“完全由 nonce 引起”。Secondary 是对同一原始回答的附加诊断，不替换已冻结主成绩。两者共同的 29/32 仍包含检测边界和模型回答问题，不能归为已经解决的随机波动。

## 4. 当前可采用的结论

引用 ID 是在本批暴露开发材料上减少选择器输出长度、避免回抄/字段归属错误的标准工程方案；本轮没有证明它比整段引用选择保留了更好的事实或提高了问答正确率。后续主线应优先处理完整敏感名称的边界和合法任务 `UNKNOWN`，继续保留真实 A→B 来源、签名、ACL、迁移检测与完整恢复核权。论文创新、独立泛化和总体效果验收均不能由本次 8 故事成本结果替代。
