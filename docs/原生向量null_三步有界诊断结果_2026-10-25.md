## 纯 Chroma 控制

真实 Chroma 1.5.9，384 维有限非退化 float32 公式向量，原生 PersistentClient；未使用 Python list 模拟检索结果。固定 `n_results=100`，6 条合成记录、3 次 upsert、2 次指定 delete、12 次 count/get 和 query。删除前合法数量 2/3/1，删除后 1/2/1，每次实际 query 均完整返回对应 ID、文档和元数据。44 次原生存储操作完整记录，网络事件 0、模型模块加载 0、代码/原生二进制摘要后验一致。

这一控制未复现错误；它没有经过 WebUI 适配器、真实查询编码或 async 工作线程，不能据此排除这些路径或声称底层组件绝无问题。

## 目标端观察

使用旧 v3 实际 target add 的 3 条文本/路径和三个 resident 的原文本/路径投影，未使用旧数据库，也未把完整源文或 source-only canary 发送给新目标。仍为 OpenWebUI 0.12.3、Chroma 1.5.9 和相同本地 MiniLM 资产；实际创建新的原生用户/JWT 与集合。

每次 HTTP 查询只调用 original Chroma.search 一次，真实查询向量形状 `[1,384]`，全部有限，12 次向量哈希相同，`np.asarray` 观察到的输入表示 dtype 为 float64（不把它当作模型权重 dtype）。运行时 relevance threshold 均为 0。调用来自两个工作线程，全部返回 SearchResult，trace 均在 finally 恢复。

此观察器在 original search 前增加了 count/get 读取，且请求顺序比完整桥接更短；它可能改变缓存或时序。故 12/12 结果不能作为“增加 count/get 已修复”的因果结论。67 份自有源码归档、21 项资产前后核验通过；网络仅有已观察到的本地 capability bind 与标准库 socketpair，无被拒外联。

## 完整同序 trace-only 观察

新 launcher 在调用原 `run_native_exact_fact_bridge.run` 前预注册并归档两个新增控制流文件。作用域内的 WorkerRPC 工厂只把目标脚本替换为新 subclass，源脚本和 RPC 参数保持原样；调用结束后恢复工厂。原完整结果保存在 `standard_run/`，原来的 64 份源码档案不被描述为包含新控制流；新增两份位于独立 `trace_implementation/`，均完成执行后摘要核验。

该 worker 不在 search 前后增加 count/get，不读取或改写向量，不更改 query、k、阈值、授权、返回对象、except 或重试行为。它只在 original search 的真实线程临时启用 `sys.settrace`，匹配原函数 `__code__`，捕获被吞异常的类别、消息哈希、代码行和阶段。额外仅识别固定公开错误模板标记及明确 dimension 数字，不采集异常消息原文、locals、token 或认证凭据。

6 个 snapshot 的第一个为空账户，原生 3 个 404 不进入 search；其余 5 个阶段 × 3 用户恰好 15 次 search。15 条 trace 均与实际原生 HTTP `/memories/query` 的 request index、actor 对齐；每个主体恰好 5 次、每次 original 调用 1 次，返回均为 SearchResult，finally 均恢复。29 项原标准通过；source/target embedding 调用严格为 2/21，生成 0，网络阻断 0。标准 64 份归档、15 项资产、8,875 SDK 文件及额外两份控制流的完整性均通过。

## 当前可成立的结论

原 v3 确有四个真实 JSON null；原生适配器吞异常并返回 None 是已核实的潜在丢失错误信息路径。三步受限诊断均未复现，被吞的具体异常至今未取得，因此**根因未知，没有确定修复**。trace-only 同序成功增加了一条有明确观测差异的完整受控资格证据，不足以证明稳定性、跨样本泛化、原生索引可靠性或整个项目已通过。

保留原 v3 失败工件及文档；下一次实验需另行明确新假设或可复核的复现依据与预算，不能无限重跑直到得到绿灯。普通 ACL、签名事实范围和显式清理仍属于工程强基线，不因本次诊断成为论文新算法。

主线程随后运行独立原生验证器，同序`standard_run`工件核验通过：164份HTTP观察、15份非空向量正控、27次源网关读取，以及64份归档、15项资产、8,875 SDK文件逐项一致。其核验不使用producer通过标志；新增两份注入控制流另外核查，不混入原64份。公开汇总见`benchmarks/native_exact_fact_bridge_20261025_summary.json`，仍明确稳定性与总体论文目标未通过。
