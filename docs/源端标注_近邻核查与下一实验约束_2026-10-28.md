# 源端标注：近邻核查与下一实验约束

日期：2026-10-28。本轮为上一轮真实负结果后的方法复核。研究目标仍为 Agent 记忆安全迁移与权限保持；以下资格检查不替代原自然语言检测、独立下游任务、原生环境及论文创新验收。

## 1. 已被实际结果排除的解释

上一轮 24 条开发正文、28 次本地生成中，源端把“该机构正在向本公司购买展示柜”标作 CUSTOMER，而未标作为机构名的第二个“苔藓”。签名、JSON 交接和接收方并集保持了错误位置。确定案例可准备从 18/20 降至 11/20，已准备载荷漏遮仍为 1 处。源标签迁移与拥有相同两份检测输出的接收侧并集全部 24 例等价。

因此，增加签名或调整标注时机没有解决此次语义错误；不能把新增源检测带来的信息增量当成迁移协议优势。完整结果见[真实对照报告](源端上下文标注_实现与真实对照结果_2026-10-28.md)。

## 2. 已有事实卡实际能做什么

`memory_migration_study/source_fact_cards.py` 的组织角色卡先读取 `record['label']['findings']` 中已有 CUSTOMER 正标签，再按冻结前缀语法寻找角色锚点。它不独立提取组织，也不补齐空候选。`SourceFactCardTable` 绑定当前用户、Agent、授权实例、策略和生命周期，并明确禁止序列化，是本地主机的派生证据表。

可复用的是当前授权、记录哈希、精确位置与策略校验。不能直接把该表称为源业务系统提供的实体真值或跨 Agent 通用传输包。

本轮读取 examples 文件清单确认已有自然语言运行材料、与其分离的评分文件、表示因子实体文件和公开数据适配入口。仅凭文件名不能认定某实体文件是先于记忆产生的业务输入；必须逐项核实来源链、生成顺序与实际执行入口。尚未建立下一实验所需的源字段资格。

## 3. 一手方法与直接重合

以下为截至本次检索的定向核查，不是完整系统综述，也不表示已复现作者成绩。

公开 [xmemory Splitwise 数据](https://github.com/xmemory-ai/datasets/tree/main/splitwise)的 README 与目录已核：它是自动生成的费用事件及余额问答，提供生成代码。可用于考察结构化事件记忆，但不是客户关系/中文否定/权限迁移的现成金标。此处未下载数据、未运行生成器或作者模型，也未把它替换为当前验收集。

## 4. 下一实验必须先验证的前提

若采用源原生字段，应先在真实输入或工具响应中证明以下内容先于记忆和评分存在：来源对象 ID、实体 ID 与名称、关系类型与方向、事件/有效时间、已认证来源及独立权限。若只有正文，则属于重新抽取，需按检测方法评价，不能称来源原生真值。

源 Agent 可以选择已有对象/字段引用；可信主机按实际输入渲染记忆与精确跨度。不能从评分文件填字段，不能依据目标输出倒推原始标签，不能让模型输出的 `admin`、`owner` 或关系状态变成授权。

如果需要重新生成公开合成事件，应明确是受控工具源场景：先冻结生成器与政策，再生成输入；输入与评分程序隔离。它只能证明相应信任前提下的工程资格，不关闭原自然语言检测门槛。

## 5. 同信息强基线与停止条件

至少比较三个条件：正文接收方检测；同源字段的普通 JSON 传递与完整独立 ACL；项目协议携带完全相同的字段与当前核权。后两组必须得到相同源信息，不能通过信息量不同建立算法优势。

首批资格检查可覆盖当前/历史客户、反向供应关系、从未采购、未知关系、同名普通词与机构。先核字段血缘、精确定位、实际漏遮/多遮蔽、合法准备、待审、跨用户/Agent、篡改和撤权，再决定是否需要模型任务。可靠正保护继续继承；一个否定判断不能静默删除已有保护标签。

停止与解释规则：

- 找不到合格源字段，不运行新的“源原生字段”模型实验，也不把手写评分标签改名为业务元数据。
- 与普通 JSON＋完整 ACL 同样通过，仅记录标准工程能力，不能扩写成新算法优势。
- 未改善漏遮或增加不必要阻断，保留负结果，不扩样本或反复改提示刷分。
- 没有迁移独有失效或安全/效用/成本优势，论文贡献保持未成立；可以继续寻找真实异构后端的测量差异。

## 7. 本轮已经执行的接口修复与证据闭环

实际复现发现，请求字段顺序问题位于 `candidate_context_batch.build_request`：候选池经过排序JSON保存并读回，池语义与池哈希相同，嵌入候选的字典字段顺序却改变提示字符串及请求哈希。没有将该问题误归因于模型或迁移丢数据。

新增显式版本 [candidate_context_batch_v2.py](../memory_migration_study/candidate_context_batch_v2.py)。它递归固定JSON对象键顺序，保留数组顺序、原文Unicode、空白、符号及字符位置；使用新版本/spec/hash，旧冻结实现与结果不修改。这是项目受限JSON契约，不是RFC 8785/JCS完整实现。

解码必须携带保留的v2请求，并重新计算摘要后与当前输入重建请求核对；拒绝v1、策略/模式/摘要错配、非有限值，以及保留旧hash的整数/浮点或布尔换型。仅用Python对象相等会把`True`与`1`等视为相同，因此不足以校验请求。该接口不能证明记录的字节实际发给了模型，真实实验仍须保留外部捕获证据。

本轮50项直接相关离线测试通过，其中16项为新增v2测试，0失败/错误；plain/marked两模式经JSON往返一致，见[接口聚合摘要](../benchmarks/candidate_request_roundtrip_v2_20261028_summary.json)。没有真实模型或网络调用。这不是全仓CI、检测效果或下游任务验收。v2改变了模型实际看到的字段顺序，不能把旧版本响应登记为v2的真实调用；后续须按新请求版本冻结并运行。

上一轮源端标注批次的[独立审计](../benchmarks/source_annotation_independent_audit_20261028_summary.json)也已实际完成：231个冻结源码、5份历史输入和76份捕获文件哈希一致，72格独立重算与原结果相同，80次权限反例和24组强基线等价均核实。审计不重新获得临时HMAC密钥，也不构成离线重新验签或外部时间见证。

## 8. 原自然语言检测门槛的工程基线候选

源原生字段场景不覆盖现有自然语言检测失败。为了检验当前失败是否受到模型能力限制，另核查了[Qwen3.5 4B Q4_K_M](https://ollama.com/library/qwen3.5:4b-q4_K_M)与[9B Q4_K_M](https://ollama.com/library/qwen3.5:9b-q4_K_M)：官方页面体积分别约3.3GB、6.6GB，短摘要分别为`d8b0f5e9760c`、`56671c2ab938`。短摘要不是完整模型固定凭据，下载体积也不是峰值显存。

[官方4B模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)与[思考控制文档](https://docs.ollama.com/capabilities/thinking)提供关闭思考的接口依据，[Ollama结构化输出](https://docs.ollama.com/capabilities/structured-outputs)提供JSON schema依据。[v0.17.4发布说明](https://github.com/ollama/ollama/releases/tag/v0.17.4)已有Qwen3.5支持先例，但本机v0.40.8与具体量化、grammar、GPU runner的组合仍需实际资格核验。本轮未下载或运行新模型。

下一批应优先检查4B的本机资格，固定完整manifest/blob摘要、运行版本、关闭思考、4096上下文与1024输出上限。沿用同一识别方法、提示、策略和评分，只更换模型；若方法必须适配接口，先用无模型合同检查明确差异，不能把提示改动和模型改动混在一起归因。

可采用预先冻结ID的12→24条嵌套开发批次，初始12条不重复调用，每条最多初始一次与既有格式/定位修复一次，全部24条总上限48次生成。前12条若存在运行失败、静默截断、更多实际漏遮或更多已知案例阻断，就停止该候选；通过后才补剩余12条。需要按这些相同案例比较旧基线，失败和待审均保留。以上尚是资格约束，具体ID、适配器和输入哈希未冻结，不能称已完成预注册。

换模型只是一项工程强基线。24条已暴露材料即使通过，也只能进入方法冻结和新独立材料阶段，不能直接宣布原P90/R95、63/64联合成功或论文创新达标。
