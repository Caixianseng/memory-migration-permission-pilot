# V1 engineering results

This is one predeclared CPU campaign, not another model-quality evaluation:
8 fixed fault schedules × 3 methods = 24 rows; 10 controlled synthetic size
fixtures × 3 methods × 6 commits = 180 normal delivery rows. All methods receive
cloned closed initial stores, identical sealed packets and authority events.
The ordinary ACL comparator has receiver-local commits and separate seal
consumption. Strong transaction B and Gateway C share exactly the same mature
transaction/recovery kernel.

`regression_outcomes.csv` and `performance_measurements.csv` retain every
predeclared method/scenario/normal-commit measurement, including failures and
latency outliers. There are no exclusions or post-result threshold changes.
`project_measurements.csv` gives fixture-level descriptive aggregates. Ten
fixture sizes are controlled engineering inputs, not ten sampled organizations
or independent natural-world datasets. No CI or significance test is reported.

`summary.json` defines measurement scope and nearest-rank P95. Logical SQL
counts include observed timed SQLite trace statements, including read-only
receiver verification; they are not physical disk I/O. File sizes are observed
bytes. Large timing observations remain unchanged and their cause is unknown.

`campaign_completion.json` binds the full local raw CPU files, SQLite stores,
worker/ACK/crash evidence and captured code to SHA-256 values. The independent
verifier checked 136 receiver/policy databases and all saved artifacts without
rerunning schedules or writing databases. Its public summary links the full
local verification by hash.

Raw CPU SQLite stores and complete worker records remain locally preserved.
They can be regenerated using the frozen runner/contract; this directory is a
public results export, not a claim that binary raw stores were uploaded. The
engineering chart is supplied as SVG here; its PNG counterpart remains in the
local analysis directory and is included in the figure provenance manifest.

`archived_platform_replay_summary.json` records two explicit file adapter
checks using previously recorded WorkBuddy HY3 and Harness Flash outputs. No
new platform inference occurred. No raw commercial interaction files, native
private folders, platform tokens or account metadata are included here.

The old C reproduction is separately summarized. It is not a newly discovered
leak: the reproduced defect is the inability to confirm an already committed
effect after authority changes. Production uses the mature transaction path;
legacy orphan databases are never silently migrated.

The preserved interface test log has 13/14 PASS: its one historical assertion
expects a different integrity error name despite actual HTTP409 rejection.
All eight fixed strong-core safety/recovery cases pass. This non-core mismatch
is visible rather than edited into a reported all-tests-PASS result.
