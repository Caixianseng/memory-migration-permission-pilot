# 关系证据卡：结构化记忆近邻与可证伪边界

日期：2026-10-25。本轮限四组检索，随后只打开作者论文、论文直接链接及官方仓库；未下载、安装或运行作者代码，未调用收费研究 API 或模型。本文是研究备忘，不是算法效果或完整系统综述。

## 1. 结论

“把记忆改成角色/事实/证据卡，再让模型更准确回答”已有明确近邻，应先作为工程强基线。现有 Union 标签与显式角色投影在本项目八个开发故事中已经覆盖 20/20 个角色值；另一个模型仅达到同一分数，不能证明超越完整基线，也不能证明下游问答改善。

可以继续检验的具体问题是：**跨后端只获准投影部分事实时，卡片中的角色、实体值、关系参数及支持文字是否共同具有当前合法的精确事实依据；在不向问题内容授予事实资格的前提下，这种限制能否改善安全—合法效用—成本的取舍。** 这仍是待证问题。完整来源依赖与当前权限重算也应满足同一安全要求，不能把它故意做弱。

上述固定 v1 页面用于核对机制，不表示已检查每篇的最新修订或正式录用状态。官方当前仓库也只作能力说明，不作为本项目已复现的证据。

[Graphiti 官方 README](https://github.com/getzep/graphiti) 当前明确列出来源 episode、带有效期的三元组和自定义类型，并说明应用需自行建设 tenancy、access control 与运行服务。因此不能将“框架不是完整权限产品”说成安全缺陷，更不能据此省掉应用层完整 ACL 基线。[A-Mem 官方仓库](https://github.com/agiresearch/A-mem) 提供内容及上下文/关键词/标签管理与检索接口，属于结构化记忆的可实现对照参考。

## 3. 新发现的 2026 近邻：LongMemEval-V2

沿原作者仓库链接核对到 [LongMemEval-V2 官方仓库](https://github.com/xiaowu0162/LongMemEval-V2) 与 [arXiv 2605.12493v1](https://arxiv.org/html/2605.12493v1)，论文日期为 2026-05-12；本次未核查其期刊/会议录用状态。

它让记忆模块返回 compact evidence，再交给固定 reader；原始状态切片、切片加 notes、多个知识池与 agent 组装证据均有对照。论文 §3.4 的 oracle 证据实验本身使用支持轨迹/切片标签，只能作为阅读上限，不能照搬为在线方法的输入。官方 Query 接口对方法隐藏 question ID/type、gold 和评分配置，是本项目需要遵守的隔离参照。

其任务含错误前提识别，进一步说明“问题中说了某关系”不能直接充当记忆证据。该工作不是本项目授权迁移基准：不能把其问答数字与本项目受控 32 题比较，也不能把它没有作为主目标测试权限迁移解释为无人研究。其默认固定 reader 和资产规模也不等于本机四位量化 4B 配置；本轮没有尝试复现。

## 4. 一个可证伪的区别

测试对象应是**整张关系卡的合法见证闭包**，而不是只验证实体值在有权文本里出现。

例如，获准事实 A 只说“项目甲的合作组织为组织 X”；另一条未获准事实 B 说“组织 X 是项目乙的买方”。如果卡片用 A 的组织值，配上 B 的“项目乙—买方”关系，仅核对值跨度会遗漏关系来源。用户在问题里断言这一关系，同样不能提供授权或记忆事实依据。

拟比较的干预要求：卡片的角色、值、关系参数、语法支持与原文位置必须能回到当前获准的精确事实；不满足时不生成该卡。若支持来自多个输入，必须明确哪些输入共同必要，不能凭文本相同宣称来源独立。撤权后，新上下文只使用仍有效的完整见证；不能通过重新签发授权伪造“保留旧独立授权”的成绩。

**可证伪主张**：在固定事实候选、检测、用户/Agent身份、模型与预算后，合法见证卡提高安全与正确回答同时成立的比例，或在与完整依赖重算等安全、等效用时显著减少实际成本。若它只是让已知八故事答对，或与完整强基线安全/效用相同而没有成本优势，该主张不成立。已有 IFC、来源传播及独立授权工作也约束这一主张，不能将“闭包”名称本身当成新算法。

## 5. 必须保留的强基线与消融

1. **当前完整文本强基线**：相同的真授权、Union 生成标签、问题检测、假名化与恢复；格式兼容若启用，对全部组对称启用。保留缺失事实、越权、失败和待审分母。
2. **结构化阅读强基线**：同候选池和同授权过滤后的普通 JSON 事实卡；另以相同预算比较摘录后回答的 CoN/证据阅读，不能只比较原始提示。
3. **显式角色规则基线**：复用现有 Union 值跨度和通用角色锚词，不调用额外模型，不读取参考答案或固定公司词典。已有 20/20 是源角色覆盖结果，后续必须测实际问答。
4. **完整来源依赖强基线**：每次按当前权限重算所有卡片字段依赖；支持预先已有独立来源与策略版本缓存。不能只给候选方法完整依赖、给基线粗糙交集，再宣称安全胜出。
5. **消融**：去掉角色信息但保留相同值；只检验值而不检验关系支持；保留来源而去掉当前权限重查。后两项是明确的不完整诊断条件，不能作为唯一主要竞品。

建议先在已暴露材料上做机制资格检查，再冻结方法与阈值，建立新独立材料。更应增加跨记录借用、同名不同来源、问题自带错误关系、源撤权与仍有效独立见证的配对任务。以完整卡片可用性、未授权关系披露、合法联合成功、真正 UNKNOWN、检测/恢复阻断和实际开销分层报告。源角色 20/20 或引用字段存在均不等于问答成功，也不替代原检测与原生稳定性验收。

如果完整标准基线在同条件下同样安全、效用相同且成本更低，下一步应调整研究问题；不能继续把“结构化卡＋HMAC＋权限”组合包装为创新。可能成立的交付形式还包括跨后端投影失效的可复现测量基准，但它同样需要对既有来源/权限工作逐项比较。
