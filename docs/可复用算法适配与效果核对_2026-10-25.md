# 可复用算法适配与效果核对

日期：2026-10-25。参考用户提供的《可复用算法与项目清单》，在现有 Python 工程内加入两个可选模块：受目标约束的加权角色覆盖、绑定可信上下文的检测缓存。原来的默认流程和历史实验继续保留。

本轮确认了配置成本和重复检测开销的收益；**没有确认漏检率或合法问题回答率改善，也没有建立新算法或论文创新结论。**

## 1. 清单中采用了什么

| 参考方法 | 本轮处理 | 原因 |
|---|---|---|
| 角色挖掘／二部图覆盖 | 增加 `role_cover` 规划基线 | 能直接输出现有容器、对象及副本映射 |
| 内容、策略、检测器绑定的缓存 | 增加进程内检测缓存和完整成本对照 | 用简单强基线核对“生成时标注减少调用”的贡献 |
| 策略关系验证 | 独立实现有限请求域检查器，导出新增／缺失关系 | 当前域很小，可以穷举交叉验证；它不是 Cedar/SymCC |
| Cedar、PAM、SpiceDB、Biscuit、Qdrant 等 | 保留为后续集成参考 | 本轮不需要增加授权服务器、数据库或新语言运行时 |

角色覆盖的文献依据为 Tripunitara 的 [Minimizing the Number of Roles in Bottom-Up Role-Mining using Maximal Biclique Enumeration](https://arxiv.org/abs/2407.15278)；核查了[作者仓库固定版本的 README](https://github.com/tripunit/minrolemining/blob/f3aecc9948d0214cf4ed1099d4ab477916a78a4d/README.md)。作者精确求解路径使用 Gurobi。本项目没有复制其源码，也没有声称复现整套论文算法；这里使用标准覆盖建模，独立编写适合小规模测试的有界搜索。

## 2. 针对本项目的角色覆盖适配

### 2.1 通俗解释

把一条“主体可以读取记忆”的合法关系看成一个必须覆盖的格子。主体是已经绑定的“用户＋执行 Agent”，不是记忆中自称的身份。

一个容器对应一组读者。把某条记忆放进容器，就让这组读者拥有该记忆的读取关系；它只能覆盖明确允许的格子，不能填补未知或拒绝的关系。同一条记忆可以放进多个容器，但必须有明确复制许可。

本轮目标为：

`总代价 = 容器数 × 容器权重 + 对象放置数 × 副本权重`

“对象放置数”包含第一份内容，不仅是额外副本。默认权重为 4 和 1，属于示例成本单位，**不是实际人民币费用**。可以改权重，不能把少建一个容器自动视为整体更优。

### 2.2 新增约束

1. **迁出与复制分开。** 未批准迁出的对象不进入目标。复制为 false 或 unknown 时，仍可在一个完整读者组中放置一次；不能拆成多份。
2. **容器隐含所有者。** `implicit_readers` 表示任何容器都会获得读取权的主体。如果该主体本来无权读某条记忆，这条记忆不能部署到此目标。
3. **目标可表达的读者组。** `allowed_reader_sets` 限定目标实际支持的有效读者集合；不生成目标无法部署的组。
4. **完整覆盖可部署关系。** 求解器不能通过少迁数据、漏掉合法读者来降低成本。因授权未知或目标语义无法部署而排除的对象，单列原因和合法关系损失。
5. **有界求解。** 小域枚举全部读者子集，结合有界分支搜索；超过规模或搜索预算时保留完整、安全的可行配置，并明确标记 `optimality=not_proven`。

没有只枚举“极大矩形”：计入副本成本、禁止复制和受限目标集合后，不能直接套用“只最小化角色数”的结论。默认小域上限为 8 个主体，搜索状态上限为 30,000；搜索证明只针对声明域中的可部署子问题。

### 2.3 独立检查器

`plan_verifier.py` 不调用规划器或 `decision()`，直接根据共同策略重建合法关系，再从容器、对象及副本映射计算实际关系。它检查：新增权限、合法关系缺失、未知、内容一致性、唯一 ID、完整映射、复制资格、目标组约束、身份映射及隐含读者。

授权参照和目标约束由检查器调用方提供；被检查的计划不能通过修改 `source_only` 标志来改选更宽松的参照。对这一点增加了专门反例测试。

模型检查以后，合格配置继续交给现有参考 HTTP 后端，以独立主体凭证实际探测 `read` 和 `list`。这不是 Open WebUI/Cognee 原生部署，也不是无限请求空间证明。

## 3. 权限配置实测

8 个合成场景、每个 3 种配置，共 24 份计划。4 份违反目标约束的旧基线计划在预检阻断，20 份进入参考 HTTP 探测。

| 场景 | 原配置 | 适配结果 | 如何解释 |
|---|---|---|---|
| 重叠读者 `{a,b}`、`{b,c}`、`{a,b,c}` | 相同读者分组：3 容器、3 对象、成本 15 | 2 容器、4 对象、成本 12 | 成本降低 20%，复制增加 1 份，合法关系全部保留 |
| 副本成本提高为 8、容器为 1 | 3 容器、3 对象、成本 27 | 同样为 27 | 不为减少容器而产生昂贵副本 |
| 第三条记忆禁止复制 | 逐读者复制丢失 3 条合法关系 | 3 条记忆各放一次，全部保留 | 正确分组也可做到，不能据此宣称新算法优势 |
| 目标只有 `{a,b}` 和 `{b,c}` 两种读者组 | 旧分组不能直接部署 | 合法复制第三条记忆，2 容器、4 对象 | 展示目标约束适配；目标能力是显式合成契约 |
| 所有容器隐含读者 a | 旧基线会给 a 新增一条读取关系，预检阻断 | 拒迁不应给 a 的记忆 | 未新增授权，但丢失 2 条合法关系，不能算完整迁移成功 |
| 部分策略未知 | 未知关系保持未知 | 同样保持未知 | 不能因为目标不可见就将其认定为安全通过 |

角色覆盖的 8 份计划均未观察到新增读取关系；其中 6 个场景完整保留，隐含所有者场景有缺失，未知策略场景仍未通过完整安全判定。HTTP 的关系计数将 read/list 分开，因此 2 条主体—记忆缺失会对应 `W−=4`。

独立穷举测试还检查了全部 512 个三主体、三记忆的二值矩阵，新规划器与独立参考的加权最优值一致。这是小域实现正确性证据，不是大规模最优性保证。

## 4. 针对标签与检测缓存的适配

### 4.1 缓存复用什么

只复用已经通过原文位置和结构校验的语义检测结果。缓存项仅保留片段偏移、类别和受限版本元数据，不存储原文、问题文本、代号或恢复映射；键为进程内随机密钥计算的 HMAC。缓存不序列化到文件，容量默认 256 条，有效期默认 300 秒。

缓存键绑定：

- 当前用户与执行 Agent、签发方域、授权状态和对象来源授权；
- 原文内容、来源 ID、完整规范化敏感策略；
- 检测器源码摘要、提示词摘要、模型摘要、配置及生成参数。

缓存命中发生在当前身份、来源、授权和生命周期检查之后。命中以后，仍运行规则检查、问题与记忆的片段传播、外发检查，并为当前请求生成全新的代号和恢复映射。恢复时再次检查权限。

**待审、错误或无完整调用记录的检测不进入成功缓存。** 缓存也不会把漏检变成已发现：如果一次成功检测本来漏掉了实体，缓存可能复用这个漏检。

### 4.2 标签不能只记录一个旧版本号

`prepare_labeled_transfer()` 新增可选 `label_requirements`。调用方可以要求当前接受的构建器版本，以及 `detector_revision(agent)` 根据完整可信检测器配置生成的版本指纹。

签名有效但版本不匹配的标签进入重新检测；权限、来源或撤权检查失败则直接阻断，不能靠重新检测“补授权”。旧调用不传新参数时保留原行为，现有历史包不会被悄悄改写。

本轮示例中的标签由本地检测器在记忆构建时生成，签名绑定完整检测器指纹。该实验直接保留原始短记忆，不执行上一轮有损事实摘录，因此只评估复用机制。

## 5. 真实本地模型对照

使用固定 Ollama 0.40.8 与 Qwen3 4B Instruct 量化模型。4 条新合成记忆（中英各 2），每条有 3 个合法请求，其中一个是重复问题，另有 1 个越权请求；共 64 个“请求×方法”记录。

同一批记忆与标注用于四个条件，方法顺序固定随机化；当前用户和源授权不变。评分答案与敏感片段标签单独保存，只在模型调用及恢复结束后评分。没有针对本轮结果调提示词或修改真值。

| 方法 | 合法答对 | 处理前阻断 | 真正模型 UNKNOWN | 迁移检测调用 | 分摊构建标注调用 | 检测总调用 |
|---|---:|---:|---:|---:|---:|---:|
| 每次迁移检测 | 4/12 | 8 | 0 | 24 | 0 | 24 |
| 每次迁移检测＋缓存 | 4/12 | 8 | 0 | 16 | 0 | 16 |
| 构建时标注 | 4/12 | 8 | 0 | 12 | 4 | 16 |
| 构建时标注＋缓存 | 4/12 | 8 | 0 | 12 | 4 | 16 |

普通缓存相对每次检测减少 8 次调用，即 33.3%。计入构建标注成本后，生成时标注没有胜过普通缓存；标注加缓存在本轮也没有进一步减少调用。

8 个合法请求在问题检测时得到 `semantic_uncertainty`，没有进入回答模型。失败不缓存，因此重复的不确定问题仍会重新检测。每种方法仅 4 个请求进入模型，这 4 个均答对、恢复成功且未观察到金标漏遮。不能把“4 个可准备请求中无漏遮”写成“12 个问题全部安全可用”。每种方法的 4 个越权请求均在回答模型前阻断。

全实验实际发生 **84 次本地模型生成**：构建标注 4 次、迁移检测 64 次、答题 16 次。构建标注物理上只运行一遍，各生成条件比较时分别分摊成本，不能将这些分摊重复加到账单。云端调用 0，新增 API 费用 0 元。

结论是：缓存节省开销，**未改善此次合法回答率**。4 条故事规模很小，也包含重复问题，不支持统计显著性或语义泛化结论；没有重用此前保留集调参。

## 6. 使用方式

零模型成本的权限对照：

```powershell
python -B -X utf8 scripts/run_reuse_benchmark.py --output results/new_role_comparison
```

增加真实本地模型四条件对照：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup_local_privacy_agent.ps1 -SkipDownload
python -B -X utf8 scripts/run_reuse_benchmark.py --with-local-model --output results/new_reuse_comparison
```

新目录必须不存在。运行不会调用 DeepSeek 或其他云端 API。

权限接口：

```python
from memory_migration_study.policy import make_plan
from memory_migration_study.plan_verifier import verify_plan

options = {"container_cost": 4, "object_cost": 1,
           "implicit_readers": [],
           "allowed_reader_sets": [["a", "b"], ["b", "c"]]}
plan = make_plan(case, "role_cover", "unique-run-namespace", planner_options=options)
check = verify_plan(case, plan,
                    implicit_readers=options["implicit_readers"],
                    allowed_reader_sets=options["allowed_reader_sets"])
# check["safe"] 与 check["equivalent"] 分开使用；将缺失和未知呈现给调用方。
```

隐私接口保持现有参数，再加可选项：

```python
from memory_migration_study.detection_cache import DetectionCache, detector_revision
from memory_migration_study.memory_labels import prepare_labeled_transfer

cache = DetectionCache(max_entries=256, ttl_seconds=300)
prepared = prepare_labeled_transfer(
    records, query, policy, authority=authority,
    actor_id=actor_id, agent_id=agent_id, request_id=request_id,
    mode="generation", agent=detector, detection_cache=cache,
    label_requirements={"expected_builder_version": "your-current-builder-version",
                        "expected_detector_version": detector_revision(detector)},
)
# build_record(..., detector_version=detector_revision(detector)) 应在构建时绑定
# 实际用于生成标签的检测器；不要把迁移检测器版本冒充构建标注器版本。
```

不同的标注器和迁移检测器可以有不同指纹。调用方必须声明当前接受的标注器版本；升级后旧标签应重新检测。对没有可信 `cache_identity()` 的第三方检测器，缓存明确旁路，不猜测版本。

## 7. 已完成适配、研究边界和下一步

本轮在已有算法上增加了项目所需的复制许可、目标读者集合、隐含所有者、命名空间及身份映射约束，并把标签、缓存与完整策略、版本、当前授权和重新恢复绑定起来。这些是可复用的工程适配，已经有源码和对照证据。

它们仍不足以自动构成论文创新：加权覆盖、缓存、版本绑定本身都是成熟方法。若作为论文，下一步应固定一种真实目标的权限限制，用更大、独立的授权实例，与完整角色覆盖及正确缓存比较，并把合法任务损失计入。

当前合法问题的主要失败在问题敏感检测，而不是云模型拒答。值得单独研究的适配是：对宿主构造的、没有用户字面值的结构化字段查询，提供可验证的模板来源；有自由文本或实体槽位时仍完整检测。该项**尚未实现**，不能直接把模型说“不确定”的文本当作不敏感，也不能从本轮 4 个故事挑固定字符串绕过检测。若实施，需要新数据和绕过攻击测试。

本轮尚未提供：生产级密钥服务、跨进程缓存、在线原生撤权、Cedar 集成、任意平台策略翻译或全语义隐私保证。
