# 原文受限标签：机制开发预注册

日期：2026-10-28。上一轮同一全文方法换模型仍失败，其中4条初始与修复均为合法JSON，失败来自名称抄写或出现次数。本轮检验原文绑定解码能否减少这一类执行失败，同时独立评价敏感语义。本方案不降低原P90/R95、独立64题、原生环境及论文创新要求。

## 1. 近邻、实现与保证边界

[Constrained Tagging for Span Labeling](https://arxiv.org/abs/2610.28922v1)于2026-10-20提交，提出字节词表trie与有限状态机约束的原文复制/插标签；[SPANIEL](https://github.com/harshsinghal/SPANIEL)也有源保持PII标注实现。两者都有直接先例，不能将本轮包装为新算法。所核两个GitHub代码树均未见明确代码许可，不直接拷贝或vendor；论文许可与HF权重许可不替代代码许可。

本项目独立用一般状态机编译输入依赖GBNF，复用已下载Qwen3.5 4B同一GGUF及同一个llama-server后端：原文第i个codepoint有outside/inside两个状态，只能复制下一个原字符或插入合法开闭标签。支持非空、不嵌套、相邻跨度，选用原文中不存在的确定性分隔符；不NFC归一化、不改空白。32个片段上限由主机解析器检查，超限阻断，不声称语法已经强制此计数。

新模块`source_tagging.py`返回精确原文位置及标签，不产生权限。原文完整复制只保证位置可核验，不保证选对敏感对象；不标任何实体也可完整复制，不能算安全通过。原始论文HF处理器与本GBNF实现、硬件/精度不同，不能声称已复现其速度或零开销结论。

## 2. 运行资格与数据

固定使用已校验的`model.gguf` SHA256：`a9d0a3e1d8c91732a3812becd31f8d4a8ff57414903f226306069f0437e2ac50`；运行器为现有Ollama包内`llama-server.exe`，记录实际exe及CUDA backend DLL摘要。固定127.0.0.1:11436、单slot、4096上下文、关闭思考、GPU卸载；不另下载模型。

正式批次前只允许1次公开Unicode短句的约束运行资格，验证grammar接口、原文codepoint保持、完整结束及token计数。保存实际请求/响应及receipt；不属于正式材料。失败即保留，不自动重复资格生成。

运行资格的首份原响应已实际返回完整的Unicode原文标记，441输入/16输出token。初始校验器错误地要求旧`stopped_limit`字段，新运行器实际使用`stop_type="eos"`和`truncated=false`。保留该仪器检查失败，只按已保存原请求/原响应离线重判；不进行第二次资格生成。正式接口显式接受已核验的新结束合同，限制/未知/缺字段仍拒绝，不能仅凭`stop=true`放行。

固定8条已暴露开发ID：`[1,4,6,11,13,16,19,22]`，中英文各4条，覆盖名称抄写/次数、否定、未知、同名普通词与“苔藓”。按已知错误类型选取，是有意构造的机制诊断，不能当独立自然验收材料，也不把这8条替换成更简单数据。

## 3. 四条件与公平比较

| 条件 | 本轮处理 |
|---|---|
| free_tag | 同GGUF/后端/共享prompt，自由生成状态首行与带标签原文 |
| constrained_tag | 完全相同prompt和推理参数，仅增加原文copy/tag GBNF |
| qwen35_quote | 回放上轮同8条全文quote/occurrence输出，属不同输出方法/运行封装的工程参考 |
| qwen3_conditional | 回放同8条现有最强条件位置输出，作为工程强基线 |

两种新标签条件共用输出：首行`OK`或`REVIEW`，后续逐字复制正文并仅插合同标签；未知关系需要REVIEW。主机先解析状态，再验证原文与标签。不能因输出没标签就补成明确安全，不能让模型自报状态成为授权。

所有条件分别使用同一当前权限、空源标签migration准备、实际假名化及错误user/Agent反例；不合并条件的正标签。只有constrained与free比较可用于约束机制归因，不能把换后端/提示相对旧quote的差异全归因于grammar。

## 4. 冻结与调用预算

正式前保存运行资格、实际`/apply-template` prompt及`/tokenize`结果，每条两模式使用相同prompt，token_count不超过3072，留下1024输出余量。模板与分词API仅本机非生成，不读取评分答案；冻结messages、prompt、grammar、输入、源码、收据及全部摘要。原文只在本机处理。

16次正式生成（8条×2种新模式），每条每模式仅1次，无修复；资格最多1次，总新增最多17次。temperature=0、seed=42、输出1024、串行，正式最多1800秒，0云端/付费/下游/原生写。采用预先固定的平衡模式顺序，并记录缓存/耗时，不用相邻顺序差异冒称解码速度收益。

独占开始记录禁止重复批次；所有32格、新响应与实际足迹封存后才解析评分。HTTP/身份/token缺失/越限/不完整生成保存后停止；内容复制或标签解析失败单列待审，不伪装为语义拒答。失败不得用改变参考、截断、删除困难材料或追加提示调参补救。

## 5. 分开评价机制与效果

机制指标：完整结束、去标记后精确原文保持、可定位性、解析失败、grammar大小/编译开销和实际token/耗时。报告语义FP/FN、未知待审、实际漏遮、多遮、已知可准备、合法事实保留及权限反例。COPY成功不表示敏感判断或原验收通过。

是否推进完整24条的效果门槛仍同时要求：constrained精确位置P≥90%、R≥95%，无准备成功后参考漏遮，known可准备不少于相同8条条件位置强基线，未知案例均有实际语义不确定证据且阻断，权限反例及成本记录完整。即使8条达到门槛，也只是开发推进资格，不自动关闭原独立检测、64题或论文创新要求。

若仅原文保持改善而语义仍失败，保留机制结果并停止扩大，不称已减少合法问答拒答。若与既有约束方法等价，结论为强基线适配与工程修复，创新仍须另有新问题及充分对照证据。
