# 权限投影测量：定向近邻补核 v2

核验日期：2026-10-26。目的限于核对“统一记忆交接、异构权限表达、当前撤权与安全—效用测量”的已有覆盖。本轮只读论文/规范与作者代码，未运行他人代码，未调用模型或原生服务。检索为三组定向查询及其一手引用追踪；不是系统综述，也不用未搜到证明空白。

**裁决：测量选题需要进一步收窄。** AMSB已经覆盖多提供方、原生与外部辅助能力归因、隔离、生命周期及恢复；Signed Memory Projection Records已经覆盖来源到上下文的可验证投影、策略/信任快照与重放边界。它们明显压缩了此前候选定位。当前没有新证据支持“首次安全记忆迁移协议”“首次原生/网关分层评测”或新算法优势。

## 2. 与我们已经完成的内容怎样对齐

以[最新主线验收](论文目标_主线验收与竞品核验_2026-10-25.md)为准：共同源投影已经在Cognee和WebUI上执行真实普通账户、精确事实与当前规则同步；标准完整网关通过，原生read映射通过，其他未实现动作明确unsupported。之后WebUI读取面资格又区分了原文、元数据ID、列表与默认write/显式read搜索。不能继续把这些工作写成“还没有任何原生资格”。

但当前共同源是可信控制器装载的受控合同，**不是从一个厂商原生身份/ACL系统导出，再迁入另一个厂商的双向迁移**。静态 `AGENTS.md` 的Qoder/Harness四位置结果也不能补足这一步。AMSB覆盖了原生/辅助归因，ApertoMemory/Projection覆盖了有限互操作与来源投影，因此我们仅剩的条件性候选应更具体：**凭据绑定的原生源读取权限，经真实导出适配和目标重建，在双向生命周期中是否产生可复现的语义损失**。这是待测范围差异，不是已成立的新贡献。

目前没有理由预期新算法会超过“完整当前权限重算＋普通缓存＋正确原生ACL映射/外部网关”。既有98格结构上限及共同源实测都支持保留该否定判断。这里不重复PAM、SAMEP、EAL-Bench等已有表；其完整标准保护仍属于强基线。

## 3. 唯一建议的下一实验：有限主体的真实原生源双向往返

**问题与可证伪假设。** 将WebUI→Cognee、Cognee→WebUI各跑一次：若源端的真实read关系已被官方API观察并完整记录，正确原生映射或完整当前核权网关应保持同一有限主体集合的合法读取与撤权；若仍失败，必须定位到实际导出、身份映射、容器范围、目标强制执行或更新完成边界。不能将源端不存在的委托/TTL语义补写进所谓“原生导出”。预期强基线可能全部通过；此时没有算法收益。

### 3.1 固定最小材料与边界

- 每方向一个全新隔离源、一个全新隔离目标，继续采用当前两个已资格版本和官方HTTP身份路径；owner及四个用户/执行Agent组合分别是普通原生账户，bootstrap管理员单列。这些组合账户不是厂商第一类Agent IAM。
- 两个公开合成精确事实，各自独立容器；先建立Alice对两事实的read及Bob对第二事实的独立read，worker组合无权。导出前用八条真实主体—事实原文关系建立**有限闭世界**原生参照，并核对owner取得的原文哈希；不访问私有DB或把owner读取当其他主体读取。
- 导出由我们的adapter经官方API读取原文及可取得的原生策略证据并生成中间包；如果没有产品原生export端点，明确称“API读取式导出适配”，不冒称厂商完整备份。无法完整导出策略时先停在 `unverified/unrepresentable`；不得从文本或模型猜授权。八关系观测只能支撑本批主体，不能证明任意新增主体的完整ACL。
- 包中分别声明可验证的read关系、来源/对象映射、策略观察时间及未表达的语义；受信源控制器仍可保留迁移ID和当前源复查合同。它不能借此把厂商没有的原生export/share/委托权变成已有事实。未知约束必须拒绝或进入明示网关模式。

### 3.2 两个必备强臂，一个可选负控制

| 条件 | 完整处理与允许的正确结果 |
|---|---|
| **N：正确原生投影** | 完整投影源端已验证的有限read关系；允许按事实拆容器、正常批量查询/索引/缓存。每个当前源状态完成后重算并同步目标ACL，再宣告同步屏障完成。无法保真表达的约束明确unsupported，不静默放宽，也不算成功。 |
| **G：完整当前核权网关** | 目标owner-only存储；每次新交付重查源端当前原生授权及目标局部规则，配正常缓存和失效管理；元数据/列表也走同等约束。它是主强基线，允许安全正确地解决全部情况。 |
| 负控制（非胜利依据） | 仅复制导出时ACL、不处理后续撤权。只有事先冻结且实际需要定位生命周期差异时才运行；不能把胜过它当算法优势。 |

两个时点即足够：初次导入完成；撤Alice第一事实read、保留Bob第二事实独立read并完成规定同步屏障后。第二时点重复旧导入包/同迁移任务，再跑两端当前八关系，检查旧包不能恢复已撤read而Bob原有独立read仍在。若旧包不含撤权更新，单凭格式校验或签名无法决定当前授权，N与G都必须使用相同完整当前源状态。原文已经交付的旧会话不计“应被遗忘”；不声称异步零窗口、跨后端原子提交或厂商原生TTL。

每时点只测已资格的原文与授权对象枚举面；各后端列表语义不同，应通过已冻结接口合同分别解释，200空列表、401、服务异常与unsupported分开。若Cognee尚无对应搜索资格就不写“完整搜索通过”。不调用生成/嵌入模型；当前链路问题尚未定位前不追加下游回答实验。

### 3.3 评分、分母与停止条件

主要指标为：源观察→包→目标内容哈希/映射保持；有限read关系的非法新增与合法损失；撤权后新交付、旧包重放与独立read保留。分别报告native/gateway/unrepresentable/unverified及HTTP失败；unknown不能当deny。记录真实HTTP、迁移量、当前核权/ACL更新次数与屏障耗时。两方向、两事实、重复请求是机制单元，不包装成大量独立故事或自然样本。

**继续条件**是出现超出已知“不支持”清单的、版本固定且可复现的语义损失，并且完整强基线的修复成本或效用差异具有实质意义。**停止/降级条件**是：只有已知功能不支持；正确N与完整G都通过且成本普通；失败来自我们adapter的普通bug；或没有足够原生源策略证据。届时交付兼容性/复现工具和负结果，否定新算法或强论文创新已成立，不继续靠添加术语与矩阵数量包装。

本备忘只建议冻结前审阅，不表示本实验已执行。现有检测P/R、原云端对照、新独立任务以及旧向量失败的验收缺口均保持原状态。
