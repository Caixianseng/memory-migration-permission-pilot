# 联合语义校正：五条件完整迁移开发预注册

2026-10-25。继续用户目标：效果验收通过、达到论文工程标准和创新要求；新增约束为账户累计已用额度不超过60%。开始时工具可读取的周额度为15%，按累计使用口径控制，主要阶段前复查，接近上限时保留交接余量。本轮只用本地模型，不追加付费API调用。

## 1. 事实与新假设

上一轮引用式构建使8个故事全部构建成功、32题必要事实全部保留；严格格式修复后29/32正确，但联合仅27/32。已核实的剩余问题包括：买方全名只遮住后缀；普通组织角色词被当实体；公开旁观组织被归入客户。继续只调整原文格式不能解决这些语义问题。

本轮假设：在原有候选位置上同时判断“是否为受策略保护的具体实体”和“该实体完整边界”，可以提高完整遮蔽及合法使用。模型只能提出角色/原文片段，不能决定读者、授权、来源或工具权限。

本新子目标尚未实测，已确认实验失败次数为0、L0。历史其他方案有正负结果，但不凭命令退出码或重复展示日志累计此方法失败。此前一轮已有真实构建改进和独立证据，属于进展。

## 2. 固定材料与条件

仍用已暴露的8个合成开发故事、4模板族。每故事重新实际构建一次ReferenceMemoryBuilder(select)记忆，独立GLiNER标注、原授权签名并JSON交接；五条件共享同一已验证记录。各条件32道合法题、8道越权题，共200行。失败、待审、构建或预算阻断全部保留原分母，不改答案。

| 条件 | 做法 |
|---|---|
| baseline | 原GLiNER＋规则，原迁移与恢复 |
| union | GLiNER＋既有LocalSensitivityAgent独立并集强基线，使用既有DetectionCache |
| roles | 仅应用联合结果中的角色裁决，实体边界保持原样 |
| completion | 仅对被判断为具体实体的候选补全原文边界；其他原候选保留 |
| joint | 同时应用角色裁决与边界补全 |

三种语义条件共享同一次联合生成结果，是应用消融，不是三套独立生成器。共享键绑定当前原文、完整策略、候选位置、用户、执行Agent和受信授权生命周期域；模式不进入缓存键。失效/不完整输入不能复用为成功结果。每次读取与恢复仍重新核权，缓存不是授权。

## 3. 模型与安全约束

仅处理已有类型为PERSON/ADDRESS/CUSTOMER/PROJECT的候选，类型由主机固定。其他类型保护保持。输出只能包含当前cid、角色和精确原文quote；具体实体quote必须覆盖原候选的指定位置，并通过长度、唯一定位、显式字段边界校验。不能换源、改类型、创造新权限或读取答案。

不确定或持续格式/定位错误记录needs_review，不重试语义猜测。最多一次原生成＋一次格式/定位修复；不静默截断。明确业务注册值和原规则重新加入，有效的生成标签在generation/two_stage路径仍保留，不由新ML降级。

新hook只在原身份、签名、源、精确fact范围、当前ACL及epoch通过后执行；baseline过程中发生撤权时，hook前再次拒绝。hook仅得到选择记忆与问题、规范策略、检测结果、主体ID及缓存域摘要，没有完整源副本、record/access对象、签名密钥或恢复映射。原prepare、egress与恢复检查继续执行。

## 4. 预算、账本与冻结

固定Ollama/Qwen模型及摘要、运行版本，4096上下文，构建/语义最多1024输出token，回答最多64，temperature=0、seed=42。所有模型输入按完整请求/格式做预算预检，真实usage另检查。

最坏物理POST硬上限464：A构建16＋每合法任务至多2次共享联合语义64＋五条件回答160＋并集检测224。最后一项按不依赖缓存成功的上界：20个源块×4任务＋32问题，每段最多2生成。不能按“缓存一定命中”降低最坏预算。实际所有失败和修复尝试均计数；生成、编码和缓存命中分开报告。

账本记录实际请求/响应、usage、JSON正文序列化字节和哈希，明确不含HTTP报文头。外部网络禁止。授权检查、callback开始/结束及任务结束使用同一个递增事件序列，以匹配归档代码和真实调用，不能用虚构时间戳证明先后。事件不保存密钥或恢复映射。

运行前冻结实现、入口、模型、配置、原文和评分文件哈希。评分文件在模型阶段仅读字节供哈希，所有构建、检测、回答、原恢复及secondary结束后关闭模型阶段，再解析评分；模型阶段关闭后禁止POST。
