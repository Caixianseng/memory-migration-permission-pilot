# GitHub自动测试：连续失败原因与修复范围

日期：2026-10-26。对应仓库的`Offline tests`工作流。本次只修复工程测试的可移植性，自动研究目标继续暂停。

## 1. 截图中的红叉代表什么

每次向`main`推送都会重新执行整套测试。一个未解决的问题会让多次提交各留下一个失败记录，不能把红叉数量当作独立算法问题数。第5次运行成功后，第6至18次连续失败；第6次日志已经出现历史结果文件和旧工程源码缺失。

[第6次运行](https://github.com/Caixianseng/memory-migration-permission-pilot/actions/runs/40201718094) · [收尾提交对应的第18次运行](https://github.com/Caixianseng/memory-migration-permission-pilot/actions/runs/40260179431)

第18次Windows测试发现1524项，5个断言失败、20个运行错误、15项可选检查跳过；Ubuntu为3个断言失败、18个错误、15项跳过。这里的错误是Python执行异常，如找不到依赖或文件。两边的重复错误不能相加成独立病例数。

此前本机已有依赖、旧工程、历史结果和模型资产，本地回归通过；GitHub每次从干净环境检出，无法读取这些未分发文件。此前交付没有跟进远端Actions结论，是工程验收遗漏。

## 2. 具体原因与对应修复

| 原因 | 日志或代码证据 | 本次修复 |
|---|---|---|
| 工作流没有安装测试依赖 | `No module named 'jsonschema'`、`No module named 'fastapi'` | 测试前安装已有`requirements-dev.txt`中的四项固定依赖及其依赖项 |
| 假定本机输出目录已存在 | `results/candidate_export_fake_*`创建失败 | 每个相关测试自行准备临时输出目录的父目录 |
| 单元测试读取历史实验产物 | 引用旧快照、隐私审计和Qoder能力探测文件 | 用临时合成快照或临时源码清单测试同一真实核验流程，保留任务分母与篡改拒绝断言 |
| 测试依赖未分发的旧工程 | 找不到旧`qualify_migration.py` | ACL合同测试使用原类定义的冻结摘录并核对来源/摘录哈希；仅验证归档的用例使用明确不可执行的合成文件 |
| 文件守卫测试先去检查真实模型 | `asset_integrity_failed` | 直接构造真实继承守卫的测试状态，验证允许任务文件、拒绝评分答案和参考归档；不运行模型资产资格检查 |
| Windows临时目录有长短路径别名 | `RUNNER~1`与`runneradmin`比较不一致 | 测试夹具先使用规范路径；生产环境的链接、越界和文件完整性检查保持原样 |
| 一个矩阵任务失败会取消另一边 | 旧默认`fail-fast`行为 | 设置`fail-fast: false`，两个平台分别完成并报告 |

没有修改迁移、授权、隐私检测或恢复算法，没有删除原安全断言，没有添加“出错也通过”的处理。新增临时资产明确不是可用模型或原生SDK，不产生新的模型效果证据。

## 3. 怎样复查

在Python 3.12环境中运行：

```powershell
python -m pip install -r requirements-dev.txt
python -B -X utf8 -m unittest discover -s tests -v
```

GitHub工作流覆盖Ubuntu与Windows，安装测试依赖时需要访问包源；测试使用合成材料和受控本地接口，不要求云端模型密钥、模型权重或原生客户端登录。

旧工程2项、原始公开数据11项及固定官方wheel的1项检查，原本就有明确的缺文件跳过条件。本次没有增加跳过条件；缺少这些材料时，这14项继续显示`skipped`，不能算作通过或原生效果验收。此前还有1项因未安装`jsonschema`跳过，本次已安装并实际执行。

本轮用563份仓库及新增测试夹具文件建立干净副本，并创建只安装`requirements-dev.txt`的新Python环境。没有复制历史`results/`、旧149项工程或模型目录；实际发现1524项，1510项通过、14项跳过，0失败、0错误，耗时约265秒。环境中没有Torch、Transformers、Cognee或Open WebUI。详见[干净回归摘要](../benchmarks/ci_clean_regression_20261026_summary.json)。

本机原1524项全通过是当时完整本机材料下的记录，保留原分母。干净仓库的通过项与可选跳过项应分别报告，不能覆盖那份历史结果。

最新远端状态以[GitHub Actions](https://github.com/Caixianseng/memory-migration-permission-pilot/actions/workflows/tests.yml)中对应提交的Ubuntu和Windows两个任务为准。修复后的新运行不会更改旧提交的失败记录，历史红叉保留用于追溯。
