# 原生向量时序：固定文本配对诊断

2026-10-26。本轮只诊断一个假设：写入完成后立即进行向量查询，是否比固定等待 500 毫秒更容易出现先前的 `null`。它不是修复，也不是完整迁移验收。

## 结果

| 条件 | 真实查询 | 完整返回本用户应有记录 | `null` | 搜索异常事件 |
|---|---:|---:|---:|---:|
| 立即调度 | 6 | 6/6 | 0 | 0 |
| 固定等待 500 ms | 6 | 6/6 | 0 | 0 |

**本次固定输入、首次查询条件下没有复现故障，也没有观察到等待的成功率收益。原 v3 的 4 次 `null` 仍未关闭，根因未确认。** 不能把两组均成功写成“等待修复了故障”或“已排除时序竞争”。

## 如何保证两组可比

- 从原 v3 失败记录读取逐字相同的 6 条文本、路径、身份角色和写入顺序；不再随机生成 resident 对照文本。
- 6 个配对，assistant、owner、outsider 各两个配对；每种角色各有一次立即臂先运行、一次等待臂先运行。
- 每臂新进程、新临时数据库、新原生用户。每臂只有 6 次写入和 **1 次首次向量查询**，没有先查再等、额外 count/get、重试、删除或重索引。
- 本地 Open WebUI `0.12.3`、Chroma `1.5.9` 与原失败的 15 项资产固定；13 份执行源码及其归档核对一致。query、k=100、相关性阈值 0 保持固定。
- 6 个配对的全部写入向量和查询向量均逐位相同，不只是文本或模型名称相同。

outsider 在这里拥有自己的一条 resident 对照记忆。它成功取回自己的记录，不表示获得其他用户的记忆。评分同时要求本用户记录完整、没有其他用户 ID，且逐项文本、路径、类型、原生创建/更新时间与原 POST 回执一致。

写入元数据来自真实 POST 响应，没有为评分额外读 SQL 或向量数据库。查询原 HTTP 字节、JSON、SHA-256 与落盘 `.bin` 相互核对；`null`、执行错误、缺项或元数据不符均不算成功。

## 实际时间和调用量

“立即”指 API 在最后一次写入后立即调度，不代表原生向量搜索在零间隔发生。实际最后一次 upsert 完成至 HTTP 查询开始为 **5.53—6.88 ms**，至原始 search 进入为 **27.01—38.48 ms**。查询前还有原生路由处理和本地 embedding。

等待臂从调度到 HTTP 开始实际等待 **500.17—500.58 ms**，最后 upsert 至原始 search 进入为 **528.09—535.14 ms**。

共 12 次真实查询、72 次写入、84 次被包装计数的原生 embedding 函数调用，0 次生成调用、0 次云端调用、0 元新增 API 费用。该 embedding 计数是既定函数边界计数，不是底层 GPU/神经网络 forward 追踪。

首次普通失败后完成其匹配臂、停止新增配对；权限/范围/观测失效立即停止。本轮所有单元通过，失败停止分支没有在真实运行中触发，而是在 12 次上限处结束。资产的开始和结束哈希均一致；这不是运行过程中持续监视资产修改的证明。

## 独立复核与解释边界

本地原始目录为 `results/native_vector_timing_20261026_v1/`。新增标准库核验器 `scripts/verify_native_vector_timing.py` 不导入或调用后端、模型。它独立核对原始 6 条写入、72 次 POST 与 12 次查询的原 `.bin`、返回元数据、时钟、向量配对、36 个互异原生用户、72 个互异目标 ID，以及当前和归档源码/资产。回执 `independent_timing_audit_v2.json` 的 741 项核对全部通过，核验新增模型/原生调用均为 0。检查数不增加独立实验样本数。

可在原始产物仍存在时离线执行：

```powershell
python scripts/verify_native_vector_timing.py --run results/native_vector_timing_20261026_v1 --original-run results/native_exact_fact_bridge_20261025_v3 --output results/native_vector_timing_20261026_v1/new_independent_receipt.json
```

双方均启用了相同的 `sys.settrace` 异常观察器，保持原搜索实现的返回与异常处理，不增加后端读取。**观察器仍可能影响调度**；本轮也没有原 v3 的多次 snapshot、删除和旧任务重放顺序。因此，本轮没有排除未追踪或更长生命周期中的竞争，也没有证明原先成功与失败的差别由等待造成。

驱动的 `interpretation` 字段没有单独把 postflight 纳入其字符串生成条件；本轮独立核验额外核实了源码与资产 postflight 实际全部通过，未发现由此产生的真实误验。冻结驱动未作事后修改。

本轮只支持“在这 12 次固定输入、双方追踪、全新数据库的首次查询中未复现”。原生端到端稳定性、旧 v3 故障关闭、跨 Agent 迁移效用与论文创新均不能由这次结果推出。
