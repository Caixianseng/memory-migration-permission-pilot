## 实际运行及隔离

在项目根目录执行以下命令，输出位置必须是新的目录名：

```powershell
python -B -S -X utf8 results/submission_reproduction_audit_20261030/recompute_existing.py --run-name stdlib_only_run03
```

`-B` 禁止生成字节码缓存；`-S` 不加载 site-packages。本次实际 Python 版本和解释器位置见 `verification.json`。运行脚本先复制最少必要的历史响应和封存文件，再调用已有评分器；离线评分期间，socket 连接接口及 `subprocess.Popen` 被设置为立即失败。没有读取模型凭证、账户快照，也没有调用真实客户端或模型。新增网络、客户端及模型调用均为 0。

## 固定代码与可获得性的缺口

审核时 Git HEAD 为 `3e3c9641e6e96b4b4480c80a6b57abd1df6924a0`。该提交没有收录这些最新隔离实验的源码、数据、测试及报告。分别按三批冻结计划统计，未跟踪的 `experiments/` 文件数为 12、14、9；有重叠，不可相加作为独立文件总数。工作区文件哈希匹配，不能替代提交已包含这些文件。

原始结果位于被 `.gitignore` 排除的 `results/` 下。只给出 GitHub 仓库链接，外部复核者不能获得本轮全部评分输入。本次没有改变忽略规则，没有提交、推送或公开任何原始实验结果。

既有执行计划和交付清单使用 Windows 相对路径字符串，其中含反斜杠。Windows 能读取，Unix 的 `Path` 不会自动把反斜杠当路径分隔符。新复核包应统一采用 POSIX 相对路径，并检查路径解析后仍位于包内；旧清单应原样保留，通过有版本的适配层读取，不能悄悄改写旧哈希。

实际执行时产生的随机签名密钥、宿主状态和本地恢复映射没有全部持久化。这有利于减少映射泄露，但意味着封存响应的离线重算不能重新执行当时的密码学授权。复核包应分开提供两条路径：从公开合成案例重跑确定性主机流程；从封存响应重算模型实验。重新运行在线模型还需要相应客户端、账户与额度，输出不保证逐字一致。

## 最小复核包应包含什么

1. **固定代码和声明**：完整提交或内容寻址源码包、支持的 Python/操作系统版本、授权规格、威胁模型、每个结论适用范围及性质到证据的对应表。
2. **公开且有限的数据**：开发和检查故事、可信权限与独立评分参考分别提供；说明标签作者、人工复核状态、参考暴露时间与检查集是否仍保持独立。案例若已参与调试，应转为已暴露材料。
3. **两种运行模式**：零网络的主机重跑与封存响应评分为默认；真实 Qoder/Harness 重跑必须显式启用，预算、重试、版本和工具权限单独配置，不在导入模块时启动。
4. **足够的封存响应**：计划、输入/保护视图、加载证据等级、原始回答、最终恢复结果、失败分类、耗时、可公开的费用汇总和预测关闭记录。账户原始快照、凭证、恢复映射及无关诊断日志不应成为公开评分的必要输入。
5. **独立评分与出图入口**：统一一个只写新目录的命令，拒绝缺失/篡改/路径越界，不覆盖原件；输出故事级、条件级和共同配对统计，并保留未知、失败和未执行分母。独立参考不能调用生产核权函数形成真值。
6. **真实外部验收记录**：让未参与实现的人，从新解包目录按说明复算，保存环境、命令、差异和反馈。子代理重算只能作为交付前自查，不应填写为该项已完成。

## 本轮工具修订记录与边界

首轮复核脚本在统计 Git 未跟踪源码时仅匹配 `experiments/`，遗漏了冻结计划中的 Windows 反斜杠路径。修正为先规范化分隔符后重新执行；主要统计和交付哈希在修订前后都一致。本问题属于复核工具缺陷，不是模型效果的失败，也没有修改任何评测答案。

随后以 `-S` 禁用 site-packages 实际重算，结果仍一致，说明本轮离线评分路径不依赖第三方 Python 包。它仍使用同机现有源码和已封存参考，尚未在新机器或完整独立解包副本中完成验收。后续应由主任务制作正式新制品包后，再做一次匹配最终制品的干净目录复核；不应无改动地反复重算刷数量。
