# 上下文候选判型：真实结果与裁决

日期：2026-10-26。本轮为检测机制的开发诊断：80条原开发材料＋40条已暴露的旧保留材料。后40条仅作回归，**不是新独立验收集**。本文件对应[公开汇总](../benchmarks/context_candidate_detection_20261026_summary.json)，不更新主线验收结论。

## 1. 研究问题与对照

本轮检验：在NER和规则产生候选后，使用本地模型依据固定上下文判断候选是具体值、泛称还是字段名，能否补回漏检并减少误报。

可下载[合成材料离线复核包](../benchmarks/artifacts/context_candidate_detection_20261026_v2.zip)及[校验清单](../benchmarks/artifacts/context_candidate_detection_20261026_v2.manifest.json)。包内保留原始本地请求/响应、真值、源码快照和首次验真器失败；不含模型权重、账户或恢复映射。该包已在新目录解压，零模型重放747项检查通过。

在匹配的仓库版本中，可用下面命令重算，已有目标目录会拒绝复用：

```powershell
$replayDir = "results/context_candidate_public_replay"
if (Test-Path -LiteralPath $replayDir) { throw "请使用新的复核目录，保留旧证据" }
python -m zipfile -e benchmarks/artifacts/context_candidate_detection_20261026_v2.zip $replayDir
python scripts/verify_context_candidate_diagnostic.py --run $replayDir --output "$replayDir/verification_replay.json"
```

此命令读取已记录的本地响应，不启动模型，也不执行包内归档源码；真值只用于离线计分。复核通过不能将该方法的负结果变成验收成功。

三个条件共享同一次源检测和同一批材料：

1. **同期NER＋rules**：本轮重新运行的NER与规则对照。
2. **仅原候选判型**：复用完整候选池的同一份模型判定，只允许原检测候选进入后续处理。
3. **全部候选判型**：还允许将引号、括号等产生的未定类候选提升为敏感值。

后两者是共享判定的机制消融，不能当作各自独立优化、各自调用一次模型的竞品。原格式类保护和显式注册保护保留，未修改授权、准备、恢复及默认分支。

这里的NER对照是**同期重新执行的基线**，与历史80条材料上较强NER条件的结果不同。本轮没有完整重跑历史全部条件，不声称优于历史最优检测器，也不把本轮对照冒充既有强基线的全面覆盖。

## 2. 执行与独立核验

实际完成120份材料、360行条件记录、81次本地chat POST，以及168次编码器`infer`入口观测。适配器也报告168次编码调用，两类计数分别保存；入口观测不是GPU kernel追踪。39份没有候选而零生成，81份各一次生成，没有第二次格式修复。

本地判型模型为`qwen3:4b-instruct-2507-q4_K_M`，Ollama版本0.40.8；NER为`fastino/gliner2.5-multi-v1`，采用`cjk_aware`切分与0.5阈值。完整模型摘要和选项见公开JSON。本轮没有云端模型调用或新增API费用。

独立离线验真器核对来源/代码快照、模型阶段关闭与评分时序、调用预算、CID/EID输入、原始观测重放、强保护保留，以及全部条件的独立全跨度评分。修正验真器自身问题后，**747项一致性检查通过，验真新增模型调用为0**。该结果证明保存证据符合已检查合同，不等于检测效果、安全性或论文创新通过。

## 3. 真实结果

TP是真阳性，FP是误报，FN是漏检；精确率为TP/(TP＋FP)，召回率为TP/(TP＋FN)。所有材料保留在分母中。

| 材料 | 条件 | TP / FP / FN | 精确率 | 召回率 | 整条完全正确 |
|---|---|---|---|---|---|
| 开发80 | 同期NER＋rules | 55 / 12 / 3 | 82.09% | 94.83% | 69 / 80 |
| 开发80 | 仅原候选判型 | 55 / 12 / 3 | 82.09% | 94.83% | 69 / 80 |
| 开发80 | 全部候选判型 | 55 / 17 / 3 | 76.39% | 94.83% | 64 / 80 |
| 已暴露回归40 | 同期NER＋rules | 18 / 2 / 2 | 90.00% | 90.00% | 36 / 40 |
| 已暴露回归40 | 仅原候选判型 | 18 / 2 / 2 | 90.00% | 90.00% | 36 / 40 |
| 已暴露回归40 | 全部候选判型 | 20 / 8 / 0 | 71.43% | 100.00% | 32 / 40 |

全部候选条件补回旧回归材料中的2个漏项，但增加误报；开发材料未补回漏项。两个材料组均未同时达到精确率≥90%、召回率≥95%的检测目标。旧回归材料召回率达到100%不能代替联合门槛，更不能作为新独立验收成绩。

## 4. 为什么增加了误报

113个最终候选判定中，101个为`value`，12个为`generic_role`；`field_label`、`other`、`uncertain`均为0。因此不能说模型把所有候选都判成值。

更具体地看：87个原有定类候选全部仍为`value`，所以仅原候选条件没有改善同期基线。26个未定类候选中，14个被提升为`value`，12个判为泛称。

14个提升项对应2个新增TP和12个新增FP。新增FP全部是字段/段落标题，不与注册敏感跨度相交：开发材料5个，旧回归材料7个。实际输入窗口已包含“标题为”“一栏登记为”等角色线索，CID/EID与目标位置也一致；这批错误发生在语义角色判断，不是单纯输出格式错误。是否增大上下文或去掉旧类别提示有帮助，本轮未做因果对照，不能断言。

集合比较中有1个旧FP跨度消失，但它被更长的错误标题跨度替换，不能记作成功纠正误报。因此是**新增12个FP、替换1个旧FP跨度，净增11个FP**；未丢失原TP。两个split的净FP变化分别为＋5和＋6。

## 5. 验真器失败与修正记录

第一版验真回执为失败，保留了修复前失败复现，没有覆盖原始调用、gold或得分。定位出的两处问题均属于验真器自身：

- 继续读取已从报告移除的`actual_encodings`字段，没有按新合同区分观测与适配器报告值。
- 将问题文本的源命名写成`query`，正式合同使用`__query__`。最先的空gold材料未触发问题，后续含问题源敏感跨度的材料使验真器报错。

修正只涉及验真器。第二版重新核验747项全部通过，并独立重算出上表原有成绩。完整checks保存为新文件，终端仅输出摘要；旧失败证据仍保留。**验真器修好不等于方法效果改善。**

## 6. 本轮裁决

本轮为负结果：扩展候选池能补回特定漏项，但当前逐候选上下文判型没有可靠地区分字段名与取值，整体精确率和整条正确率下降。方案继续保持可选实验状态，**默认方法不变，检测门槛未通过**。

本轮未评测合法问题拒答、下游回答、原生记忆迁移或论文新颖性，不能作相应改善或完成声明。原材料均已暴露；后续方法和阈值冻结后，仍需新独立材料及完整强基线。字段—取值的联合关系约束可以作为下一步假设，但尚无新实测，不能写成已实现收益。
