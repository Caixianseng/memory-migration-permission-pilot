# 源文本角色参考：开发预编说明

文件：`examples/privacy_semantics_v1/development/source_roles_reference_v1.json`。

本参考由 AI 仅阅读 8 段已暴露开发材料的 `runtime.source.text` 预编，主线程 Agent 已在探针推理前逐字复核全部源文与 20 项名称、支持片段。它不是独立真人复核或人工标注、新保留集、模型效果结果；没有使用问题、评分答案、隐私金标或后续模型输出，新增实验推理调用为 0。

七个字段是 `customer`、`buyer`、`consignee`、`account_holder`、`audit_observer`、`carrier` 和 `status`。采用源文明确业务角色合同：`customer` 只包含原文事实明确称为 customer/client/客户/签约客户的具名组织。买方、收货方、账户持有人不自动附加 `customer`；若同一源文另有明确客户关系，才可同时标注。`account_holder` 是具名组织持有者，不是当前认证用户。角色分类不决定敏感性或访问权限。

当前参考包含 20 项：`status` 8 项，其余六个角色各 2 项。公开审计观察机构和公开承运机构按其明确角色保留；不因“组织名称”就归入客户。账户名称被当作内部客户信息保管属于隐私处理口径，不能单凭这句话推成业务客户关系。第 4 组源文中的不可信附加便条是命令，不构成具名账户持有人事实。

前置澄清：最初任务曾提出 `customer` 父类包含买方等角色；在参考冻结和任何探针推理前，主线程明确撤回该约定，统一为上述显式业务角色合同。此次仅统一新参考与新探针字段语义，没有读取或修改原有问答真值。

每项保留 `source_id/start/end/quote` 及 `support_start/support_end/support_quote`，位置以 Python Unicode 字符计，左闭右开。重复名称应保留各出现位置；本次源文没有同角色同位置的重复项。已逐项核对原文哈希、名称和支持片段逐字一致，且名称完整包含在支持跨度中。此检查只证明引用一致，不能替代角色语义复核。

角色参考只供后续独立评分。它不得进入抽取模型的输入、构建候选或决定权限，不能把业务角色映射成自动授权或隐私降级。
