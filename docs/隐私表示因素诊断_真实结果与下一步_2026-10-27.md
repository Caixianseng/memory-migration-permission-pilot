# 隐私表示因素诊断：真实结果与下一步

日期：2026-10-27。执行者为GPT-6.1 Sol（ultra）；实验模型为本机固定Qwen3 4B。依据[预注册方案](隐私表示因素诊断_预注册方案_2026-10-27.md)，完成144次本地调用，无重试、无云端/付费/原生客户端调用。公开汇总见[机器摘要](../benchmarks/representation_factor_20261027_summary.json)。

## 1. 对项目意味着什么

**目前最需要处理的是表示与提示的组合效用，以及检测类别合同，而不是再造一种迁移协议。** 同一批4个开发故事、12道题，短粗代号配原提示为12/12，长粗代号配原提示为10/12。增强证据指令修复了长粗表示的两处错误，却使短粗表示和自然假名各多出一道合法题UNKNOWN。它不是通用修复，不能只看缺失题改善就切换默认。

正确的人工实体类型在本轮四个条件均为12/12，但这是已知正确类型的表示上限；没有评测自动类型识别，更不能据此宣布新的敏感检测精确率/召回率。自然假名也不是天然更稳：原提示11/12，增强提示10/12。

144次调用是12道题的条件对照，独立内容仅4个已暴露故事。138/144总正确数不能用作一般成功率，6个错误位置只来自2道逻辑题。这里只形成下一轮强基线选择依据，不是新算法优势或论文验收。

## 2. 完整结果

每格分母固定为8道合法题和4道缺失信息题，均使用全部四张事实卡与同一Flat-ID接口。

| 表示 | 原提示：合法 / 缺失 / 总计 | 增强提示：合法 / 缺失 / 总计 |
|---|---|---|
| 合成原文 | 8/8 · 4/4 · **12/12** | 8/8 · 4/4 · **12/12** |
| 短粗代号 | 8/8 · 4/4 · **12/12** | 7/8 · 4/4 · **11/12** |
| 长粗代号 | 7/8 · 3/4 · **10/12** | 8/8 · 4/4 · **12/12** |
| 短代号＋人工正确类型 | 8/8 · 4/4 · **12/12** | 8/8 · 4/4 · **12/12** |
| 长代号＋人工正确类型 | 8/8 · 4/4 · **12/12** | 8/8 · 4/4 · **12/12** |
| 自然假名 | 8/8 · 3/4 · **11/12** | 7/8 · 3/4 · **10/12** |

144次均通过工程格式检查，合法题错误事实1个位置、合法UNKNOWN 2个位置、缺失题虚构答案3个位置。具体为：

- 中文关系故事Q2询问某项目的客户：长粗原提示选成承运方F4；短粗增强与自然假名增强返回UNKNOWN。参考是客户F3。
- 英文改写故事Q3询问未提供的预算负责人：长粗原提示、自然假名两种提示均选最终审批人F1，参考是UNKNOWN。

这说明“返回一个有权读取的实体”与“回答了正确关系”是两项不同要求。合法UNKNOWN也必须计为效用损失，不能算安全收益。

## 3. 能归因到哪一层

| 层面 | 本轮支持的判断 | 仍不能声称 |
|---|---|---|
| 迁移/权限协议 | 本轮固定开发文本，不改变已有权限合同；此前原生源/目标输入等价证据保留 | 本轮重新执行了迁移、在线撤权或通用互通协议 |
| 表示与提示 | 相同事实与模型下，不同格式/提示组合出现逐题翻转；简单短粗原提示在这12题已全部正确 | 纯字符长度因果、nonce总体效应、新关系算法不可替代 |
| 实体类型 | 正确类型的表示条件可以达到这批题的上限 | 自动检测达到P90/R95、类型映射没有成本或错误 |
| 运行环境 | 首轮因服务未监听，0模型调用即停止；恢复同一固定运行时后144次完成 | 环境问题解释了所有语义错例 |
| 评测合同 | 另发现CUSTOMER有“客户组织”与“任意组织”两种口径，后续须显式统一 | 旧已声明宽口径结果全部无效、旧gold应改成有利答案 |

短长代号共享同一题的随机串，短形式使用前4位，长形式追加其余20位；类型标签均为8个ASCII字符。字符等宽不保证分词相同，长度比较也改变额外token与可读性。自然假名匹配原值字符数、UTF-8长度和词数，但仍改变词汇语义与分词。结果应称具体表示方案的差异，不应过度解释为纯机制证明。

这一探针没有改生产签名nonce、授权能力或恢复映射。若随后将短模型可见代号接入真实链，仍须保留独立的内部请求身份、来源和当前核权；短显示串不能充当授权凭证。

## 4. 执行、失败与核验

冻结计划canonical SHA-256：`29acc1c72e9a1ea6d2cf13f41afe20ed607af44db95ca73ac6bde17d4dee9f49`。原提示逐字保持；增强提示仅追加通用关系/时间/否定证据规则，没有预算或审批专用示例。12条件轮换，所有条件在12个调用位置各出现一次；同一题的两个提示除system外字节完全相同。

首轮`run_01`健康检查报`ConnectionRefusedError`，0次模型调用，144项均保留为not_run。核实无目标服务进程/监听后，使用已有安装脚本的`-SkipDownload`恢复固定本地服务，校验安装包、模型和版本，没有下载。`run_02`沿用同一个plan02与全部144输入，承接记录绑定首轮哈希和0次已用预算；没有重复任何已发出的模型请求。

实际运行：Ollama0.40.8、Qwen模型digest `0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0`，端点仅`127.0.0.1:11435`，串行、temperature0、seed42。调用阶段约28.344秒，输入49,240/output1,167 token，单次最大528/12，低于固定4096上下文/64输出上限。服务准备时间不混入模型阶段耗时。

120个私有请求及对应响应的注册原值扫描均未见原值；原文24个请求只发送到本地模型。扫描只覆盖登记值与指定出口，不保证完全匿名化、不可推断或检测无漏项。

14份实际运行源码与快照匹配，144个实际请求与计划/回执哈希一致，144个响应绑定、600个summary证据哈希核验通过。根代理另外使用标准库独立重算成绩和逐题错误，没有调用被测评分器；结果一致。预测关闭后执行器才解析评分参考，材料早已暴露，不能将此程序隔离称为盲测。

另有两个发布前仪器修正，均未追加模型调用：首个零调用计划遗漏硬错误停止及部分预定配对，修正后生成plan02，plan01未执行；运行关闭后，在干净目录复现测试夹具依赖`results/`已存在的问题，并将发布版来源冻结改为明确依赖清单，避免把其他测试临时导入的模块当成实验依赖。实际运行快照与发布修正分别保留，不用发布版覆盖原件。

发布版11项新离线测试在原先没有`results/`的影子环境通过。随后干净仓库副本全量发现**1742项：1728通过、14可选跳过、0失败/错误**，测试阶段353.412秒；382份Python文件前后哈希不变，与当前源码一致。工程回归不是模型准确率或论文验收。

## 5. 向量与检测的并行核查

[历史向量持久化取证](历史向量空结果_持久化取证_2026-10-27.md)核实6条旧向量、6次写入和2次删除记录；在副本的最终状态执行3次自身向量查询，均返回对应活记录。首次离线AST转换产生的3个null是本轮诊断编译环境缺陷，已用保存结果、零新增查询定位并纠正。原始历史查询向量和当时瞬态索引未保存，因此**旧4次null根因仍未知**，不能拿3次新查询成功将它们关闭。

[检测类别合同审查](敏感类别合同一致性审查_2026-10-27.md)发现GLiNER/CID/NLI的CUSTOMER包含任意组织，Qwen提示意图更接近具客户关系的组织。完整policy哈希批准保证输入绑定，不证明类别语义同义。旧已批准的保守遮蔽比较保留；后续共同P/R验收须先冻结本体及实际提示/标签定义。可见文本有充分证据的项目类型漏检和实体性误报仍是检测能力问题，不归咎于评分歧义。

## 6. 下一步的收敛决定

1. 冻结**短粗代号＋原提示**作为后续最简单强基线；保留长粗原提示为比较基线、正确类型表示为受控上限。暂不切默认、不宣称它已经在新题达到63/64。
2. 不再在这4个故事上增加提示、换随机串或追加表示以追求全绿。下一次效用比较使用方法冻结后新建的独立材料，区分合法事实选择、缺失UNKNOWN、权限拒绝和工程失败。
3. 新检测验收先明确客户关系组织或任意具体组织的共同合同，确保实际模型输入与参考一致；随后评测真实检测，不能用本轮人工完整类型替代P/R门槛。
4. 继续保留新独立64题、检测P≥90%且R≥95%、历史向量故障解释、完整强基线增量和论文创新等未完成项。本轮明确UNKNOWN、类型标签和自然假名均有已有研究基础，未建立新算法贡献。
