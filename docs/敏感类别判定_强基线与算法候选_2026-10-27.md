# CUSTOMER 合同：算法强基线与可检验假设

日期：2026-10-27。本文仅核对公开一手论文、作者模型卡及官方代码；新增检测模型、付费 API、原生客户端调用均为 0，未下载或安装模型，未访问未开放 fresh64/heldout，未修改 gold 或运行中的 probe。

**结论：客户关系识别应与具体组织提取分开验收。GoLLIE 的指南控制抽取、GLiNER2 的描述式分类/关系接口、多语言三值 NLI 都是必须考虑的已有方法。固定定义、传递定义、返回 offset 或增加 needs_review，本身不足以成为新算法贡献。** 以下基线尚未在本项目执行；官方功能存在不等于客户关系、否定、历史或中英文隐私合同已获验证。

## 值得实现的强基线

| 基线 | 同一任务的具体实现方式 | 必须保留的失败与限制 |
|---|---|---|
| 完整指南的本地 LLM；英文加 GoLLIE-7B 候选 | 给所有臂同一客户定义、业务 scope、历史与否定规则；GoLLIE 放入 docstring，本地 Qwen 放入可信 policy。先比较相同语义输入，另记录模型规模、量化、时延和调用预算。 | 更换模型与指南呈现方式不是纯算法消融。GoLLIE 官方英文定位不应被静默翻译包装成已支持中文。字符串输出的定位后处理必须单列。 |
| GLiNER2.5 multi 的 span 提取＋关系/候选分类 | 完整流水线先从正文产生具体组织候选和准确位置，再用相同 scope 的描述判断 `affirmed_current`、`affirmed_historical`、`explicit_noncustomer`、`unknown/conflicting`；也可比较有方向的 customer-of 关系抽取。 | “没有提取到客户边”不等价明确非客户；纯组织名必须 review。正文用 we/我们作业务主体时，不能暗中补入 gold 公司名。多任务官方接口不证明任意组合仅一次内部前向；记录真实调用。 |
| 共享候选＋多语言三值 NLI | 对每个候选 occurrence 与完整证据窗构造 scope-grounded hypothesis；比较单肯定命题三类，与肯定/明确否定双命题加预冻结冲突处理。strict 的肯定命题覆盖“当前或曾经的客户”。 | NLI 候选必须来自运行时提取，不能来自 gold。neutral/低置信/冲突到 review 的映射是待验证决策策略。512 token 截断不能丢掉否定、历史或跨句指代证据；否则 review 并报告覆盖不足。 |

候选关系分类的公平比较可以共享同一无 gold 候选生成器及位置，但它只是“给定系统候选”的条件任务。最终仍须报告完整流水线的候选漏检与位置 FN，不能只展示候选已知时的关系准确率。仅保留固定组织 NER 作为保守遮蔽参考，不应以该弱臂代替关系强基线。

## 四项可检验假设（尚未执行）

1. **出现位置保留。** 在相同模型、定义和解码预算下，比较 quote 全局扩张，与保留候选 occurrence 或受约束 start/end 的输出。假设后者降低同词普通用法位置上的 FP，且客户名召回不下降。现有 `local_detector._validate_output` 对 quote 执行全文 `text.find` 循环，NER 保留位置；本轮 probe 应保留原行为，不能把其额外位置 FP 全归因于模型。这是接口/解码改进候选，单独增加 offset 不构成新算法。
2. **关系证据三分与时间处理。** 比较宽组织候选直接保护、关系/分类四标签、单命题 NLI、双命题 NLI。在共同候选与证据下，假设显式肯定/否定/未知分解降低明确非客户额外遮蔽，并保持历史客户保护。分别测历史肯定＋当前否定、纠正后的否定、未知关系；review 的已知正例仍计 FN。
3. **定义的因果响应。** 相同正文在 strict 与 broad 下成对运行，再用未见过但等义的定义改写检查稳定性。假设有效方法在明确非客户/关系未知组织上按定义改变判定，在泛称及普通词普通位置保持不标，在肯定客户处保持保护。只换哈希而预测不变不证明遵循定义；定义进入模型本身已有 S1/S3/S4 先例。
4. **证据不足时的选择性处理。** 预冻结 neutral/低置信/证据窗不完整/相互冲突的 review 规则，比较同覆盖率下错误放行与过度遮蔽。假设可减少未知关系被当空结果放行，同时保留可接受处理率。若只是全部 review、降低覆盖率或隐藏正例 FN，假设失败。

上述假设需要新的独立评估材料。当前 16 正文用于合同开发诊断，不能据此调阈值后宣称一般 P/R、P90/R95、正式 64 题验收成功或算法创新。阈值、关系方向、历史范围、候选生成、指代规则和冲突决策须在独立开发材料上冻结；未知/unsupported/工程失败分开列。报告端到端精确位置 TP/FP/FN、确定性判定与跨度均正确数、unknown-review 命中及错误 clean-negative 数、正例 review FN、覆盖率、时延和实际调用预算。

**可主张的后续贡献必须由实验给出：**例如在公平关系强基线之外，对策略条件、证据与出现位置进行联合建模后，在共同隐私约束和覆盖率下仍稳定降低错误。本文没有证明该贡献成立，也未把既有指南抽取、NLI、关系分类、拒答或 offset 视为新发明。
