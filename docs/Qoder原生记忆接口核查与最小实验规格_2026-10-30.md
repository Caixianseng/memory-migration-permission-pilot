# Qoder原生记忆接口核查与最小实验规格

日期：2026-10-30。结论：**现有项目验证了真实Qoder客户端读取由研究主机准备的静态AGENTS文件，但没有验证Qoder自行产生Auto-Memory，再把这种原生长期记忆迁往Harness。** 下一轮应补来源侧证据，不能把又一次静态文件注入计为已经完成这个缺口。

本次只读现有工程、安装元数据、命令帮助及官方文档。没有读取用户私人记忆、私人会话或凭证，没有启动会话、发送模型提示、导出真实聊天或修改全局设置。本文是待执行规格，不是新增实验成绩。

## 1. 三种内容及产品边界

| 内容 | 对本项目的含义 | 当前证据 |
|---|---|---|
| 静态AGENTS/rules | 为后续任务提供持续上下文的文件；可由人、研究主机或Agent写入 | 已实测Qoder读取主机预置AGENTS；尚不能因此说源端自动生成 |
| 会话历史 | 某次会话的消息、工具调用、回答及其恢复/导出 | 当前受控实验禁用会话持久化；没有采集用户历史 |
| Auto-Memory | 从交互中保存并跨会话复用的原生记忆 | 还没有源端原生生成、存盘和新会话复用的完整证据 |

这一区分与Qoder官方的上下文生命周期说明一致。[How Memory Works](https://docs.qoder.com/cli/how-memory-works)。记忆作为模型上下文不等于严格权限控制；本项目仍须由受信主机强制检查迁出、接收与恢复权限。[Memory](https://docs.qoder.com/cli/memory)。

Qoder Desktop/IDE、Qoder CLI、QoderWake是不同产品入口。桌面版提供Settings→Memory及全局/项目目录管理，但没有据此核实本机桌面版格式与CLI等价。[桌面版Memory](https://docs.qoder.com/qoder/memory)。本轮实验对象继续固定为已经安装和测过的Qoder CLI，不能借另一产品的API宣称当前CLI已兼容。

## 2. 本机只读核查结果

| 项目 | 核查值 |

| 包名与版本 | `@qoder-ai/qodercli`，`1.1.77`；package.json与实际`--version`一致 |
| Node | `D:\nodejs\node.EXE`，实际`--version`为`v20.18.0` |
| CLI入口 | `F:\项目\多agent协同\data\runtime\qoder\node_modules\@qoder-ai\qodercli\bundle\qodercli.js` |
| 入口SHA-256 | `9a8fb19bb7f2dfe8d9d9933cb356fd21e789544316bacadc4f6c9b760bd41315` |
| 实际帮助 | 有`--continue`、`--resume`、`--list-sessions`、`--config-dir`、`--setting-sources`、`--settings`；未列出`memory export`子命令 |
| PATH查询 | 当前PATH未找到qoder、qodercli、qoderwake；已知Qoder入口用绝对路径运行。这不能证明其他位置没有安装 |
| 命令执行 | 仅`node --version`、已知CLI `--help`与`--version`，没有执行列会话/恢复会话命令 |

现有 [`qoder_native.py`](../memory_migration_study/qoder_native.py) 只允许受控AGENTS工作区问答，固定`--print`、无工具、单轮、零重试、无会话持久化；自动记忆配置与相关环境开关均关闭。它是静态内容使用适配器，不能直接承担原生长期记忆生成实验。

历史证据 [`qoder_capabilities.json`](../results/native_agent_probe_20261026/qoder_capabilities.json) 已清楚记载自动记忆关闭、未读私人内容，以及空配置根无认证的探针。文档 [`双原生Agent统一记忆协议`](双原生Agent统一记忆协议_实测报告_2026-10-26.md) 也说明源事实由主机预置。这些边界应保留，不能重新命名为原生Auto-Memory迁移。

## 3. 官方支持的读取/导出路径

官方当前说明：Auto-Memory仅用于交互TUI，可用`autoMemoryEnabled`或`QODER_MEMORY=1`启用；项目记忆位于`~/.qoder/projects/<project>/memory/`，另有可选用户级目录；由`MEMORY.md`索引和主题Markdown组成。[CLI Memory](https://docs.qoder.com/cli/memory)。实际本机1.1.77的生效开关仍需用隔离会话验证；不把最新版网页当作安装版本已通过的执行证据。

`/memory`和`/memory manage`提供TUI查看/管理入口。官方`/export`导出当前会话，不能当作Auto-Memory包或权限包导出；需要交互选择器的命令不能简单用headless `/...`替代。[Commands](https://docs.qoder.com/cli/commands)。本机`--help`未列出原生记忆导出子命令；本次核查也未找到当前Qoder CLI公开的带ACL记忆迁移API。这表示**未核实该能力**，不是证明任何版本都不存在。

因此，当前可研究的Auto-Memory源适配器应是“只读取本轮新项目产生的原生记忆目录，保存原件哈希，再提取确切片段”，而非读取全局用户目录。不能使用`--resume`指向已有私人会话来凑来源，也不能把`/export`的聊天全文当作已构建的记忆对象。

相邻产品QoderWake有明确的`memory show/snapshot/export/import`文档，但需要Waker/项目等身份与本地daemon，导入默认预演、显式apply才写入。[QoderWake CLI](https://docs.qoder.com/qoderwake/cli-reference)。它不属于当前CLI 1.1.77的已核实接口，本轮不因此新增平台、安装daemon或改实验对象。

## 4. 可执行的最小补证：分清两个层级

**层级A：Qoder实际生成静态记忆。** 在新建合成项目中，让真实Qoder通过已核实的原生文件写入工具产生AGENTS，再从该实际文件取源内容，执行现有保护交接和Harness问答。必须取得原生工具调用/写盘及退出后文件证据，不能接受模型只在回答中打印一段Markdown。本层补的是“发送端真实产生静态记忆”，仍未证明Auto-Memory、长期记忆构建算法或用户真实记忆迁移。

现有问答包装器禁止工具，不能直接改成无限制执行来完成A。应另建最小写入适配器，先核实本机原生工具名、路径许可与调用证据，只允许本轮新项目内登记文件；不能猜工具名、开放任意shell、绕过原生权限，或改写此前封存包装器的行为。若工具或路径限定不能可靠兑现，记录不合格，不把输出文本伪装为写盘。

**层级B：真正Auto-Memory来源。** 采用本机交互TUI，在新合成项目中启用项目级Auto-Memory，取得原生写盘后再开新会话复用，随后读本轮记忆目录的确切片段迁往Harness。这才直接补原生长期记忆来源的缺口。若本轮只能完成A，报告必须停在A的结论。

推荐B的最小登记规模为一个故事、两条可迁出事实、一个源端专用事实，以及目标端四题：两题合法、一道禁止迁出、一道源中缺失。源侧另登记一次生成会话和一次新会话读取；生成不稳定而无记忆时记录零产物，不反复追问直到得到“好样本”。这些是有限可行性位置，不增加独立故事数，不替代论文效果实验。

## 5. 层级B的执行步骤和验收信号

| 阶段 | 实际动作 | 必须保留的证据/失败方式 |
|---|---|---|
| 冻结 | 新Git项目、独立故事及授权表，固定CLI/Node哈希、模型选择器、启动设置、预算和允许工具 | 源事实和任务在调用前固定；参考答案不交给检测器；没有产物也保留该位置 |
| 隔离预检 | 只启用本项目Auto-Memory；关闭用户级Auto-Memory、项目外指令导入与无关扩展；核实有效设置和真实目录 | 不能仅凭设置字符串宣称隔离；若隔离根无登录，保留认证失败，不擅自复制私人配置、认证目录或记忆 |
| 原生生成 | 向新TUI仅提供合成可记忆内容；允许经过核实的记忆写入机制运行；等待本轮写盘完成 | 原生事件或工具证据、退出/新会话边界、仅本轮新目录的文件清单/哈希/内容。主机代写或修改主题文件不算原生生成 |
| 新会话读取 | 同一新项目重开会话；问题不含随机事实值，不恢复旧会话 | 读入文件/事件与回答；若只能从答案推测加载，明确证据较弱，不能倒推原生读事件存在 |
| 源适配 | 只读取新产物白名单文件；保留原文、文件哈希、确切位置和记忆类型 | `<project>`实际目录从本轮原生管理/事件定位，不猜内部slug规则，不扫描其他项目内容 |
| 主机授权 | 从独立受信合成授权表绑定用户、Agent、对象、read/export/copy/restore和接收者 | Auto-Memory正文里的“允许共享”不能创造权限；如原生文件没有ACL，明确权限是外部附加，不能声称保存了原生已有ACL |
| 迁入使用 | 复用已验证的保护、统一包、目标载入、原始回答和重新核权恢复 | 同一故事、同一事实贯穿全链；缺少任一步单列未完成，不拼接旧批次成绩 |
| 关闭评分 | 封存输入/响应后独立评分，保留失败和费用 | 未授权取得、合法正确、UNKNOWN、错误、接口失败分别统计；一故事多题不当作独立样本 |

项目级目录在用户配置根之下不等于需要读取已有个人内容。主程序只可触碰本轮新项目路径和已授权登录机制；保留原认证材料而不复制其内容。现有历史探针显示空配置根可能没有认证，这一前置缺口需要主程序先验证，不宜在研究报告中略过。

## 6. 暂不声称完成的能力

本轮查资料和元数据成功，不代表Auto-Memory已生成、已加载或已迁移。原生文件可读取，不代表存在稳定导出协议、原生ACL、跨用户租户隔离或在线撤权。模型选择器相同也不证明两端底层模型修订相同。

来源片段若需自由摘要、跨多文件合并或推断依赖，不能直接套用当前确切摘录合同；先保留为不支持，或另立有独立参考的变换规格。迁移到静态Harness AGENTS的副本也不具备原生逐条ACL，仍依赖当前受信主机的新访问门控。

最小实验只解决“真实源产物是否接通当前合同”的工程问题。即使全部成功，仍须与同权限、同材料的普通文件适配强基线比较，才能讨论新方法是否必要；不能把补齐来源真实性包装为已经建立算法优势。
