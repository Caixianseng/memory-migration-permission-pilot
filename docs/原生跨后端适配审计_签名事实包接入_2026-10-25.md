# 原生跨后端适配审计：签名事实包的最小接入

日期：2026-10-25。只读检查代码和相关单元测试；未运行适配器、启动后端、访问外部 API 或模型，也未读取凭据文件。本文不是本轮原生实验结果，不改变已冻结生产包或运行器。

## 结论

已有代码能复用原生账号验证、真实存储读写、用户级容器映射、对象清理及旧任务重放对照。但是，**现有原生入口不能直接证明当前带签名 fact 的协议互操作**：原生入口消费旧 case/plan、Mem0 导出行或 content 字段，没有调用新的 exact-fact grant 验证，也没有原生理解 HMAC label、allowed_agent_ids 或本地 authority 的 epoch。

当前 `prepare_labeled_transfer(..., privacy_pipeline="boundary")` 的同 host JSON 交接，不能据此改称原生跨后端互操作。Open WebUI 原生用户隔离与研究网关的 Agent 绑定必须分别表述。

## 1. 已核对入口与实际边界

| 入口 | 实际做了什么 | 对新签名事实包的缺口 |
|---|---|---|
| `memory_migration_study/native_webui.py` | 固定 Open WebUI 0.12.3；原生 FastAPI/TestClient、独立用户登录、whoami 检查、原生 memories add/search/list；保留原始响应做观测 | `_insert_memory` 只传 `content/path/type`；不验新 grant/label。`_native_plan` 消费旧 case，并固定检查四个迁入副本，不能直接替换成任意新 fact 集 |
| 149 测试工程的 `cognee_local_migration_probe.py` | 固定 Cognee 1.6.5；真实注册用户、官方 `cognee.remember(Mem0Source(..., mode="preserve"), user=...)`、原生数据集读取 | 主要输入是 Mem0 导出行；没有签名 fact 的显式允许字段投影、验签、范围核验和生命周期 sidecar。不能从 preserve 名称推断任意安全字段都被保留并强制执行 |
| 同工程 `openwebui_migration_probe.py` | 按真实目标用户逐读者创建 memory 副本，原生 list/lexical/path/semantic 路径检查；显式 source→target copy 清单 | 迁入的是旧 `record['content']`。新 grant 的 content hash/range、Agent 范围及本地撤权状态尚未与 copy 清单建立接口 |
| `qualify_migration.py` | 真实 Mem0 服务外加明确研究应用网关；绑定凭据到 principal，拒绝调用方自行指定 user/actor；另外区分 Letta 官方 `.af` 回环与自定义跨系统桥 | Mem0 网关 ACL 是研究应用控制，不是 Mem0 原生终端用户认证；新 exact-fact authority 还没有与该网关的资源 ID、当前策略一体绑定 |

Open WebUI 适配器自身已明确：Agent 是 `application_level_fixed_worker`，不是产品原生认证的独立 Agent principal。把来源 `agent_id` 原样写进 metadata 不会自动获得原生 Agent 权限强制执行。

## 2. B 是否可能收到多余完整 source

新 `MemoryLabelAuthority.build_record` 的 record 包含：

- `text`：获授权的 exact fact。
- `source.text`：用于受信 host 核验位置的完整源材料。
- `access` 和 `label`：本地共享密钥域签名的授权与敏感标注。

因此不能把整个 record 序列化后当作 B 的原生 memory content，也不能默认第三方 preserve importer 会安全地忽略全部嵌套额外字段。完整 `source.text` 应继续只保存在受信来源验证域。

最小 B 写入应是**允许列表投影**：原生对象只放经验证的 `record.text`；独立受信 sidecar 保存 fact/源对象定位、范围、内容 hash、授权引用、策略版本及 target native IDs。密钥和 RestorationMap 都不进入导出包。原生 `metadata` 如果不支持安全字段，sidecar 保持在受信网关；应据实称为网关桥接，而非产品原生支持该协议。

当前 `_insert_memory(..., text, ...)` 的窄内容接口可以复用，但它前面必须有新 record 的真实 `validate_access`；不能绕过刚修复的 `scope_version/content_sha256/source_start/source_end` 核验。

验证不能只证明“目标存在预期 fact”。需在完整 source 的未迁移部分放独立受控标记，检查 B 的目标 raw/list/search 响应与错误体中均没有它。当前原生适配器保留完整响应，是可复用的观测基础。

## 3. 身份、权限表达与无法支持的约束

已有强基线覆盖：

- 来源和目标主体需完整、单射映射，身份碰撞或缺失不当作安全。
- dataset owner 是隐式读者，不能只比较 members。
- 多副本可访问关系按并集计算，不能只检查某一个安全副本。
- `source_readers ∩ recipient_readers ∩ target_readers` 与 export/copy 许可分别计算。
- 未知授权、明确禁止导出、禁止复制分别排除；拒绝全部会产生合法访问损失。
- `verify_plan(..., allowed_reader_sets=..., implicit_readers=...)` 可拒绝受信目标模型无法表示的读者集合，但它本身不验证产品执行。

其范围仍是有限注册主体、对象和静态 read 关系。149 工程 `reader_decision` 对其他操作返回 `not_applicable`，这不是“目标已经执行了不支持约束的拒绝”。未看到可覆盖任意期限、用途、share/重新委托、跨 Agent 身份或派生约束的通用能力协商入口。

最小接入应限定一种声明清楚的支持类型：**用户级静态读 ACL + 明确固定应用 worker**。若包要求目标无法强制的额外条件，要在目标写入前明确 unsupported/refused；不能只复制字段后宣称约束保持。若使用网关补足条件，需要检查原生直连是否可绕过，并把假设写入威胁模型。

## 4. 撤权与旧任务重放已有覆盖

149 工程已有以下标准参考，不应重新包装为新算法：

| 控制 | 已有证据范围 |
|---|---|
| 精确 ACL 分组、逐读者复制、reject-all 对照 | 有限静态读关系及合法保留率 |
| 目标撤 read/share、删除迁入对象、重建分组 | 原生动作与后置内容检查；不能仅凭 HTTP 接受判成功 |
| 未迁入 resident 对象 | 检查清理没有误删独立目标内容或丢失其合法访问 |
| 映射 owner、source controller、target admin 等身份对照 | 不静默借用更高权限凭据；403 单列为权限不足，而不是执行成功 |
| `stale_refresh`、`precheck_refresh` | 对照当前源读取与旧 precheck 的差别 |
| `precheck_fenced`、`stale_tombstone` | 受信 policy epoch / per-relation 撤权 floor |
| durable receipt / bound job digest | 区分幂等完成记录与当前授权；持久登记不等于跨源、目标原子事务 |
| still-authorized owner retry | 避免全部拒绝被当成安全成功 |

`migration_replay_probe.py` 已明确不证明墙钟并发、原生目标崩溃恢复、既有明文遗忘或同主体独立授权血缘。其独立 owner retry 是另一读者关系，不能替代刚补的撤权前 G1/G2 同主体独立授权见证。

`replay_registry.py` 当前关系键是 `(source, record, reader)`，receipt 再绑定 job 与 body digest。接新 exact fact 时，`record` 必须稳定指向获授权 fact/位置，而不是只指向包含多个 fact 的整 source；同时 sidecar 需保留每个 grant 与全部目标副本的对应关系。现有原生脚本尚未接这条新绑定。

来源撤权没有自动使目标已存副本失效的产品保证。现有流程依赖显式目标清理和受信 worker 的重放检查；撤权执行者必须有相应目标权限。目标无法由源 controller 清理、或本机网关可被原生直连绕过时，应记录协议不满足，而不是切换 admin 后省略权限前提。

## 5. 最小真实跨后端验证建议

只追加一个有边界的小 harness，复用既有原生方法；不要在旧固定三记忆/四副本 launcher 内悄悄替换成不同分母。

1. **来源与包资格。** 来源使用已核验的真实 Mem0 + 明确研究 ACL 网关；从当前授权读取构造新 exact-fact grant。完整 source 含一个未迁移受控标记，B 仅获一个 fact。受信 host 核对签名、内容/range、真实用户与 worker，再做目标允许列表投影。此时无需模型。
2. **最小目标。** 先选一个原生 Open WebUI 目标，使用现有独立用户身份、原生 add/search/list 和正负控制。证明合法用户读到完整 fact、outsider 读不到、未迁移 source 标记未出现在任何目标原始响应。保留 source fact→全部 target IDs 清单；另有无关 resident 对象防止“清库即安全”。Cognee 作为之后的第二个适配器，不把两者一次性扩成任意互通。
3. **约束不兼容负例。** 提供一个超出声明支持类型的约束，验证在 native write 前拒绝、目标无新增对象；合法访问损失单列。不得用元数据字段存在代替强制执行证据。
4. **撤权及重放。** 撤源 G1 后，用正确目标执行身份清理其全部 native copies，按已知旧 IDs 与 list/search 检查；旧迁移 job 不得重建副本。保留源当前读取 + epoch/floor 与 bound receipt 标准基线，并检查 resident 对象和仍合法内容。
5. **接回既有 G2。** 如本轮需要证明合法独立访问保留，G1/G2 必须在撤权前同时签发，两个受信来源的独立性由 fixture 明示。G1/G2 目标映射分别留存；G1 旧路径失效，新上下文沿原有 G2 仍能访问。相同 fact 仍可沿 G2 合法出现，因此需按对象 ID / 授权路径判分，不能把“再次看到相同字符串”一概算泄漏，也不能反过来忽略 G1 旧路径。

上述前四步是最小 native 资格与安全验收；第五步只把已经存在的本地 G1/G2 协议落到目标对象上，不要求扩成一般多父授权算法。之后才考虑用相同受控任务接真实 Agent；无模型阶段的程序 token probe 不计 LLM 效用。

## 6. 应如何命名结果

- 现阶段可以称“本地受信签名 fact 交接与隐私恢复验证”。
- 按上述实际接入后，可称“Mem0 研究网关 → 某个原生目标的受控 fact/读权限桥接”。
- 未验证的任意 Agent 互通、原生 Agent 身份、跨进程最新状态、防分区/崩溃原子提交、派生语义权限与已交付明文遗忘继续保持未验证。
- 旧适配器强基线和新包接入本身不构成创新成立证据；需在相同约束和分母下与完整简单基线比较。
