# 历史向量空结果：持久化取证

日期：2026-10-27。公开聚合：[机器摘要](../benchmarks/native_vector_persistence_forensics_20261027_summary.json)。详细工件仅保存在本地 `results/native_vector_forensics_20261027_v1/`；本文与机器摘要只公开聚合数字和哈希，不发布数据库、向量、原始响应或日志。

**旧四次 HTTP 200 + `null` 的根因仍未确定，原 v3 的 25/29 失败仍保留。** 本轮新增的是旧持久化状态的取证，不是原查询重放、修复验证或完整源→目标验收。3 次新原生查询的预算已经用尽，没有追加查询。

## 新证据

先对旧 Chroma 向量数据库逐字节复制，再以只读、immutable SQLite 连接审计副本；未打开 WebUI 用户或认证数据库。原向量库的逻辑日志完整保留 6 次 upsert 和 2 次指定 main 副本 delete。六条历史向量均为 384 维 FLOAT32，所有数值有限、范数与 1 的差小于 `1e-6`；其中主事实的两个账户副本向量相同，共 5 种不同向量。最终 4 条活记录与两次删除一致，SQLite `integrity_check=ok`。

旧目录实际包含 3 个空的 HNSW segment 目录，没有 HNSW 索引文件。最初准备检查误以为目录只能有一个 SQLite 条目，在任何原生导入或查询前停止；该失败另存，修正为核对文件清单并保留空目录。**这是本轮准备检查失配，不是历史故障根因。** 初次准备没有执行查询，未消耗 3 次查询预算。

随后在另一份完整副本上，由固定 Chroma 1.5.9 正常打开数据库，每个账户以自己历史 resident 的存储向量做一次 `k=100` 查询，通过 `asyncio.to_thread` 调用原生同步 API。未执行显式重索引、upsert、delete、count/get、HTTP 或模型调用。三个原生查询均返回该账户最终应有的完整活记录集合，分别为 1/2/1 条；文档、元数据和 ID 均与历史存储内容一致，没有跨账户结果或原生异常。

这三次是以 resident 向量进行的新 self-query。历史 `Customer service and delivery status.` 的查询向量没有持久化，原进程的临时索引状态也没有保存。Chroma 打开副本可能从逻辑日志恢复或重建内存索引，故**实际原查询向量重放为 0 次，历史四次空值复现为 0 次**。本轮不能区分旧进程内的时序、索引或查询输入路径。

## 三种结果分别保留

| 观察层 | 输入与操作 | 实际结果 | 新增原生查询 |
| --- | --- | --- | ---: |
| 原生持久化副本查询 | 三个历史 resident 向量，最终状态副本，原生 Chroma API | 3 次正常返回；原生异常/null 均为 0 | 3 |
| 初版离线 AST 转换 | 已返回的三个 QueryResult，隔离编译固定 search 和结果类型 | 3 次 `None`；后续捕获到本轮隔离编译的 Pydantic 异常 | 0 |
| 忠实编译后的离线转换 | 同三份已保存 QueryResult，`dont_inherit=True` | 3 次正常 SearchResult，与固定换算和字段逐项一致 | 0 |

初版诊断脚本含 `from __future__ import annotations`，`compile(ast)` 默认继承了这一选项；固定厂商结果类型模块没有该选项。隔离 `exec` 中的 `SearchResult` 因此未完成定义，构造时抛出实际 `pydantic.errors.PydanticUserError`，固定 search 的 `except` 把它吞为 `None`。单独的零查询检查重现了该异常，并在不继承额外编译选项后对同三份已保存原生结果完成转换。初版执行脚本、计划和报告均保留，未被纠正结果覆盖。

**这是本轮离线诊断器的缺陷，不是历史四次空值的已证根因。** 历史运行正常导入原生模块，并已有同函数成功查询，不能把隔离编译故障套回历史进程。旧原生适配器会把查询、距离换算或结果构造中的任意 Exception 吞为 `None`，这个错误信息丢失机制仍成立；本轮没有取得历史异常类型或行号。本轮实际 `Collection` 对象真值为 True，其完整 MRO 没有 `__bool__` 或 `__len__`，没有观察到非异常的 false-collection 分支。

## 预算、完整性与结论边界

本轮实际原生向量查询 **3 次**；HTTP、count/get、显式写删、embedding、生成模型、付费 API 和查询重试均为 **0**，观察到的网络事件为 0。原生调用使用已有 `.venv-native-webui`，因为 CI 环境没有 Chroma；没有安装依赖。绑定的 8 份原生 Python/二进制源码与 3 份查询控制源码后验摘要一致。离线核验不导入 producer、后端、模型或评分器，63/63 项工件检查通过；这些是同一轮工件一致性检查，不是独立样本，也不是 OS 级执行证明。

可新增的结论仅为：旧存储向量没有发现维度、非有限数值或持久化删除损坏，最终状态能在一次原生恢复路径下通过 self-query。历史进程的具体异常、原查询向量与临时索引状态仍未恢复，未形成生产修复。旧四次空值和原整体失败不关闭；本轮也不增加稳定性、权限迁移或论文创新结论。
