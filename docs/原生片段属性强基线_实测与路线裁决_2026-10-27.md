# 原生片段属性强基线：实测与路线裁决

日期：2026-10-27。项目仍是 Agent 记忆安全迁移与权限保持；本轮检查迁移前敏感标注这个环节，没有更改迁移协议、授权规则或默认检测器。

## 1. 结论

固定 GLiNER 模型的原生实体片段属性接口已接通并完成一次真实本地实验，但未达到预注册推进条件，暂不替换现有方法。严格客户关系策略全部阻断；宽泛组织名策略的可准备数改善，但精确检测不及同材料 Qwen，且存在局部名称残留。

这支持两个判断：当前问题包含语义判定与实体边界错误，不能归结为协议字段丢失；增加一个现成分类接口也不能直接形成论文创新。此前任务预算方向亦被简单强基线覆盖，不据此继续扩大仿真。

“确定案例”指参考策略可以作出敏感/不敏感判断的案例。“可准备”只表示隐私处理层产出拟发送载荷，不表示下游 Agent 回答正确。严格策略另有 2 条真正未知关系，应当待审。

严格策略本轮为 10 个语义待审、2 个候选数量超限；没有已准备载荷，不能称“零泄露且可用”。宽泛策略为 10 个可准备、2 个候选数量超限；精确跨度 TP=8、FP=6、FN=4，精确率 57.14%、召回率 66.67%，没有达到 P≥90% / R≥95%。10 个可准备载荷保留了预先指定的普通事实，10 个错误主体负控均被拒绝。

原文档分类严格策略中的唯一载荷来自一个本应待审的未知案例，因此“0/10 确定案例可准备”和“1 个载荷”并不矛盾。

旧结果没有重新调用模型。两代方法的候选生成 schema 不同；宽泛策略还去掉了不必要的客户关系门控，不能将差异单独归因于属性分类器。新评分器与旧封存三臂的 72 行结果作零模型差分，162 个共有聚合值全部一致。

## 4. 失败具体发生在哪里

1. **类型与关系混淆。** 明确不是客户的组织被判成关系未知；已终止关系的历史客户也可能被判成非客户或未知。接口返回合法，不等于语义判断正确。
2. **候选边界错误。** 模型把 `our company`、`customer/supplier/buyer` 等泛称提为组织名；两个正文因超过 2 个候选触发预先规定的覆盖阻断。没有按结果临时提高上限。
3. **同词不同位置未区分。** `splice`、`捻线` 的普通词用法与组织名用法被同时提取。宽泛策略过度遮挡，严格策略因置信不足阻断。
4. **中文实体不完整。** 对“琥籽筛具有限公司”只提取“琥籽筛”，对“雾稞仪表联盟”只提取“联盟”。完整实体精确匹配会判错，但仅检查完整原字符串是否仍出现，会漏掉局部残留。

实际拟载荷分别留下了“`[代号]具有限公司`”和“`雾稞仪表[代号]`”。因此 0/10 只表示没有匹配到登记的完整原字符串，不能写成零隐私泄露。这是封存后发现的具体见证，不是完整的语义泄露评测；原有指标和真值未回改。

## 5. 同期修复：诊断器不能制造新故障

向量诊断观察器原本在自身记录异常时抛出新的 RuntimeError，可能改变后端原来的 `None` 返回或遮住原异常。本轮改为保留后端行为、独立记录 `observer_failure`，并让新诊断验收拒收观察失败的结果。11 项离线故障注入/验收测试通过。

这不代表历史 4 次 `HTTP 200/null` 已定位。重新读取上次封存的 164 请求诊断后，四个历史位置返回记录数为 3/3/1/1，15 次后端查询全部正常；历史故障复现次数仍为 0。观察器失败分支当时没有触发，故不为此次修复重跑相同 164 请求，也不按新格式追改旧报告。

下次业务必要运行经过该接口时，可沿现有调用记录实际查询向量、容器、过滤条件、k、阈值及故障阶段，禁止为观察额外发起读取。获得具体差异证据后再设计最小复现。

## 6. 路线裁决

**本轮强基线推进条件失败，默认方法保持原样。** 不降低门槛或改答案追求过关，不把接口接通称为论文创新，不立即在同一批已暴露材料上追加提示调参。

后续有价值的工作是：把“完整原值未命中”补充为能够检查实体局部残留的预先定义指标；将实体边界、关系判定和授权执行分别定位；用独立材料验证候选方案后再运行 Agent 任务。新指标的开发材料与最终验收材料要分开。

目前仍未达成整体论文工程验收：一般敏感检测 P90/R95、独立 64 题至少 63 题联合成功、历史向量问题归因，以及稳定超过完整强基线的创新证据均未成立。持续目标保持进行中，自动研究不因这一子实验结束而宣称完成。
