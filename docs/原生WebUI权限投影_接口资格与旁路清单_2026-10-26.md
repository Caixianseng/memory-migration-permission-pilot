# 原生 WebUI 权限投影：接口资格与旁路清单

日期：2026-10-26。**本轮仅源码资格审查和假测试，没有启动 Open WebUI、创建原生身份、调用模型或联网。** 下列实际投影结果均保持 `unverified`，不能将可行接口与单元测试当作原生实验通过。

以上是清单编制阶段的状态。后续主任务已完成[原文/Note ACL与网关的真实对照](共同源权限投影_原生对照与网关结果_2026-10-26.md)：两个隔离臂共222次HTTP，网关25项符合、原生11项读取一致，14项受约束操作在本适配中不支持。本清单列出的其余元数据、替代内容入口和搜索旁路尚未全部执行，不能从已测结果推断通过。

## 1. 已核对的实际安装与旧适配器

本机专用环境为 `.venv-native-webui`，安装分发元数据为 `open-webui 0.12.3`。当前真实适配文件是 `scripts/native_exact_fact_target.py`，没有名为 `native_exact_fact_target_worker.py` 的对应文件。三个 `native_vector_*_worker.py` 继承该 target，再观测原生向量路径；它们不是新的身份系统。

旧 target 本来就使用 `TestClient` 真实 ASGI HTTP：原生 `/auths/signup` 首建管理员，管理员 `/auths/add` 建普通用户，再分别 `/auths/signin` 和 `/auths/` 核验。因此不能把它误说成直接 SDK 传入 user 对象。旧 `NativeWebUIAdapter` 也明确 Agent 是应用侧固定绑定。它只覆盖 owner/assistant/outsider 三个业务账户，不足以直接代表本轮四个用户—Agent 对。

旧路径还调用 `legacy_project/scripts/openwebui_migration_probe.py` 的 configure，该完整模块顶层依赖旧 `memory_transition_oracles`，并配置本地 MiniLM；本轮新 worker 不依赖这套旧工程或模型资产，不改旧文件。

## 2. 为什么选正式文件＋Note，而不选知识库/向量路径

官方 `routers/knowledge.py::create_new_knowledge` 在创建知识库后直接调用 `embed_knowledge_base_metadata`；后者调用 `app.state.EMBEDDING_FUNCTION`，没有已核实的跳过开关。`/{id}/file/add` 还要求处理后的 file.data，并调用 `process_file`。不能为满足零推理要求替换这些实现、伪造成功或隐去尝试。

正式 `POST /api/v1/files/?process=false&process_in_background=false` 则把上传字节存为原生 file，跳过 `process_uploaded_file`。正式 Notes 的 create/update/access-update 路径只做原生持久化、ACL 和事件处理，没有已读代码中的生成/embedding 调用。

本轮采用 **每条精确事实一个原生 file＋一个 owner 所有的 Note ACL 容器**：Note 的 `data.files` 精确引用 `[{"type":"file","id":file_id}]`，`data.content.md` 为空，不复制整段源文档。官方文件访问控制会从 file 所有者的 Note 中查精确附件 ID，再检查该 Note 的 read grant；创建者与 file owner 不相符的任意 Note 不能因此授予读取。

这属于原生持久文件/笔记读取权限投影，不是自动 Agent 记忆、知识库索引或向量效果。当前没有一个新原生响应，接口是否在本机运行成功仍待实测。

## 3. 身份与运行边界

新增 `scripts/native_webui_projection_worker.py`：`owner`、`alice_reader`、`alice_worker`、`bob_reader`、`bob_worker` 五个普通原生用户分别创建、登录并 whoami；初始 `bootstrap_admin` 单列，不代替业务主体访问。四个组合主体明确表示 Alice/reader、Alice/worker、Bob/reader、Bob/worker。

这是**不同原生用户账户编码不同用户—Agent 对**的正常投影，不是 WebUI 独立认证了 Agent 身份。产品看到的是不同用户 UUID；可信控制平面负责源元组到凭据句柄的映射。所有凭据正文仅在内存；auths 响应可能含 JWT，原始正文和哈希均不存，只保留 whoami 解析后核对的 ID、role 和请求索引。原生认证数据库正常由应用自己管理，不读取其中凭据字段。

CLI：

```text
.venv-native-webui/Scripts/python.exe scripts/native_webui_projection_worker.py --state <NEW_ASCII_SYSTEM_TEMP_CHILD> --http-cap 200 [--openssl-dll-dir <EXISTING_OPENSSL3_DIRECTORY>]
```

新进程、全新 ASCII 系统临时子目录、已存在的专用环境是前提；不安装依赖、不下载模型。必要时使用现有 OpenSSL 3 DLL，worker 不提供或修补 DLL。

官方配置设 `RAG_EMBEDDING_ENGINE=''`、`RAG_EMBEDDING_MODEL=''`：`routers/retrieval.py::get_ef` 的本地模型加载条件不成立，启动后必须观察 `app.state.ef is None`。保留模型 API 关闭与显式死地址，网络审计仍禁止端口9、模型端口及外网，仅允许 stdlib 内部 socketpair。Python inference-entry guard 对生成/embedding 入口记尝试并抛错；这些是可审计入口边界，不是硬件级证明。使用真实文件/Note 请求，不覆盖 auth、ACL、DB、embedding 或存储函数。

init 预期18条原生 HTTP 入口（6次创建＋6次独立登录＋5次 whoami＋1次匿名负控制）。这是源码上的请求计划，尚未实际执行；每臂硬上限200，所有设置、失败和读取都计数。超过上限在下一次 forward 前阻断。

## 4. 与统一执行器对接的 RPC

每行 RPC 使用既有 `serve_commands` 的 `{id,command,data}` 格式。所有目标数据和读取均在真实 HTTP 中产生；worker 不按本地读者集合过滤 `read_raw`，也不会在只读用户尝试分享前替原生系统作拒绝。

| command / data | 实际原生接口 | 返回与边界 |
|---|---|---|
| `init {}` | signup、admin add、独立 signin、whoami、匿名 notes list | 五个业务普通身份；bootstrap 单列，所有能力测量尚未完成 |
| `create_dataset {dataset,actor:'owner'}` | `POST /api/v1/notes/create` | dataset 只能 readonly/managed；返回顶层 `id` 及映射，实际为 Note ID，初始 ACL 空 |
| `add_exact_fact {dataset,fact_key,actor:'owner',text}` | 上传 file `process=false` → Note update 挂附件 → owner file content 阳性 | fact_key 与 dataset 同名；最多2条、每条4096字符；原文响应必须逐字节等于输入 |
| `grant/revoke {dataset,actor,recipient,permission:'read'}` | `POST /api/v1/notes/{id}/access/update` | 发送完整读者集合，保留其他读者；200还需核返回 grant 集合及后续原文关系。revoke 并非 Cognee 的 DELETE 路由，不能复用其消息字符串 |
| `read_raw {dataset,fact_key,actor}` | `GET /api/v1/files/{id}/content` | 原生 FileResponse，无 JSON 包装；相同 file ID 的授权阳性建立后再判无权404 |
| `list_datasets {actor}` | `GET /api/v1/notes/`，不传 page | 原生 JSON 数组，原生不分页查询所有可读 Note；空可见性是 `[]`，不接受 null/{} |
| `list_data {dataset,actor}` | `GET /api/v1/notes/{id}` | 原生 NoteResponse 对象；`data.files` 含实际 file ID；正文为空，不以此替代原文读取 |
| `summary {}` / `report {}` | 无 HTTP | `datasets[k].id` 为 Note ID，`facts[k].id` 为 file ID；含全部请求证据、固定失败、入口计数 |
| `snapshot {}` | 四个组合主体分别 list；每个已注册 fact raw＋Note detail | 2fact 时20条原生请求；属于相关关系检查，不是20独立样本 |
| `close {}` | 生命周期关闭 | 恢复 profile、关既存 DLL handle；不把原生状态冒充已删除 |

trace 与 Cognee 对齐：`index/status/response_checked/execution_error/cookie_present/authorization_present/native_raw_body/native_body_sha256`。非认证响应另外保存原始字节文件；上传保留实际 multipart 内容、字节数及哈希。没有重写响应内容。每请求清理 cookie 并检查实际发送头；JWT 和密码不进入 trace。

## 5. 原生响应 schema 与拒绝条件

- `notes/`：`list[NoteItemResponse]`，元素含 `id,title,data,is_pinned,updated_at,created_at` 及可选 user。它会截短 data.content.md，不能据此断言 Note 完整正文；本夹具正文为空且只用其可见 ID。
- `notes/{id}`：`NoteResponse`，含 `id,user_id,title,data,meta,access_grants,created_at,updated_at,is_pinned,write_access`；data.files 保留附件 ID。已有 Note 的无读权分支为403，缺 Note 为404。
- `files/{id}/content`：成功返回上传的原生文件字节；无权访问现存 file 的分支为404来隐藏存在性。必须先用 owner 阳性确认同 ID/同内容，再核其他主体；不把任意404或空内容当安全通过。预期合成 A71/B92 各19字节，实测若不同则保留失败，不能修改材料补成绩。
- 只有 read 的用户向已有 Note `/access/update` 发分享变更：源码要求 owner、write grant 或 admin，预期原生403；认证401、其他执行异常单列，不能算预期权限拒绝。

普通用户 notes 功能和个体 grant 的正式默认开关分别为真；public Note 分享默认假，仍保留。`filter_allowed_access_grants` 会检查 `access_grants.allow_users`，不应为使试验成功而跳过它。源码的 UI 分享开关与该 API 过滤不是同一个检查；本轮不据源码推断所有运行配置或 UI 行为均已验证。

## 6. 必须保留的旁路清单

新增 `bypass {dataset,fact_key,actor,operation}` 只允许这份固定只读清单：`file_metadata`、`file_data_content`、`file_content_html`、`file_content_named`、`file_list`、`file_search`、`note_search`。分别使用实际 files metadata/data/content/HTML/named-content/list/search 与 notes/search 路由。原始响应全项扫描两条注册事实及所有原生 IDs，不只看选中的命中；词法 filename search 不是语义向量检索。

原生 `has_access_to_file` 还会汇总合法知识库、共享模型、channel、shared chat 和 file owner 的共享 Note 路径。这是源码可见的有效授权来源，不能把其存在自动称为漏洞。新隔离状态只建立本试验声明的 Note/file，不导入其他共享对象；若未来增加这些来源，必须登记独立授权并重新测撤权，不能宣称本轮已穷尽所有产品路径。公开 Note、共享 chat、模型附加、已交付明文和多租户攻击均未新增运行。

N/G 两臂必须各自新状态。N 由统一源规则控制器重算完整 ACL 并真实下发，G 的四个普通主体不获原生 ACL，门控使用可信 owner 读取后交付，再探同一目标的直达旁路。两者都是完整标准基线；本 worker 自身不决定源策略，也不把 coordinator 的撤权更新称作 WebUI 原生跨系统撤权。

## 7. 冻结证据

新 worker 内固定12个已审阅官方源文件的SHA-256，init 检查已安装分发版本及每个原文件哈希，不执行归档源或修 vendor。主要源码为 `routers/auths.py`、`routers/files.py`、`routers/notes.py`、`models/notes.py`、`models/access_grants.py`、`utils/access_control/files.py`、权限过滤以及正式 retrieval 工厂；完整哈希以 worker 的 `FROZEN_VENDOR` 为准。

`tests/test_native_webui_projection_worker.py` 仅以 FakeClient 检查请求路由、原始字节保留、凭据日志隔离、完整读者集合与硬计数；不会导入 Open WebUI 或发真实请求。它通过只能证明新适配器合同，不提高原生成功率或独立样本数。实际资格、旁路和完整源规则投影都须另存真实结果；失败时保留原件，不借修改 schema、材料或目标权限放宽结果。
