# 原生权限语义投影：最小源合同与测量矩阵草案

日期：2026-10-26。**冻结前方案，不是实验结果。** 本轮只读指定实现并编制合成合同，未操作 WebUI/Cognee、未调用任何模型或付费研究接口、未修改核心代码。可审阅机器模板：`docs/proposals/source_policy_projection_contract_v1_20261026.json`。

## 1. 先限定要测什么

研究源端明确称为 **trusted reference gateway（可信参考网关）**：主机给定真实身份、精确事实及正确授权，测同一合同在两个目标上的实际投影。它不是厂商原生源 IAM，更不是已验证的“Mem0 原生 IAM → 两种系统”迁移。先做直接 API/权限测试，不引入 LLM 权限抽取、语义检测或回答能力这几个混杂因素。

最小夹具只有 **1 个合成故事、2 条精确事实、2 个用户、2 个执行 Agent**。25 个预定义断言覆盖 8 个语义主题（身份、读取不蕴含其他操作、分享、导出、委托、期限、撤权、重放）；另有 10 项能力索引。它们是相关的结构检查，不能写成 25 个独立案例或把两个目标的矩阵格数当样本量。`delegation_expired` 与 `root_revoked` 是从同一前状态分出的两条分支，时间不倒流串行执行。

源合同是否能运行，与目标是否能保真表达是两件事。本模板中目标能力全部为 `unverified`；share/delegate 的参考求值器也尚未实现。**先补纯本地参照及资格检查，再冻结端点和请求上限；本文件本身不能触发执行。**

| 指定文件 / 接口 | 本轮实际核对的能力 | 不能据此声称的能力 |
|---|---|---|
| `memory_labels.py::MemoryLabelAuthority.build_record / validate_access` | 可信所有者/读者与执行 Agent 分开检查；原文、精确跨度、内容哈希及签名绑定；记录/来源撤权、epoch 与可选当前 authorizer 检查 | 接口没有 operation、接收方、导出去向及父授权链参数；不是通用 share/delegate 授权器。读者集合与 Agent 集合的现有乘积表示不自动等于任意“用户—Agent”联合授权集合 |

`scripts/migration_policy.py` 及本轮核查的几个具体旧目录中未找到该 legacy 文件。按主任务要求不扩大扫描；不把旧规范当现行实现证据。以上结论仅来自指定三个现行文件，不外推相关依赖的未读实现。

因此，本轮应新增一个小的**操作参照/投影测试器**，复用原有精确事实和身份保护；不修改签名、恢复规则，不把敏感标签当授权。新参照实现前，不能将模板预期值登记成已执行的源网关结果。

## 3. 统一合同的最少语义

每个请求至少绑定 `user_id + executing_agent_id + exact_object + operation + recipient/destination + current_policy_revision + time`。身份由可信认证层解析，不接受请求体或记忆文字自行声明。每条 grant 对一个完整用户/Agent 对生效；多条授权可以提供独立合法依据，但不能分别取用户集合与 Agent 集合再交叉扩权。

权限分别定义：

- **read**：经受管接口交付精确事实。
- **share**：为指定接收者创建平台内可撤回的读取授权；新授权依赖指定父授权。本实验不把分享定义成任意自然语言复述。
- **export**：经明确的受管导出接口输出到指定目的地。已经有权读取明文的人可以手工复制；本实验不能宣称从信息上禁止这一点，也不把所有读取误算为非法导出。
- **delegate**：创建显式子授权，限制对象、接收者、操作集合、期限和转授权深度。子授权不能超过父授权。平台创建读者与委托执行权限分别留痕，不能混用名字掩盖不同语义。

有效期用 `[not_before, expires_at)`。当前授权为“至少存在一条合法独立授权，且该授权及所有依赖祖先当前有效”。源事实有效性、grant 期限、撤权、删除是不同概念；首轮固定事实内容，暂不研究自动时间语义抽取。

初始迁移由单独获准的可信控制平面执行，不能因用户可读而默认用户有 export 权。对目标所有者/管理员的合法控制能力不作攻击者能力；旧 import job 只能经受管迁移入口重放，攻击者不能借管理员凭据任意创建新对象。

## 4. 两条事实与最小状态机

`fact.readonly` 仅授权 Alice/reader 读取，用 P01—P06 检查跨用户、跨 Agent 与 read 不能升级成 share/export/delegate。

`fact.managed` 初始有两条独立授权：`grant.root` 给 Alice/reader 受限 read/share/export/delegate；`grant.independent` 单独给 Bob/reader read。合法 share 只给 Bob/worker 创建 read 子授权；合法 delegate 只给 Alice/worker 创建截至逻辑时间 20 的 read 子授权，子授权不能再委托或导出。

| 状态 / 断言 | 主要预期 | 要避免的错误判断 |
|---|---|---|
| initial：P01—P12 | 3 个身份读取判断；只读不能升级；合法分享/导出/委托成功，错误接收者/目的地/操作扩张拒绝 | 把原生不支持操作算成漏洞；把已有独立 read 当作 share 操作被允许 |
| with_children：P13—P16 | 两个新接收者可以读取；子 Agent 不能再次委托或导出 | 只有接口返回成功，却没有核对实际授权副作用 |
| delegation_expired：P17 | 到时间 20 后新读拒绝 | 永久缓存旧 allow，或将 source 事实时间误作 grant 期限 |
| root_revoked：P18—P23 | 根及两个依赖失效；Bob/reader 的独立 grant 保留；依赖旧 job 拒绝，独立旧 job 在重新核权后可幂等保留 | 删除整个共享容器“解决”撤权，却误删独立合法依据；重放旧快照复活授权 |
| all_managed_revoked：P24 | 再撤独立 grant 后，新的受管读取拒绝 | 用旧对话已有明文当成新检索，或声称可让用户遗忘 |
| initial：P25 | 旧 job ID 配不同正文，拒绝为 `invalid_replay` | 把数据完整性失败混入正常权限 allow/deny 分母 |

状态切换有完成屏障，串行操作。首轮不声称测试分布式原子提交、竞态或崩溃恢复。后台队列若不能确认终态则该项 `unverified`，不以等待超时当作安全通过。

## 5. 每个目标保留两条完整强基线

**N：目标能力内正确原生投影。** 允许正常的按接收者/授权拆对象、one-to-many ID 映射、容器划分、索引失效及普通缓存。也允许声明清楚的组合主体账户投影，但须记录实际原生主体类型、账户/凭据数和用户—Agent 映射维护成本；这不等于产品原生提供独立 Agent IAM。两用户共用 owner key、只改 JSON 中 actor 字符串，不能成为原生身份试验。约束无法表示就明确安全拒绝，不能静默丢字段制造“成功迁移”。

**G：完整当前 ACL 参考网关＋普通缓存。** 检查所有祖先、独立授权、操作、接收者、目的地、期限、策略版本和 job 正文；允许普通索引、批量核权及依赖失效。此前98格的完整重算/正常缓存已否定简单算法优势，本轮不能重新弱化它。该网关须真正覆盖被测所有路径；如果最终用户能用同一权限绕过网关直读目标原文，就不能把该部署计为完整 `gateway` 保护。

同一目标各约束的状态可以不同，例如身份读取原生、重放入口外部门控、某种导出不可表达。不要给整个产品只贴一个笼统“安全/不安全”标签。PAM 的完整当前授权适配可作为后续协议基线；首轮没有实际适配和测量时应明确未测，不能把本地参照命名为 PAM 作者系统。

## 6. 四态与实际证据

| 状态 | 最少需要的证据 | 如何计分 |
|---|---|---|
| `native` | 版本/真实认证主体/实际目标对象；真实操作及可达 get/search/list/共享/导出旁路检查；目标本身强制该条约束 | 只对证据覆盖的语义和接口成立；记录映射代价 |
| `gateway` | 当前源核权和出口的完整实际门控；在范围内的原生旁路关闭/不可达；不声称目标原生能力 | 安全与合法效用分别记；网关有开销也不能据此削弱其保护 |
| `unrepresentable` | 本版本/本适配臂无法保真表达，能力探查与正确拒绝可复核 | 正确拒绝保安全，但合法操作未完成/不可实现；不是漏洞，也不是合法成功 |
| `unverified` | 尚未实测，或认证/传输/服务/空响应导致无可靠结论 | 不纳入已验证安全或成功；完整分母中单列 |

模板中 Open WebUI 与 Cognee、N/G 两臂、每个约束均从 `unverified` 开始。本轮没有根据产品印象预填“不支持”。具体端点须在实际版本资格审查中填写；不虚构接口路径。

先用授权身份确认对象确已存在/可读，再以独立真实身份访问同一对象；读取授权判定以原始响应实际交付为准。搜索或列表需要检查全部返回项，不能只看有利的一条。HTTP 200+null、空结果、401/403、404、执行错误分别记。实际 allow/deny、操作副作用、传输结果和四态分类是不同字段。若某接口不存在，保留该接口边界，不拿另一路成功覆盖它。

原始请求/响应证据按白名单存储，公开报告只用合成内容、哈希、固定错误和匹配对象 ID；认证头、凭据正文、恢复映射、账户信息不进入工件。每个物理请求（包括建用户、建对象、清理、重试、健康检查）都必须有归属和计数，冻结前确定总请求上限；本模板上限为 null 表示禁止执行，不是无限预算。

## 7. 冻结和停止

冻结前必须完成：参照求值器独立验证25预期、两产品实际版本/身份映射/端点和旁路清单、临时资源清理方案、固定物理请求上限、源政策及事实哈希快照、N/G 完整保护均不弱化。来源哈希与状态值都固定后才能运行；这份草案不包含任何新模型任务。

执行应分资格与测量两步：先核实版本、真实身份和 P01—P03 所需读取路径；对象本来不可读或两身份无法独立认证时，停止该原生臂，不能继续堆重放测试。某操作没有可用原生接口时，记录能力边界与正确拒绝，不伪造接口。只有当前读取和操作确有可测路径，才进入对应生命周期分支；不同分支使用独立隔离命名空间或完整可核对的复位，不让目标状态跨分支污染。完整网关臂也必须先证明在范围内无直达旁路，否则不能靠网关“自报拒绝”通过。

本轮已用不导入项目模块的临时纯 Python 求值检查25项草案预期、跨度/哈希、主体引用和全部初始四态，检查一致；这是合同静态自检，**不是已部署参考求值器、原生运行或独立样本验收**。JSON 中已记录三个指定源文件的审阅时哈希。正式执行器仍应自己验证合同和独立参照，不能用同一模板预期反向构造运行结果。

预注册报告至少分开列：未授权交付/副作用、合法成功、安全但不支持的拒绝、未核实失败、独立 grant 保留、旧任务重放、原生/网关可实现范围、建模与维护/清理开销。第一次小夹具只证明测试合同可执行；要形成测量论文还需独立材料和非平凡的可复核发现，不能靠扩张矩阵数字。

**可证伪的窄问题：**同一正确源政策，采用各目标合理完整的原生映射后，是否仍有在生命周期中才显现的权限/可用性投影差异？完整网关是否修复，代价是什么？这不是新算法假设。如果只有文档已说明的不支持，或正常原生映射/完整网关平凡解决全部条件、没有有用的交互与代价发现，应停止“算法创新/已成立测量贡献”的主张，收敛为兼容性工具或工程报告。认证失败和空响应更不能用来填补论文差异。
