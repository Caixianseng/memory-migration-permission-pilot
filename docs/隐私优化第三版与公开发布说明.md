# 隐私优化第三版与公开发布说明

## 优化内容

本轮把改进集中在完整实体边界与可用性：已经核验的姓名、客户、项目、地址片段若截断了连续字母或编号，做有限边界闭合；在问题和记忆间传播已识别的同值实体。相似前缀形成不同的完整值与代号，不能把短名称和长名称混成同一对象。短姓名不会在无关普通词内部匹配。未明确识别的中文后缀、空格分隔后缀或语义关系仍可能遗漏，不能任意把整句视为一个敏感值。

JSON输出的类别枚举按可信策略动态收紧，宿主继续核验类别及原文位置。对模型多加的外层成对引号等格式，仅在内部证据仍逐字存在时修复；不使用错字、空格或语义模糊匹配。模型没有工具，不能自行改策略或授予权限。

新增实际拟外发文本评分：用临时映射验证逐段替换是否与原文对齐，随后才用独立金标计算完整遮蔽、部分遮蔽、未遮蔽和额外遮蔽字符。金标不提供给检测或转换函数。待审与阻断保留分母；额外遮蔽字符只作为可用性风险代理，不能等同问答质量。

## 保留一次失败，处理预算退化

最初的v3静态提示为1674字节，较长的系统提示加上固定4096上下文、1024输出预留，使多条正常输入在长度预检阶段被阻断。在该次独立40条保留材料上，v2组合召回率74.55%，v3降至51.82%；可准备请求从33/40降至17/40。这是退化，未选为默认候选。

失败的代码、数据、原始输出和冻结清单保存在本机；可公开的聚合结果见[失败候选摘要](../benchmarks/privacy_v3_rejected_summary.json)。没有修改旧标签或删除失败病例。

随后把静态提示压缩为v3.1紧凑版本，保留信任边界、完整实体、原文证据、结构化输出和不确定时待审的要求；上下文、输出预留、模型权重和规则不扩大。使用另一批全新冻结材料验证，而不将已经看过的失败保留集继续作为独立验证依据。

## 最终冻结验证：收益与退化并存

最终版本为`local_sensitive_spans_v3_1b_compact`，静态提示835字节。另一批40条未注册实体材料全部作为保留集，中英文各20条；10个模板族、40个故事，均为自编合成材料，尚未独立人工复核。两个版本以相同模型权重、4096上下文和1024输出预留串行运行。每个模式分别执行，结果是单次冻结观察，不作显著性推断。验收后不再据此调参。

| 指标 | 冻结第二版 | 第三版紧凑候选 |
|---|---:|---:|
| 组合检测完整片段精确率 | 82.42%（75/91） | 76.24%（77/101） |
| 组合检测完整片段召回率 | 78.13%（75/96） | 80.21%（77/96） |
| 组合检测待审病例 | 1/40 | 6/40 |
| 可准备请求 | 35/40 | 34/40 |
| 可准备且无金标遮蔽缺口的病例（含无敏感金标病例） | 30/40 | 23/40 |
| 准备后仍有不完整遮蔽的病例 | 5/35 | 11/34 |
| 已准备病例中完全遮蔽的金标片段 | 70/81 | 67/80 |
| 部分遮蔽／完全未遮蔽片段 | 6／5 | 6／7 |
| 额外遮蔽的非金标字符 | 76 | 209 |
| 实际文本对齐评分错误 | 0 | 0 |

待审和后续外发门控是不同环节，因此第二版1条待审不代表只阻断1条。两个版本可准备病例不同，准备成功子集的片段数不能直接当作总体安全率。新版本完整片段召回小幅增加，但误报、待审、实际遮蔽不完整和过度遮蔽均有退化。**第三版不晋升为已验证方案，仅发布为可复核的研究候选。第二版同样未通过门槛，不能作为已安全的替代方案。** 当前代码用于公开或合成研究材料，不能宣称未知敏感内容已全部去除。

旧7题无业务词表的本地回归为：5/7可准备、2/7待审阻断；可准备输入中已注册原值残留0/5，代号恢复及隔离自检24/24。它仅覆盖已知故事及注册值，不抵消新材料暴露的问题，也不是模型答题成绩。工程测试为292项通过；本轮云端调用0、API新增费用0元。

仅用待公开文件另建干净副本测试：279项执行通过，13项因为缺少不公开分发的原生交接资料而明确跳过，无失败。冻结语料保留原始字节，避免Git换行转换导致清单失配；公开副本的语料和基线哈希另行核验。

完整报告在本机`results/privacy_agent_v3_release/index.html`，包含冻结清单、检测与真实遮蔽评分、旧题回归和测试日志。公开聚合结果见[最终结果](../benchmarks/privacy_v3_release_summary.json)，先前长提示失败结果亦保留。历史费用账本和第二版结果以哈希复核，不能把不同语料的跨版百分比直接当作算法收益。

事后错误分析显示：地址前缀、机构尾码仍会截短；角色称谓、描述语、邮箱可能被误判为其他实体；部分姓名和项目完全漏检。检测片段未完全匹配也不总等于原值已外发，例如重叠片段合并可能完成遮蔽，因此保留独立的实际文本评分。本批材料现在已经看过，只能继续用于错误分析，后续算法若按其失败调整，必须另找独立验证材料。下一轮应先改善类型约束及完整边界，并比较规则、实体识别模型与本地大模型的成本和泛化；本轮不继续重刷验收。

## 从公开仓库运行

无需原始数据、模型或API凭证，可以先验证核心处理流程：

```powershell
python -B -X utf8 examples/privacy_roundtrip_demo.py
python -B -X utf8 -m unittest discover -s tests -v
```

演示只使用自行编写的虚构材料和格式规则。它固定选择客户代号作为**模拟**云端回答，检查合法恢复与跨用户阻断，不评价大模型答题能力。

需要本地模型检测时，在Windows项目目录安装已锁定的便携环境：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup_local_privacy_agent.ps1
```

服务仅监听`127.0.0.1:11435`，关闭云功能。官方模型和运行时资产保存在被Git忽略的`.runtime/`，不会上传。没有配置或授权外部模型时，离线测试和本地检测不产生API费用。

已有原生快照的本机用户可运行`privacy-local-check`。克隆仓库不会得到原生运行环境、历史快照或原数据；这些路径的可复现条件见前两版运行说明。新自编材料与聚合指标均可随仓库分发。

冻结第二版源码另存于`benchmarks/baselines/privacy_v2/`，便于在同一材料上复核。安装本地模型后，可重跑对照（会产生新的本地推理输出，不能覆盖本轮已冻结证据；新运行不保证逐次输出相同）：

```powershell
python -B -X utf8 scripts/compare_privacy_revisions_local.py --corpus examples/privacy_eval_v3_final --baseline-archive benchmarks/baselines/privacy_v2 --baseline-manifest benchmarks/baselines/privacy_v2/manifest.json --detector-config configs/local_privacy_detector.json --output results/reproduced_privacy_comparison
```

## 发布范围及研究边界

GitHub更新包含源代码、离线测试、自编合成数据、便携安装脚本、公开演示、汇总指标和说明。原始数据、模型权重、个人附件、完整本地报告、恢复映射及API凭证不随此次更新上传。发布前检查实际暂存blob，避免只检查工作区而遗漏暂存中的敏感内容。

完整结果仍应区分检测准确率、最终遮蔽、处理阻断、合法回答质量和费用。局部边界改进、单次合成实验或通过工程测试不构成全面隐私保护或论文创新证明。本轮没有新调用云端模型，没有新的下游大模型问答正确率结论。
