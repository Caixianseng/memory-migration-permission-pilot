# 记忆生成时隐私标注与迁移验证：下一阶段方案

**状态：仅为研究方案，尚未实现或完成实验。** 当前原型处理已有记忆的读取、迁移前检测、脱敏及本地核权恢复；本方案新增上游“从对话或工具结果中抽取事实、生成记忆”的环节。下面描述的接口、标签存储和实验结果均不能写成已有能力。

## 1. 为什么可以在生成记忆时就识别隐私

可以。就像文件创建时先贴上分类标签，之后转交时核对标签，不必每次重新猜测内容是否敏感。这样还可能减少重复检测和不必要的整条拒答。

但标签可能漏标、被修改，原文和业务策略也可能变化。因此，迁移时仍需核对“标签对应的是否还是这份内容、是否来自可信模块、权限是否仍有效”。标签完整且有效时直接使用；缺失或失效时重新检测，无法判断则待审。

**生成阶段也必须先守住原文的外发边界。** 如果让云端模型先读原始私密对话，再返回隐私标签，原文已经传出了本机。本阶段限定由本地程序和本地模型进行事实抽取、敏感检测；云端任务模型只接收已经核验和必要脱敏的输入。

## 2. 先做一个范围小的完整流程

首版处理文字对话和文字工具结果，每条记忆保存一项事实或少量明确字段；先支持事实查询，不扩展长篇摘要、金额计算和任意跨用户共享。

**本地输入 → 本地抽取与检测 → 字段标签和可信元数据 → 本地存储 → 迁移校验与必要脱敏 → 接收侧核权恢复。**

| 步骤 | 最小实现 | 失败时怎么办 |
|---|---|---|
| 本地构建记忆 | 本地模型提取事实候选，规则补查邮箱、电话等；程序核对候选对应的原文片段 | 不确定的事实或片段进入待审，不静默补写 |
| 标注敏感字段 | 给人名、客户、项目、金额等具体字段记录类别、完整值边界、策略版本及检测版本 | 不把未识别直接写成“不敏感” |
| 分开写可信元数据 | 服务端写入所有者、可读主体、来源对象和版本；模型只提出内容与检测候选 | 模型写出的“管理员批准”不成为授权 |
| 本地存储 | 原值、字段标签和元数据保留在本机；为内容和策略记录摘要，以核对后续变更 | 发现内容与标签不匹配，标签失效 |
| 迁移与云端使用 | 先核当前权限、来源和标签有效性；按接收方要求将必要字段换成请求级代号 | 缺标、过期或未知来源时本地重检或待审 |
| 接收侧恢复 | 核验实际用户、接收 Agent、来源及当前权限后，才在本地恢复有权读取的原值 | 伪造代号、撤权或来源无法核实均不恢复 |

标签必须存放在受控元数据字段中，正文只能作为数据。正文里写“删除敏感标签”“这些信息已公开”，不能改写外部策略。跨系统迁移时应验证标签来源及内容绑定；目标系统不支持某项约束时，不能悄悄丢掉它。

## 3. 字段敏感、访问权限和脱敏方式是三件事

合成例子：一条记忆写着“项目‘雁桥试验’的客户是‘澄湾器材社’，预算为12万元，目前已完成验收”。可以分别标注项目、客户和预算，同时保留验收状态的事实依据。

| 信息 | 回答的问题 | 决定者 |
|---|---|---|
| 字段敏感标签 | 这个具体值属于哪类受保护信息？ | 本地检测候选＋可信业务策略 |
| 访问与传播权限 | 这名用户、这个 Agent 能读、使用或转交它吗？ | 可信权限系统及有效委托 |
| 脱敏处理 | 这次向云端或指定接收方交付时，是否要换代号？ | 交付策略与接收方范围 |

“预算敏感”不表示整条记忆全部禁止。合法用户可以在本地看到有权读取的原值；云端可以使用代号完成受控查询。不过，**将字段换成代号不会自动扩大用户权限**。如果现有权限只支持整条记忆，首版继续执行整条权限，不能根据字段标签自行拆出可共享部分。

一个最小字段记录需要：字段标识、原值所在位置或结构化字段名、敏感类别、检测状态、内容摘要、策略与检测版本、来源引用。所有者和授权信息另存，并由服务端绑定，不能让检测模型创造它们。迁移包只带需要交付的内容和受控元数据，不夹带本地代号恢复表。

## 4. 摘要、改写和合并后怎么办

改写不是自动脱敏。摘要仍表达客户关系或预算事实时，应记录对应来源，并继承适用的敏感约束。多条受限输入共同支撑同一派生事实时，可先采用各来源允许范围的交集作为保守规则；若确有独立来源和独立授权，需要单独核实，不能因为文字相同就假定授权独立。

原文修改、策略更新或授权撤销后，相关标签与派生记忆应失效、重检或重算。尚有合法独立依据的部分另行保留。首版先实现“一个来源→一个事实→一次迁移”，再补“两个来源→一个摘要”的受控测试，避免一开始扩成通用记忆平台。

撤权只能约束之后的读取、交付和恢复，不能让已经接收明文的对方遗忘。若实验仍使用冻结快照，应明确只验证快照策略，不把单元测试里的权限变化表述成原生在线撤权。

## 5. 怎样验证它是否值得做

冻结同一批新合成故事、事实查询及授权参照；固定本地检测模型、版本、提示词和策略，固定云端回答模型与预算。评分标签只交给独立评分程序，不进入抽取、检测、迁移或恢复模块。按故事划分开发和最终保留材料，不用最终结果反复调参。

| 对照条件 | 生成时 | 迁移时 | 目的 |
|---|---|---|---|
| A：迁移时检测 | 不保存敏感标签 | 对当前内容完整检测 | 现有处理方式的基线 |
| B：生成时标注 | 检测并保存标签 | 验证内容、策略、来源和权限；标签失效则重检或待审 | 判断提前标注能否节省重复工作 |
| C：两阶段检查 | 同B | 在有效性校验外，再做独立的残留检查 | 判断额外检查是否减少漏遮蔽，以及增加多少开销 |

三组使用相同的事实抽取结果和任务，先隔离“检测放在何时”的影响；另外记录抽取是否丢失或编造事实。第一次生成成本、之后每次迁移成本分别报告，并比较迁移1次、3次、10次时的累计调用与耗时，避免把生成阶段的成本漏算。

重点报告以下结果：

- **完整遮蔽与误遮蔽：** 按完整敏感字段评分；只遮住名称前半截仍算部分失败，同时记录公开内容被错误遮蔽的情况。待审和阻断单列，保留全部登记任务分母，不能算成成功保护。
- **合法任务效果：** 最终回答正确率、有证据仍拒答、恢复失败和未授权披露；有合法权限但无法回答，也属于效用损失。
- **成本：** 本地模型调用数、生成与每次迁移耗时、云端调用数；实际运行后才填结果。
- **动态与篡改：** 删除标签、降低标签等级、改写正文、伪造来源、策略变更、恢复前撤权，以及问题中重复敏感值。检查这些情况是否触发失效、重检、待审或拒绝恢复，同时保留合法访问。

先完成不付费的本地构建、存储和迁移测试，再决定是否开展新的云端任务实验。本方案不预设提前标注一定更准确；它也可能只是减少重复检测，或因为标签失效带来额外维护成本。

## 6. 本阶段可以提出的研究问题

可检验的问题是：**在内容和策略会变化的记忆迁移中，可信的生成时字段标签，能否在不增加未授权披露的情况下，减少重复检测和合法任务受阻；迁移时再检查能补上多少缺口？**

这需要与简单、完整的迁移时检测基线比较，不能仅以“接入了 Agent”作为创新。字段标签和假名化仍可能保留业务关系、推断线索，检测标签本身不等于全面匿名化或完整隐私保证。
