# 投稿验收：授权合同与独立参照审查

日期：2026-10-30。本次由未参与此前 `journal_methods` 实现的并行审计代理核对源码并运行最小离线探针；不等于独立人类评价或干净环境复现。未读取新的保留材料，未调用模型、未产生API费用，旧结果没有改写。

当前需要补齐的是**动态状态、实际交付和同案例联合评价之间的对应关系**。已有独立参照并非不存在：`policy_semantics_reference.py` 不导入生产核权，`reference_contract.py` 不调用执行主机。不过，两者验证的是预先登记的有限静态合同，不能直接推导真实客户端、动态撤权或端到端效果。

## 已核对的事实

| 位置 | 源码事实 | 对结论的限制 |
|---|---|---|
| `policy_semantics_reference.py` | 四值判决独立实现，严格类型，显式 `Deny > Indeterminate > Permit > NotApplicable` | 这是自定义有限语义，不是完整FACPL实现或普遍安全证明 |
| `reference_contract.py` | 从可信事实声明编译 read/handoff/restore；额外绑定对象、来源、受众、模型接收方、策略和时间 | 编译器和主机共同使用同一份可信声明，二者都不会独立判断声明本身是否来自真实管理员 |
| `controlled_host.py` | read复用当前授权；handoff真实调用broker；restore矩阵项只返回预检结果 | 矩阵中的restore=allow不能记成实际恢复、实际客户端成功或最终披露 |
| `run_paired_acceptance.py:162` | 为每条矩阵请求传入 `{'source_binding': True}` | 义务成功是执行器声明；另行原文核对不能自动视作这条义务已经接线 |
| `summarize.py:24` | `W_minus` 仅统计参考Permit且实际deny | 若实际unknown、超时、异常、未执行，合法交付仍可能损失，但不会进入这个数字 |
| `DeclaredReplay` | 返回原案例声明的敏感位置，不执行真实敏感识别 | 可检验标签传播和脱敏接线，不能估计真实检测漏检率 |
| `NativeAgentBroker` | 明确执行发送方读取、接收方读取、export、copy、当前版本、有效期和重放核验 | 强制点在受信主机；静态AGENTS.md不因此获得原生逐次ACL或即时撤权 |

来源与标注应分开：权限声明是受信输入；敏感真值只供评分；问题答案不能交给检测器。把同一错误声明复制到两份独立代码中，仍可能得到“双方一致”的错误结果。实现独立只排除共享核权函数造成的循环自证，不排除共同规格错误、共同数据错误和共同作者偏差。

## 本次实际复现的边界

探针仅使用旧开发故事 `dev-01` 的第一条事实，主机状态写入临时目录，退出后清除。固定请求为alice/harness对该事实handoff，来源、受众、模型接收方、策略均正确，`now=100`。

| 探针 | 静态参照 | 实际入口 | 判断 |
|---|---|---|---|
| 正常 | Permit / deliver=True | allow | 基准一致 |
| `host.unknown=True` | Permit / deliver=True | unknown / `current_authorization_unknown` | 参照缺少动态未知状态；旧W−不计入这次未交付 |
| `host.revoke(fact_id)` | Permit / deliver=True | deny / `grant_revoked` | 静态参照不表示撤权后的合同；实际入口正确阻断 |
| `source_id='unseen-source'` | NotApplicable | deny / `bound_context_mismatch` | 没有越权放行，但四值判决不逐项相同 |
| `user_id='charlie'` | NotApplicable | deny / `recipient_scope_mismatch` | 超出登记主体域，不能声称完整语义等价 |
| `operation='export'` | NotApplicable | deny / `unsupported_operation` | 三操作合同不覆盖任意业务工具 |
| `now=100.0` | Indeterminate | unknown / `invalid_time` | 均不交付，未发现这一探针的越权 |

这些结果不是“发现原生协议已泄漏”的证据。它们说明旧静态参照、当前执行状态和报表分类不能混用。新一轮若把撤权后实际deny与撤权前Permit比较，就会制造虚假的合法访问损失；若只统计deny，又会遗漏未知导致的合法未交付。

复现入口：从项目根目录使用Python导入上述三个旧实验模块，载入 `dev_cases.json` 的 `cases[0]`，用临时目录构造 `ControlledHost`，先比较 `evaluate(policy_for(case, fact), request, {'source_binding':True})` 与 `host.execute(request)`，再分别改变 `unknown` 与执行 `revoke`。这两个状态不应叠加到同一个正常探针中。旧报告与封存文件不需要重写。

## 新增的独立参考

本次新增 [reference.py](../experiments/submission_acceptance_20261030/reference.py)，接口为：

```python
judge(case, fact, request, state=None)
# -> {"decision": "Permit|Deny|Indeterminate|NotApplicable",
#     "deliver": bool, "reason": str}
```

该文件无任何import，不读取文件，不调用旧参照或生产函数。它直接用冻结合同判断声明和请求。`state=None` 明确表示基准初始态；显式state必须包含严格布尔的 `revoked` 和 `authority_unknown`，缺字段或字符串布尔不补成允许。已知不满足优先Deny；缺失、错误类型或未知状态记Indeterminate；完全不适用的操作记NotApplicable；只有全部条件满足才Permit。

参考判决器自身的18项手写测试已经实际通过：

```powershell
python -B -X utf8 -m unittest tests.test_submission_reference -v
```

测试中的期望值是手写合同例子，没有由生产函数生成。覆盖读不等于迁出/恢复、发送方读取和复制独立许可、精确用户-Agent配对、来源位置与来源ID篡改、半开有效期、严格布尔、未知、撤权和输入不变。18项测试支持判决器的这些行为，不证明方法创新，也不替代主机对照和实际交付检查。

## 建议冻结的有限合同

可信部分为本地主机、身份登记、原文来源登记、策略输入、时钟与状态记录、恢复映射；Qoder/Harness输出及记忆正文均不能创造授权。客户端及模型可能误答、输出伪造代号、请求不存在的事实。攻击者可改请求和待迁入数据，但不能改受信状态或主机代码；若要测试后者，须另立威胁模型。

源记忆限定为确切原文非空摘录，原文位置用半开区间 `[start,end)`；来源ID、原文文本和位置必须共同一致。标题只有独立获准后才能加入。自由摘要、自然语言依赖识别、多父委托、任意工具和客户端已见明文的“遗忘”不在本合同内。

请求至少绑定用户、执行Agent、事实ID、来源ID、操作、实际目标Agent、云模型接收方、策略版本与当前时刻。当前有限目标是alice/harness，源发送方是alice/qoder。其他主体的read可按确切pair核对，但不能借此取得handoff/restore。

| 操作 | 必须满足的合同条件 |
|---|---|
| read | 原文与请求绑定正确；当前user-Agent精确pair获准；未撤权；当前授权可判定 |
| handoff | read条件；接收者为alice/harness；发送方alice/qoder也获准读取；独立export与copy都严格True |
| restore | read条件；接收者为alice/harness；独立restore严格True；实际恢复还必须验证请求映射、完整记录集与新授权状态 |

检测成功、代号生成、目标加载、恢复映射可用都是执行义务，不应改写业务授权。已知deny可直接阻断；业务Permit遇到检测待审或加载失败，应保留Permit和独立处理失败状态。源端撤权后只限制新的主机操作，不能使已经接收明文的程序忘记内容。

## 性质—代码—证据对应

| 性质 | 现有强制点 | 新参考/联合验收应提供的证据 |
|---|---|---|
| 不能把两个合法pair扩成四个pair | `MemoryLabelAuthority.validate_access`、`CurrentMemoryAuthority` | 手写交叉pair反例；实际独立身份入口拒绝 |
| 读不自动变成迁出或恢复 | `NativeAgentBroker.__authorize`；显式restore门禁 | 三种操作各有允许和拒绝；恢复必须真实执行，不能只记预检 |
| 来源相同文字不能任意换位置 | 原文位置、内容哈希、签名；`verify_exact_record` | 独立期望位置；源ID/位置/内容逐一篡改后的拒绝 |
| 未知不能放行 | 当前授权绑定回执与状态检查 | 独立state=unknown；实际未知与业务deny分开；未知下实际交付计异常 |
| 撤权后新操作不交付 | 当前状态见证、broker.revoke、恢复再核权 | 同一故事撤权前后参考与执行一起变；原包重放和实际恢复同时记录 |
| 身份/会话间不能复用恢复能力 | `principal_binding`、完整记录集、request_id | 切换用户/Agent/request_id和伪造token失败；不持久化恢复映射 |
| 可用性和隐私同时核对 | 真实保护视图、原始回答和最终恢复输出 | 同案例敏感真值及任务答案仅评分时读取，分别统计载荷漏遮、过遮、正确率、未知、误拒和编造 |

真正的新增未授权交付应按“独立参考不允许交付，但实际取得了不应取得的内容”计数，不能只比较两个字符串判决。合法未交付应以独立Permit为分母，进一步分解业务误拒、未知、检测待审、超时、客户端失败、恢复失败和未执行。另保留旧W+/W−作为窄定义指标，不能让其替代总体交付损失。

下一轮需要独立冻结数据、代码和配置，并在同一案例中串起真实检测、受保护载荷、迁入验证、客户端输入、回答、当前再核权和恢复。普通逐片段隔离与已有选择性隔离必须拿到相同材料和权限；若字节等价，可共享该输入的调用，但不能算成两份独立模型样本。不同信息量条件只可用于机制诊断。

本次没有宣称完成第三人干净环境复现。独立代理检查与标准库离线重算可先排除接线和报表错误，最终仍应让未参与实现的人按固定制品重算。新合同与强基线差距是否构成方法论文贡献，须由后续同条件结果决定。
