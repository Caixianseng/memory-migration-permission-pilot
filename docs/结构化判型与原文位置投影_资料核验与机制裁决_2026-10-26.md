# 结构化判型与原文位置投影：资料核验与机制裁决

日期：2026-10-26。范围：3 组有界公开检索，随后核对作者论文、官方代码与本项目源码；没有启动模型、下载安装依赖或修改默认方法。外部材料仅作研究资料。此文不构成全面竞品排除，也不把工程简化称为论文创新。

## 1. 先固定已经观察到的事实

依据[上下文候选判型真实结果](上下文候选判型_真实结果与裁决_2026-10-26.md)及 `results/context_candidate_detection_20261026_v1` 的独立核验：

- 120 条包括 80 条开发材料与 40 条**已暴露回归**，不是新的独立验收；81 次本地生成 POST、168 次观测到的编码入口、360 行评分，747 项离线核对通过。
- 87 个已有类型候选全部被判为 `value`；26 个无类型候选中 14 个被判为 `value`、12 个为 `generic_role`。新增 14 个 value 含 2 TP 与 12 个标题 FP；一条旧 FP 被较长 FP 替代，净 FP 增量与新增 FP 数不能混用。
- 同期旧 40 条基线为 18 TP / 2 FP / 2 FN；all-candidates 为 20 TP / 8 FP / 0 FN，P=71.43%、R=100%。开发集也没有改善到原 P≥90%、R≥95% 门槛。
- 这些是输出分布与错误定位；**没有比较相同输入下不同字段顺序、删除旧类型提示或不同解码器，不能据此证明 schema bug、字段顺序效应或先验锚定的因果关系。**

`context_candidate_typing.py::_schema` 当前以互斥完整对象约束 value / nonvalue；`_material` 给模型有限 CID/EID、目标位置、局部窗口和 `proposed_category`。合法 JSON、合法 CID/EID、正确原文位置都不能证明该跨度是敏感值。当前窗口中已有标题提示仍出现 FP，也不能直接推断完整来源一定无效或一定有效。

## 3. 可借鉴的最小分类改造与可证伪对照

保持候选池、原文位置、策略与全部强保护相同，先研究一个问题：**要求模型同时生成类别、角色和证据字段，是否比直接选择合法判别结果更容易误认标题/泛称？**

可测试的改造是扁平闭集判别：模型只选择现有类别与现有角色能表达的合法联合结果，主机从固定映射恢复冗余字段，并按输入位置绑定 CID/EID。它没有新增语义标签或名称词表；也不允许主机按旧 NER 类别把所有 value 强行补成原类别。未知新类别或证据缺失仍待审。将若干字段改成一个字段是工程简化，不是创新主张。

最低限度的强基线与归因对照如下，不能只比较 all-candidates 的负结果：

| 对照 | 固定或改变的因素 | 回答的问题 |
|---|---|---|
| 同期规则＋同一 NER 原基线、seeded-only、当前 all-candidates | 同一候选与评分参考，保留原始结果 | 新方法是否真正优于已有强检测，而非仅扩大遮盖？ |
| 当前多字段输出 vs 扁平合法联合结果 | 候选、策略、窗口、模型、预算相同 | 多字段输出条件是否影响语义正确？格式失败单列。 |
| 等价完整 schema 的字段/分支顺序对照 | 只变顺序，保留相同合法语言及解析；记录实际生成键顺序 | 是否存在可复现顺序效应？声明顺序不一定就是解码顺序。 |
| 相同候选带旧类别 vs 不带旧类别 | 位置、原文、类别定义相同；不引入错类型到生产 | 能否证伪“完全依赖旧类型提示”的假设？需分 typed / untyped 评分。 |
| 同一判别器局部窗口 vs 完整当前来源 | 标记同一目标位置；只增加真实来源上下文 | 是否是语境截断问题？完整来源超预算不得截断后伪称 full-source。 |
| GPT-NER / ProgGen 式候选复核 | 完整候选、有效负例和类别说明，独立开发示例 | 简单既有自验证能否解决同类错误？示例只能来自开发部分。 |
| GLiClass 或训练好的受控跨度判别器 | 同一目标、策略及冻结标签；报告实际训练材料与阈值来源 | 非自回归判别是否更稳？不能把额外训练资源隐藏起来。 |

所有对照都要报告实体/敏感片段 TP/FP/FN、标题与泛称分层、待审率、精确边界与实际 mask 覆盖、物理请求数/编码数/令牌数及耗时。单候选调用通常增加调用数量，不预设比批量更便宜。模型判成 uncertain、格式失败和超限不能从分母消失。强规则、显式策略与认证的生成标签继续强制保留；局部语义分类器不能降低它们。

这批 120 条只适合机制开发与回归；新的验收材料必须在方法、提示与阈值冻结后独立保留。检测改善还须另做下游合法问题对照，不能从召回率推导拒答减少。

## 4. 关系卡应在什么时刻构建

[问题角色负结果](问题角色解析_真实负结果与机制裁决_2026-10-26.md)中的 consignee 错例，模型已经选对查询角色。失败发生在另一处：query 中的泛称 `organization` 被判敏感，并按现有同步传播机制遮盖记忆里的相同词；随后“最近角色前缀＋下一个代号”将这个泛称代号选为值。原生权限及恢复检查通过不代表角色和值的语义关系正确。

**在授权之后、问题同步替换之前，本地构建原文关系跨度，再投影到实际本次 PVT，原则上合法且针对这一数据流问题。** 其安全可行性有以下条件，仍需实现和测试，不能直接算已修复：

1. `prepare_labeled_transfer` 已对每条实际记录做当前用户、执行 Agent、来源与生命周期核权。关系提取只见这批授权记忆，不见未授权记录、评测答案或 query 推断的事实。不能把“提前构建”理解为提前越过核权。
2. 用现有冻结角色表达记录 `source_id`、原文哈希、角色证据跨度、值跨度及必要支持跨度；不靠字符串出现相同就推断角色，也不把 CUSTOMER 类型当成 buyer / consignee 等业务关系。
3. 继续运行同一检测、query＋memory 同步传播、重叠合并与出站检查。只在可信主机内部使用**实际替换区间**，将原文值跨度映射到本请求生成的代号和脱敏后的别名 source。重复值按发生位置核对，不按“第几个同名字符串”猜测。
4. 若原文值恰为一个实际替换区间，可投影为一个完整 PVT。若关系和值被合并进同一个更大区间，不能将整个 PVT 当作那个值恢复；若值被部分替换、对应多个代号或存在歧义，首版应拒绝该卡/待审。非敏感 literal 也必须保持原有精确来源支持与边界检查。
5. 卡绑定当前 actor / agent / request、完整策略哈希、记录授权范围、原文与脱敏载荷哈希；过期卡不可迁入新请求继续用。卡是派生证据，不是授权。原文卡和恢复映射留在本机；角色、关系本身若受限，同样不能随卡泄露给云端。
6. query 只能选择要问哪个关系，不能向卡中插入或改写事实。没有明确来源、关系冲突或否定/历史范围不清时不能因有匹配值就回答。选择后仍调用原有 `restore_labeled_answer` 再核当前权限；不放宽多来源的当前保守共同依赖，也不冒充已解决独立授权路径。

源码依据：`memory_labels.py::prepare_labeled_transfer` / `restore_labeled_answer`；`privacy.py::prepare_private_payload` / `RestorationMap` / `restore_answer`；`role_query.py::project_role_cards` / `build_role_evidence` / `resolve_role_answer`。

当前 `prepare_private_payload` 在内部计算最终合并区间与 PVT，但只返回脱敏 payload、不可序列化的私有恢复 capability 和汇总 metadata。`RestorationMap` 的 `_sensitive_spans`、`_entries` 不应直接开放给模型或角色模块。原文跨度投影需要可信准备层新增**只返该卡投影结果的受限本地接口/回执**；直接让角色选择器读取完整恢复 map，违反当前封装。现有 `project_role_cards` 只接受已经授权的脱敏记忆，也不是改传原文就完成的同一合同。

## 5. 关系投影的完整强基线与最低判断

先冻结检测、载荷与角色集合，分开比较以下因素：

- 原有自由回答＋完整脱敏来源，使用同一预声明序列化规则；保留历史 strict 结果，不重写历史成绩。
- 当前“query 同步传播后解析脱敏记忆卡”＋原有 Q0 / Q1 选择器。
- 新“授权原文位置卡→实际 PVT 投影”＋**相同** Q0 / Q1 选择器，隔离卡投影收益。
- 新投影卡＋看到完整脱敏来源的受控角色/证据选择，与 query-only 角色分类比较；各使用原有有限角色，输出仍经主机检查，不能让 query 成为事实来源。
- 普通结构化记忆/显式字段抽取＋相同权限、缓存和恢复检查，作为完整系统强基线。不能拿缺权限控制的普通图谱或缺格式校验的自由回答充当唯一对手。

可证伪的局部假设是：在存在 query 触发泛称遮盖、重复同型实体等条件时，**原文位置投影能降低卡的角色—值错配，而不减少同一强制遮盖或绕过核权**。若相同选择器下卡错配未降，或者只靠新增角色词表、移除遮盖、查询内容补事实、放松恢复才变好，就否定这一机制主张。即使该受控假设成立，也首先是本项目数据流修复证据；尚不足以成为相对既有跨度对齐、结构化抽取与授权问答的新论文算法。

本轮结论：优先检验明确的数据流差异和分类接口条件；同时保留自由回答完整来源、既有候选自验证、受控非生成判别器等强基线。未进行新推理，未证明检测达标、合法拒答降低或论文创新成立。
