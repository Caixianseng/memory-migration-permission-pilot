# 原生向量时序假设：只读证据备忘

日期：2026-10-26。仅分析已有工件和固定源码；未启动后端、模型或新诊断。后续已转入用户指定的本地 Agent Harness 实验，本假设暂不执行。

## 当前判断

现有证据不支持直接认定“刚写完所以第一次向量读太快”。更宽泛的时序敏感故障尚不能排除，但固定等待不是已验证修复。

- 原 v3 最后一次 `add_residents` RPC 返回后，首个完整 snapshot 在 0.025 ms 后开始，三主体向量查询均成功。
- 首次 null 是第二个 snapshot 的 assistant 查询 #71；该 RPC 位于最后写入后的 400.243—771.298 ms。第三个 snapshot 的 assistant #98 也 null，位于 793.121—1172.465 ms。
- outsider 集合没有删除，前三次向量读成功，随后 #136/#163 才出现 null。它不能支持“仅首读未就绪”的简单解释。
- 原 HTTP recorder 没有每次 HTTP 的起止时间，上述只能给 RPC 区间，不能补写精确 query-to-upsert 间隔。

## 同序成功不能隔离时序因果

trace-only 保持原运行顺序和主事实，不能当作相同向量输入的严格配对：三个 resident 文本每次都含新的 `secrets.token_hex(12)`，原 v3 与 trace-only 的三条 resident 内容 SHA-256 全部不同。集合/原生身份也重新创建。query 与主 fact 相同、次数相同，不消除这些差异。

两次 RPC 的总体时间亦接近：最后写后第二 snapshot，v3 为 400.243—771.298 ms，trace-only 为 410.930—800.205 ms。仅这些区间无法证明 trace 增加了足以修复故障的等待。

## 固定源码边界

已核对 v3 计划中的 Open WebUI `routers/memories.py` 和 `retrieval/vector/dbs/chroma.py` 摘要仍与本机一致：

- `/memories/add` 在返回前 `await` embedding、向量 upsert 与事件发布，不是路由显式 fire-and-forget 写入。
- 当前 async vector facade `await asyncio.to_thread(...)`；当前 Chroma Python API 对 `bindings.upsert/query` 使用同步返回。这里不能据此证明 Rust 内部不存在后台索引活动。
- Chroma adapter 的 `search()` 将任意 Exception 吞掉并返回 None，路由继续返回结果，于是可出现 HTTP 200 + JSON null。原运行未取得实际异常，仍不能区分索引异常、格式转换或其他来源。

定向查询只使用两条官方站点/GitHub检索，没有找到能直接套用到本机嵌入式 1.5.9 的写后读等待阈值；[官方版本发布页](https://github.com/chroma-core/chroma/releases/tag/1.5.9) 仅用于版本核对，不作为本次故障根因或一致性保证。

## 若日后验证：单次最多 12 查询的条件设计

当前不建议将其作为下一项自动运行。若另行开展，应先冻结旧 v3 的确切文本、路径、向量模型、query、k=100 和阈值 0，禁止每臂重新随机生成 resident 文本。采用匹配但独立的新原生用户/集合，避免“立即读后再延迟读”的缓存和读次数混杂；预声明立即调度与固定 500 ms 延迟两臂，六对最多十二次真实目标查询，臂顺序平衡。不得额外 count/get、重索引或重试。

两臂都使用同一临时诊断 search 包装，保留固定 search 正常主体，只将原吞异常处改成保存脱敏异常元数据并重新抛出；生产默认不改。记录实际 upsert 返回及 search 起止单调时钟、查询向量摘要、原始 HTTP 类型及预期合法 ID；计入全部 embedding 调用，生成模型调用为零。

出现首个异常/null 时，仅在无安全事件前提下完成其匹配臂一次并停止新配对；出现越权内容、身份/资产不符或外联即立即停止。十二次全过即以“未复现”结束，不扩量刷绿。立即失败/延迟成功最多支持该固定条件下的关联，不能直接证明后台索引是根因；两臂失败或反向结果反驳“该等待足以解决”的说法。

证据：`results/native_exact_fact_bridge_20261025_v3/report.json`、`results/native_exact_fact_trace_only_20261025_v1/standard_run/report.json`；既有诊断说明见 [三步有界诊断](原生向量null_三步有界诊断结果_2026-10-25.md)。
