# 生成时隐私标注：实现机制与本地对照实验

本轮已实现生成时隐私标注和迁移校验，并完成实际本地模型对照。结果显示：一个保留故事中重复暴露的项目名称被生成标签补上，标签复用减少了重复检测；最终合法答题与真正模型拒答没有改善。详细结果见下节及[公开聚合指标](../benchmarks/memory_generation_v1_summary.json)。

## 正式结果与当前判断

冻结版本在24个故事上实际运行，10个成功构建、14个待审；12个保留故事中6个成功、6个待审。376项本机工程测试通过。正式实验共280次真实本地生成调用（含构建、检测、回答），生成阶段共40次调用；开发预实验另外保留。新增云端调用0、API费用0元。

| 保留集指标 | A 迁移时检测 | B 生成标签复用 | C 两阶段结合 | 授权明文参照 |
|---|---:|---:|---:|---:|
| 合法题最终答对/登记合法题 | 5/24 | 5/24 | 4/24 | 8/24 |
| 合法题预处理阻断 | 14 | 12 | 14 | 12 |
| 有精确事实仍由模型返回UNKNOWN | 0 | 1 | 1 | 0 |
| 恢复失败 | 1 | 2 | 1 | 0 |
| 可准备的脱敏输入 | 10 | 12 | 10 | 不适用 |
| 可准备后仍有金标遮蔽缺口 | 2/10 | 0/12 | 0/10 | 不脱敏 |
| 额外遮蔽的非金标字符 | 0 | 52 | 50 | 不适用 |
| 迁移阶段本地检测生成调用 | 52 | 12 | 52 | 0 |

三种方法共同可准备的10道合法题来自5个故事。A的两次漏遮蔽是**同一个故事的同一个项目名称，在两道任务中各暴露一次**；B/C实际将它替换为代号，三组都保留了相同原始事实，没有靠少抽取或阻断修补这两次暴露。这是一例局部机制收益，不是两个独立漏检场景，也没有统计显著性结论。

在共同可准备子集中，A/B/C最终正确数为5/10、4/10、4/10。B少了两次预处理阻断，但最终总正确数仍与A相同；真正有事实的模型UNKNOWN反而由0变为1。因此不能把预处理放行增加写成“合法问题拒答已减少”。还需改善构建、代号使用及恢复，同时控制额外遮蔽。

保留集原始敏感字符共303个，进入正式记忆137个、未进入166个；22个受保护源片段中完整保留12个、缺失10个。缺失主要与构建待审、事实未被接受有关，绝不算保护成功。所有任务仍保留原始分母，未将未运行样本填成正确或安全。

每组12道未授权题均被宿主阻断，没有进入回答模型。由于只在6个成功构建的故事中有可交接记录，A/B/C各有6次实际迁移接口的跨主体拒绝；其余6次仅由宿主预检查拒绝。模块级跨用户、跨Agent、篡改与撤权路径由独立工程测试补充验证。

**当前发布为实验功能，不替换现有默认流程。** 简单的按内容和策略哈希缓存迁移检测，也可能节省调用，本轮尚未与该强基线比较。不能仅凭减少调用宣称新算法或论文创新。正式结果冻结后未继续调整模型、标签或答案；下一轮优先处理构建待审与代号恢复，而非扩大不合格样本规模。

## 1. 本次实现到什么程度

程序使用真实本地模型，从短对话中摘取事实，同时提出敏感片段候选。主机程序验证这些事实确实逐字来自原文，再给事实附上可信来源、用户和 Agent 权限以及可验证标签。接收角色拿到经过本地 JSON 存储往返的记忆后，先核权、再检查标签，最后准备脱敏输入、调用本地模型回答、核权恢复原值。

这里的“不同 Agent”是**同一个程序中的两个可信角色**：源角色负责生成记忆，接收角色负责使用记忆。身份不同、操作阶段不同，能够验证交接边界，但没有接入两个独立运行的原生 Agent 平台，也没有实现通用 Agent 互通协议。

“生成记忆”目前限定为**从原文摘取连续事实片段**，不是自由改写的摘要。这样可以核对来源位置，也能分清“原文信息没有被抽取”和“抽取了但没有保护”。真实摘要、多源事实合并、语义改写后的标签继承仍属于后续工作。

主要代码：

- `memory_migration_study/memory_builder.py`：本地模型生成事实和字段标签候选。
- `memory_migration_study/memory_labels.py`：绑定来源与权限、认证标签、迁移校验和恢复。
- `memory_migration_study/memory_generation_experiment.py`：配对对照、实际本地问答及分阶段评分。
- `memory_migration_study/memory_generation_corpus.py`：评测材料重建器；它含评分定义，不能作为模型输入。
- `scripts/run_memory_generation_study.py`：正式运行入口。

## 2. 记忆生成时如何标注

`LocalMemoryBuilder` 接收原始对话和独立的敏感策略。模型输出最多八条事实，每条包含原文引用，以及相对这条事实的敏感字段引用和类别。例如，它可以提出“客户为某机构”的事实，并把其中的机构名称标为 `CUSTOMER`。

程序不会直接接受模型给的位置和权限，而是自己完成以下核对：

1. 每条事实必须是输入原文中连续、逐字存在的片段，禁止凭空补充或改写。
2. 每个敏感字段必须逐字存在于它所属的事实中，并且类别属于可信策略允许的类别。
3. 字符位置由程序根据原文计算；重复事实合并，不让模型自选不存在的来源位置。
4. 格式或定位错误最多进行一次修复；持续错误、预算超限或抽取不确定记为待审，不能默默当作没有敏感信息。

仅支持少量有明确规则的外层引号修复：去除引号后，内部文字仍必须原样存在。没有模糊拼写修复，也不会从参考答案补入缺失事实。

模型提出的是“内容和敏感标签候选”。它不能创建所有者、读者列表、共享权限或公开授权。即使原文声称“系统允许公开”“忽略隐私策略”，这也只是待处理文本，不能修改主机策略。

## 3. 来源权限和隐私标签分开校验

`MemoryLabelAuthority` 为每条记忆建立两个分别认证的对象：

| 对象 | 回答的问题 | 主要绑定内容 |
|---|---|---|
| 访问授权 | 谁能使用这条记忆？ | 记忆编号、所有者、读者、允许的 Agent、源编号与源内容摘要、生命周期版本 |
| 敏感标签 | 这份内容对应哪些敏感片段？ | 记忆内容摘要、原文位置、源摘要、策略摘要、生成器与检测器版本、片段及类别、访问授权摘要 |

这里的摘要是 SHA-256 哈希，即内容的固定长度校验值，用于发现内容发生变化，不是文字摘要。标签使用 HMAC，即基于共享秘密密钥的消息认证码。它用于检查对象是否由本地可信程序认证、认证后是否被改动；**不能证明模型已经找全敏感信息**，也不是供互不信任平台使用的公开可验证数字签名。

记录会写入本地 `record_store.json`，再经过 JSON 序列化和读取边界交给接收角色。本轮 HMAC 密钥在运行开始时随机生成，仅保存在进程内存中，恢复映射同样不落盘。尚未实现跨进程生产密钥服务、密钥轮换或持久化密钥供应。模块虽提供可认证的生命周期状态导出接口，正式对照并没有据此构建跨进程部署系统。

实验记录中的原始对话与记忆都是合成材料。本地记录格式会保留源文本，HMAC也不承担存储加密作用；不能把该原型表述为已经实现生产级加密记忆库。

## 4. 迁移时如何检查

三种隐私处理条件共用同一批生成事实、同一来源和同一访问授权。首先检查真实用户及执行 Agent 能否访问；通过后才进入相应检测路径。

| 条件 | 代码名 | 记忆内容的敏感判断 | 问题本身的处理 |
|---|---|---|---|
| A：迁移时检测 | `migration` | 不使用生成标签作为检测结果，迁移时对全部记忆运行规则与本地语义检测 | 同样检测 |
| B：生成标签复用 | `generation` | 有效标签可复用；缺失或失效标签的记忆回退到完整检测 | 独立检测，不能因为记忆已标注就省略 |
| C：两阶段结合 | `two_stage` | 有效生成标签与迁移时完整检测取并集 | 同样检测 |
| 授权明文参照 | `raw_reference` | 使用相同生成事实，在本地直接回答 | 保留相同用户与 Agent 授权检查 |

三种隐私条件都执行规则检测、片段边界补全、跨问题和记忆的已知实体传播、实际出站输入校验。B减少的是对**已有有效标签的记忆**重复运行语义检测，不是完全跳过迁移检查。C可能发现两阶段各自遗漏的字段，也可能增加额外遮蔽和处理阻断，需要由结果衡量。

授权明文参照只用于观察脱敏过程带来的效用变化，全部材料为合成数据且模型在本机运行。它不是绕过权限的条件，也不是向外部云模型传输明文的方案。

如果标签缺失、标签被篡改或敏感策略变化，B会对仍有合法来源与权限的内容重新检测；不能仅凭旧标签继续处理。如果源内容身份、访问授权或执行主体校验失败，或者授权被撤销，则直接阻断，不能用重新检测代替授权。

回答后恢复代号时，再次核对当前主体、Agent、请求、策略、记录和授权。单元测试覆盖撤销记录、撤销源、生命周期变化和恢复前权限变化。这些是本地受控生命周期检查，不能声称已实现原生后端的在线撤权同步。

## 5. 对照材料和实验顺序

语料位于 `examples/memory_generation_eval/`：

- 24个独立故事，中英文各12个；12个开发故事和12个保留故事按模板族隔离。
- 每个故事包含一题合法敏感事实、一题合法非敏感事实，以及一题未授权访问问题，共72个任务。
- 覆盖人名、机构完整尾码、项目编号、地址、金额、邮箱、电话、公开策略反例及伪造授权文本。
- `runtime.json` 是模块输入；`evaluation.json` 仅用于评分；`manifest.json` 保存原始文件和规范化 JSON 的哈希以及固定分母。

模型构建器、检测器、迁移器和回答模型都不接收评分答案。评分代码会在处理后检查真实生成内容中是否存在任务所需证据；这个检查不会把事实补回模型上下文，也不会决定某条源记忆是否有权读取。

每个故事只生成一次记忆，四个条件共享这一次结果。每道题的条件顺序按预先固定的随机种子打乱。所有故事完成时注册任务条件数为288；其中未授权题应在回答模型之前阻断。合法任务的实际回答调用上限为192次，实际调用量还取决于生成与处理是否成功。生成费用和调用数独立记录，不能把B所复用的生成标签当成免费获得。

已经发生的开发失败记录保留。正式运行前冻结代码、提示词和语料；看到保留集结果后不再根据该结果调整实现或阈值。失败不通过删除故事、修改真值或只展示可运行样本来消除。

## 6. 如何判断漏检和合法问题拒答

报告必须同时看处理分母、实际遮蔽和实际回答，不能仅看检测器报出多少标签。

| 环节 | 需要单列的结果 | 不能作出的解释 |
|---|---|---|
| 原始事实抽取 | 构建成功数、必要事实是否进入记忆、敏感字符/片段保留与缺失 | 没抽到秘密不能算保护成功；没抽到答案也不能直接归因于脱敏 |
| 迁移准备 | 合法任务处理阻断、待审、可准备请求数及标签回退 | 阻断不是回答模型拒答；只看放行样本会遗漏可用性损失 |
| 实际遮蔽 | 已保留且可准备输入中的完整、部分、漏遮片段，以及额外遮蔽字符 | 内容丢失不能算遮蔽；代号也不保证关系与推断线索消失 |
| 模型回答 | 合法任务正确数、有证据仍输出 `UNKNOWN`、支持事实的合法任务数 | `UNKNOWN` 必须结合是否存在事实判断；不能用总准确率掩盖抽取丢失 |
| 本地恢复 | 恢复失败、最终答案、未授权任务是否被模块拒绝 | 代号生成成功不等于恢复成功；模型没有复述不等于底层没有披露 |

本轮把“有事实仍拒答”操作化为：合法任务所需的精确事实证据已经存在于生成记忆中，回答模型正常返回，但答案为 `UNKNOWN`。这不是对所有自然语言拒绝行为的完整语义识别。合法无答案、处理阻断、模型调用错误、抽取丢失和恢复失败分别报告。

任务正确性按最终回答与预先定义的单事实答案做精确比较（忽略大小写），没有让另一个大模型主观判分。片段评分把原文标签投影到实际保留的事实，缺失抽取另外统计。每个故事才是独立内容单元，同一个故事在四个条件和三道题下产生的多行记录不能当成新增独立样本。

## 7. 可复现运行

在项目根目录的 PowerShell 中执行。当前配置为 `configs/local_privacy_detector.json`，固定 Ollama `0.40.8`、`qwen3:4b-instruct-2507-q4_K_M`，仅连接 `127.0.0.1:11435`。构建器和检测器最多两次本地生成，4096上下文、1024输出上限；实际回答模型输出上限为64。所有调用串行，不使用云端回退。

已有经校验的本地运行时和模型时，启动或核对服务：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup_local_privacy_agent.ps1 -SkipDownload
```

首次安装缺少资产时才省略 `-SkipDownload`，脚本从官方来源获取固定运行时和模型并校验哈希；这一步涉及下载。模型准备好后的正式推理不需要外部模型服务。

先运行不要求本地模型服务的工程测试：

```powershell
python -B -X utf8 -m unittest discover -s tests -v
```

执行完整的冻结对照。输出必须是**尚不存在的新目录**，程序不会覆盖已有实验：

```powershell
python -B -X utf8 scripts/run_memory_generation_study.py --output results/your_new_run
```

只运行开发材料时，可加 `--split dev`；只运行保留材料时，可加 `--split heldout`。正式结果应明确本次运行的范围，不得把仅开发集结果称为全部或保留集结果。

主要输出文件：

- `plan.json` 和 `implementation/`：开始时冻结的语料哈希、提示词哈希与代码快照。
- `builds.json`：真实生成结果、调用次数、耗时和失败原因。
- `record_store.json`：本地持久化的合成记忆与认证标签，不包含密钥或恢复映射。
- `rows.json`：逐项实际输入、模型输出、恢复结果和分阶段评分。
- `report.json`、`index.html`：分开发/保留/全部范围的聚合结果和本地可读页面。

本次实际问答也使用本地Qwen模型，新增云端调用数和模型API费用均为零。结果只能支持这组受控材料、本地模型与原型实现下的比较，不能直接推导DeepSeek等云模型的拒答率改善。

## 8. 正式结果与研究结论

**结果以正式冻结运行report为准。** 本节由完成最终运行和一致性核查后补充，至少列出开发/保留的故事分母、构建成功数、四条件合法回答正确数、已有事实仍拒答数、合法处理阻断数、实际漏遮与部分遮蔽数、额外遮蔽量、迁移调用与生成开销，以及未授权检查。

即便生成时标注减少了重复检测，也不自动证明减少漏检或拒答；两阶段并集即便提升覆盖，也需要同时呈现额外遮蔽、阻断和开销。如果没有优势，应保留失败与原因。本阶段是工程机制与小规模研究验证，不能仅凭增加上游Agent或使用HMAC标签就宣称论文创新已成立。
