## 2. 可复用的原生接口与执行位置

下表来自旧固定 1.6.5 探针的实际调用代码；新安装后仍要对照该 wheel 路由、DTO 和认证实现复核，不能直接当成本机新实测。

| 操作 | 旧探针的确切入口 | 权限执行/边界 |
|---|---|---|
| 创建普通用户、独立登录 | `POST /api/v1/auth/register`；`POST /api/v1/auth/login`，登录为表单 username/password | Cognee 原生认证；每次请求清 Cookie，凭据只留进程内 |
| 身份核验 | `GET /api/v1/users/me` | 对应 JWT 或 `X-Api-Key`；普通用户必须非 superuser |
| 建容器 | `POST /api/v1/datasets`，JSON `{name}` | 原生 dataset owner 与权限范围 |
| 精确写入新事实 | `POST /api/v1/add`，表单 raw_data、datasetName、datasetId、run_in_background=false | 旧 resident 正对照已使用的原生写入口；新 adapter 要验证实际新增 ID 和完整原文 |
| 厂商迁移导入 | `cognee.remember(Mem0Source(..., mode="preserve"), dataset_name=..., user=真实User, run_in_background=False, index_vectors=False)` | 可信迁移进程经官方 SDK，以已注册目标 User 写入；不是登录后的 HTTP 自动权限翻译 |
| 目录/数据列表 | `GET /api/v1/datasets`；`GET /api/v1/datasets/{dataset_id}/data` | Cognee 原生 dataset ACL |
| 原文读取 | `GET /api/v1/datasets/{dataset_id}/data/{data_id}/raw` | Cognee 原生读权限；先建立 owner 完整原文阳性，再解释他人的403/404 |
| 授 read/share | `POST /api/v1/permissions/datasets/{recipient_id}?permission_name=read或share`，JSON `[dataset_id]` | 调用者原生管理权限、对象范围与接收者身份 |
| 撤 read/share | 同一路径 `DELETE`，相同参数与 JSON | 状态码是动作回执，必须核后置读取/再授予，不能把200直接算撤权生效 |
| 创建子 Agent | `POST /api/v1/agents/create?name=...` | 由父普通用户调用；返回 `agentId`、`agentApiKey`，明确拒绝冲突 DTO 字段 |
| 子 Agent 认证 | `X-Api-Key`；再 `GET /api/v1/users/me` | 核子身份 ID、parent_user_id、非 superuser；不是把普通JWT换个标签 |
| 删除单条/容器 | `DELETE /api/v1/datasets/{dataset_id}/data/{data_id}`；`DELETE /api/v1/datasets/{dataset_id}` | 对象与容器退休的权限、范围和副作用不同，不能互相替代 |

`migration_delegation_probe.cleanup_plan` 是普通参考：只清理本次已知对象、当前源策略已全部撤掉的父/子 read/share；同容器混合合法与失效记录时明确拒绝，不能假称已经解决任意粒度重分区。它没有发现未知子身份，也没有一般多父独立授权算法。

Cognee 自身租户成员移除与本轮 dataset read/share 移除不是同一操作。旧文档已区分租户范围连带清理及 dataset 授权；不能因 dataset 子权限残留就声称产品不存在级联撤权。

## 3. 原文、词法和语义读取必须分开

旧 `preserve` 导入未创建向量索引。旧 `CHUNKS_LEXICAL` 实验另外调用 `prepare_whole_record_lexical_index`，将每个 1—16384 字符的完整原文做成一个 DocumentChunk，经原生 `run_custom_pipeline`、classify_documents、add_data_points 写入 graph；各 Task 明示 `needs_llm=False`，`graph_only=True`。

检索为 `POST /api/v1/search`，固定 `search_type="CHUNKS_LEXICAL"`、top_k=15，可指定 dataset_ids，并分别测 only_context=false/true。它是研究索引准备配方，使用厂商存储/权限，但不是默认 preserve 已提供的检索，也不是语义或向量质量。不能与 WebUI 本地向量结果直接混为同一指标。

新第一轮应先资格化两产品共同的完整原文读取；词法、上下文和向量作为明确不同入口分层报告，未实现的入口为未测。

## 4. 最小新增 worker 方案

新增独立进程的 Cognee target worker，复用旧代码的配置字段、真实身份流程、原生路由和严格后置检查；不直接执行旧 `public_acl_feasibility.py` 整套固定 t003/旧 source-dir 实验。外层使用当前 `WorkerRPC` 与冻结源码、资产哈希及新状态目录边界。

现已新增 `scripts/native_cognee_policy_worker.py`。固定wheel源码显示，HTTP add 没有 `index_vectors` 参数；其实际两个低层 ingestion Task 均为 `needs_llm=False`。新worker不虚构该参数，额外监测主线程、新线程及ASGI portal中的推理入口，触发则计数并阻断，不返回伪结果。它还拒绝会被路由 `.strip()` 改写的外层空白和文件/URL形态输入。

真实read/share资格v1在13个HTTP后停止：创建dataset和空列表成功，`POST /api/v1/add` 的相同精确 `raw_data="SYNTHETIC_VALUE_A71"` 返回415，read/share阶段未执行。这是v1 worker的 `ACCEPT_LOCAL_FILE_PATH=false` 同时阻止Cognee内部暂存文件读取，不能当原生权限拒绝或源真值错误；旧结果、原POST及v1源码归档均保留。

v2只修该配置因素，原 `raw_data` 运输、文本、外部网络限制和driver保持不变：使用官方 `ACCEPT_LOCAL_FILE_PATH=true` 加 `COGNEE_ALLOWED_LOCAL_FILE_ROOTS=本次新state`，所有官方storage根必须在state内。初始化还通过真实官方helper做不创建文件的内外路径反例，并核实际save/loader设置。13项worker检查加8项driver假测试通过；其中已校验wheel的官方路径函数保持原AST逻辑，仅配置accessor为假夹具，确认state内允许、state外拒绝。主任务随后在新state完成37次HTTP的[两周期能力资格](Cognee原生读取分享撤权_两周期能力资格_2026-10-26.md)，普通read/share/revoke路径成立，独立子授权组合另作观察；原25项源策略投影矩阵仍未运行。

新CLI接受显式 `--state`、`--wheel`、`--legacy-project`、可选 `--openssl-dll-dir` 和 `--http-cap`（最高200）。第一轮仅 `init` 身份资格可以将HTTP上限收紧到16；三个用户注册、登录、users/me加匿名检查预计固定10个HTTP。它不会自动执行权限矩阵。`close` 回执保留异常类别、自有固定错误码、合法缺失模块名，不保存原异常消息或凭据。

建议命令集合为：`init`、`add_exact_fact`、`create_child`、`grant_dataset_permission`、`revoke_dataset_permission`、`read_raw`、`delete_exact_object`、`close`。所有 dataset/data/principal ID 来自本次已核验响应和可信主机映射，禁止客户端随意传旧 ID。首轮不开放 shell、任意 HTTP 路径、cognify 或自由代码。

**优先用同一已核权 `record.text` 经两产品原生 add 写入。** 这样两组均为可信复制器到原生接口，区别只在后端表达和执行。不能导入 `record.source.text` 全文，否则可能把授权事实范围外的 source-only canary 一同迁入。外部主体/源策略校验是共同可信 gate；它不应被称作两产品原生ACL。

若改用 Mem0Source preserve，应显式记录事实筛选、必要的副本 ID namespace 和源到目标血缘。这是自定义投影，不是未经改变的真实 Mem0 get_all 导出，也不证明源认证。旧未 namespace 的相同 ID 在多份复制中的身份行为不能未经核对就复用。

首轮建议使用同一源 envelope、用户、合法/越权关系与精确文本，两产品各新进程/库、初始和变化后同样的判定。可先限定最多3个来源事实、3个普通用户、1个预先创建子身份、每用户1个无关 resident 正对照；最多6个容器、7个写入对象、200次HTTP，达到上限即保存不完整。以上为待冻结的建议上限，不是已执行成绩或自动扩容授权。

先用 owner 完整读取建立目标ID与原文对应，再建立 assistant、outsider 各自合法 resident 读取。之后才做跨身份、跨容器/data-ID 读取、read/share变化、子凭据与再授权。撤权前必须完成子凭据及授权，撤权后新建授权不能冒充独立保留。

## 5. 与 WebUI 使用相同语义，不能硬凑同名接口

| 共同语义 | Cognee 1.6.5 旧代码支持位置 | 当前 WebUI 比较边界 |
|---|---|---|
| 当前用户对精确事实的读取 | 原生 dataset ACL＋raw 路由 | 个人记忆空间＋原生用户路由；副本映射显式记录 |
| 给另一既有主体授同对象 read | dataset permission read | 个人记忆路由未提供同义对象ACL授予；复制是另一操作，需单列 |
| read 与 share 分离 | dataset permission 两类位 | 不能把“无同义share API”算成一次成功的403防护 |
| 独立 Agent 身份/委托 | 原生 child＋X-Api-Key，并核parent关系 | 当前只有固定应用 worker 身份绑定；另建普通用户不等于原生子Agent |
| 撤迁入对象，不损其他合法/本地对象 | 真实 owner 清授权、删除已知数据或容器，各自核后置条件 | 真实owner删除、管理员/重置等路径各自计代价，不能假定管理员语义相同 |
| 源控制器可独立操作，且不轮换接收人凭据 | 取决于副本owner和原生授权；旧正确ACL分组/控制器拥有副本已有成功强基线 | 不得偷偷用接收人凭据执行后仍称源控制器自主撤权 |

现有源的 read/export/copy 字段没有自动给出 share 或转授权真值。若新矩阵评价这些能力，应先明确冻结源允许的操作、受众、父/子作用域及控制者；缺字段为未知/不可表达，不能事后按目标结果补源策略。

没有原生表达的约束可采用“拒绝不兼容迁入”“明示外部gate”“明确授权的副本投影”等独立条件。不能把应用网关控制写成产品原生ACL，也不能把不同信任/凭据保管条件混在一个通过率内。

## 6. 新环境启动前的资格检查

1. 固定 wheel/源码/实际依赖清单与新 Python；不得借用 WebUI site-packages 造成隐式依赖变化。
2. 在导入 Cognee 前设置独立 data/system/cache/log/repos/db 根、SQLite、ladybug in-process、2线程、64MiB buffer、LanceDB、禁止遥测/连接测试。状态路径为新建边界；Windows优先新ASCII临时根，报告写工作区。
3. 复用当前完整环境清理与严格 NetworkGuard。旧 configure 只清部分密钥，网络审计仅阻止非回环 socket.connect，仍允许任意回环；不能原样作为当前更严格隔离保证。
4. auth/register/login、agents/create 及密码操作的请求秘密和响应秘密不落盘、不哈希。其余响应也先检查未混入进程内凭据，再保留原字节、哈希、状态与身份存在性；清Cookie与实际header存在性必须核验。
5. 检查原生路由/DTO/parent/owner语义与固定版本一致，先有合法正对照。401为认证问题，500为执行错误；403/404还需确认已认证主体和对象存在性。拒绝正文含受限原文仍算披露。
6. 每次控制动作后复读受限事实、其他合法事实及 resident，记录旧凭据是否仍可用。200＋未应用正文、空200、索引未就绪不能算撤权成功。
7. 不请求生成模型或语义索引；仍需记录实际生成/嵌入调用与网络尝试，不能仅因代码没打算调用便填0。

资格不符时停在不完整/不可表达，不继续给失败改名。当前清单没有赋予新的产品安全、算法创新或端到端验收结论。
