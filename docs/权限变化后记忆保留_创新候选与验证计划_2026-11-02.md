# 权限变化后记忆保留的创新候选与验证计划

日期：2026-11-02。依据用户提供的《找创新点 完整手册》，按“事实卡→机制缺口→跨域模块→改动溯源→真实否证”整理。以下是研究候选，未实施的改动一律标为拟议，不将移植、改名或组合本身记为创新。

**优先问题：权限变化后，在不放宽硬授权的前提下，怎样用有限的记忆交付预算保留允许来源的重要事实及限定语。** 当前尚未证明普通配额、合法原文或已有记忆修复方法解决不了它，因此不宣称已找到可投稿的新方法。

## 事实与实验锚点

| 锚点 | 可核实内容 | 边界 |
|---|---|---|
| F1 | 可信主机区分读取、迁出、接收与派生依赖；`experiments/pre_delivery_revocation/driver.py:PreDeliveryRevocationDriver` | 当前串行可信主机合同，不是任意客户端原生执行通用权限协议 |
| D1 | 四个既有开发故事；来源与回答评价文件分离 | 已暴露问题、AI参照；不是独立人工金标 |
| E1 | 20次 Off 压缩诊断；合法原文7/8，基线3/8，语境1/6有答合法题 | 上游失败、UNKNOWN与政策拒答分开 |
| E2 | 12次 Max 固定记忆对照；原文8/8 | 同时改变思考与输出预算 |
| E3 | 23次来源构造对照；缓存有答合法6/6，全局3/4 | 共同有答故事仅一个，打平；潜在计算量不等 |
| E4 | 10次补充预算对照；三个配对故事全局5/6、缓存6/6 | 最大生成输出相等，实际调用量不等；第四故事目标未发送 |
| S0 | 现有确定性核权、实际输入 AND 血缘与首次交付前再次检查 | 所有新候选保留这些约束；模型分数不能减少真实依赖或授予权限 |

实验汇总见[真实模型报告](真实模型记忆对照与研究裁决_2026-11-02.md)；匿名请求计数见[公开复算包](../benchmarks/harness_diagnostics_metadata_20261102/README.md)。

## 五张机制缺口卡

| 缺口 | 证据与后果 | 简单反证 |
|---|---|---|
| G1 生成器把编辑过程与正文内容争用少量记忆位置，遗漏用户约束或关键限定语 | E1、E3、E4；合法目标缺信息，增加 UNKNOWN 或不完整答案 | 同预算的每源配额＋原句若已解决，不再主张新选择算法 |
| G2 多次来源生成增加潜在思考预算，容易把更多计算误认作来源算法收益 | E3；三次生成与一次生成的完成率不同 | 对齐总预算并计初建后若收益消失，否掉方法收益主张；这是实验设计问题 |
| G3 单向支持检查能接受不假的残缺摘要，却没有证明保留了必要内容 | E4 的用户请求被遗漏；这是由实测推导的待检验机制 | 先用独立源标注检验覆盖，普通抽取已足够则不增加检查器 |
| G4 黑盒混合生成看过撤销来源后，不能靠事后改写来源标签解除依赖 | F1、S0 的真实输入合同 | 普通依赖失效与合法重建已阻断旧M；没有新反例就不重复包装协议创新 |
| G5 客户端模型别名、登录链和会话存储不同，会让连接成功被误记成模型执行 | 新 CLI 认证失败及 E1–E4 的真实回执边界 | 以原生领取、实际回复及输入绑定验收；这是适配工程，不单独当算法贡献 |

优先研究 G1，G3作为候选验证器问题。G2先修公平性，G4/G5保持为必须通过的安全与工程要求。

## 可移植模块与近邻核查

下面的“核实”指论文、代码入口与代码许可可以定位，不表示本机已经复现指标或模型权重许可已经核完。仅选择一个子集选择库、一个核验器，避免堆叠。

| L锚点 | 源工作与代码 | 可借用机制 | 必须改动的接口 |
|---|---|---|---|
| L1 | Kaushal等，Submodlib，2022预印本：[论文](https://arxiv.org/abs/2202.10680)，[MIT代码](https://github.com/decile-team/submodlib) | 带权覆盖与预算子集选择；入口`SetCoverFunction` | 输入改为允许原句包、覆盖特征与实际token成本；求解器不宣称自研 |
| L2 | Schreiber等，apricot，JMLR2020：[论文](https://jmlr.org/papers/v21/19-467.html)，[MIT代码](https://github.com/jmschrei/apricot) | 代表性子集选择；入口`maxCoverage.py` | 是L1的工程替代，不是另一个创新；核对token成本约束支持 |
| L3 | Tang、Laban、Durrett，MiniCheck，EMNLP2024：[论文](https://aclanthology.org/2024.emnlp-main.499/)，[代码](https://github.com/Liyan06/MiniCheck) | 文档支持核验，`MiniCheck.score(docs,claims)` | 证据池只含当前允许来源；Apache-2.0代码与各权重许可分开 |
| L4 | Zha等，AlignScore，ACL2023：[论文](https://aclanthology.org/2023.acl-long.634/)，[MIT代码](https://github.com/yuh-zha/AlignScore) | 分块对齐、逐句聚合 | 保留原模型，另测关键限定语漏项；平均分不产生授权 |
| L5 | Jiang等，FLARE，EMNLP2023：[论文](https://aclanthology.org/2023.emnlp-main.495/)，[MIT代码](https://github.com/jzbjyb/FLARE) | 按需回取证据 | 原实现依赖token概率；当前Harness接口未证实兼容，不能称完整移植 |
| L6 | Asai等，Self-RAG，ICLR2024：[论文](https://arxiv.org/abs/2310.11511)，[代码](https://github.com/AkariAsai/self-rag) | 检索、生成和支持度反思 | MIT代码不替代底模权重许可；不以普通提示词冒称完整复现 |

最接近工作必须正面比较：[MemIR，2026预印本](https://arxiv.org/abs/2605.25869)已有证据、线索、声明分型与来源限定使用；[MemoRepair，2026预印本](https://arxiv.org/abs/2605.07242)已有撤回屏障、保留支持修复、验证与闭包选择。因此来源字段、先撤回再重建、闭包筛选均不足以单独构成区别。其官方代码与许可尚未核准，不冒称忠实复现。

[Claimify，ACL2025](https://aclanthology.org/2025.acl-long.348/)作为相关工作保留；官方可用开源实现未核实，本轮排除为直接移植模块。第三方同名实现不视为官方。

## 三个候选的改动溯源

| 候选 | 源机制 | 拟改动S 尚未实现 | 原样保留 | 必须观察到的新差异 |
|---|---|---|---|---|
| C1 允许证据的限定语完整片段选择 | L1或L2的覆盖选择 | 在允许集合内以角色、否定、条件、时间、目的构成不可拆原句包，按交付token预算选择 | 覆盖求解器、原文offset核对、S0硬授权 | 同候选池、同长度与总预算下，比普通配额原句保留更多关键限定语并提高合法完整回答 |
| C2 覆盖检查与授权引文补入 | L3或L4支持核验＋预算选择 | 分开测事实支持和关键内容覆盖；缺项时有界替换或补入仍允许的原句包 | 原检查器、底座模型、S0授权 | 独立标注下减少关键漏项，优势不能只来自记忆更长或检测器自评分 |
| C3 有界合法证据回退 | L5或L6的按需取证框架 | 区分证据缺失与证据未利用，回退前重新核权 | 原文检索与重新回答框架 | 同总费用优于总是Max或总回退合法原文；先作为强基线 |

这些S是拟新增接口，尚无实际代码行号或验证结果，不填写虚构的已实现位置。C3的一般形式已有RAG方法，不默认能单独写成方法论文。

## 下一轮真实实验及否证标准

1. 先恢复原生 WorkBuddy HY3→宿主撤销S01迁出许可→合法R→Harness 的完整时序，记录实际输入和新会话；模型文本不改变授权。
2. 固定新的开发故事，生成阶段不提供问题或答案。比较合法原文、一次全局每源配额原句、逐来源缓存、C1；所有初始生成和失败都计成本。
3. 同一候选池、实际交付token上限、模型、思考参数与总预算下，分别统计关键限定语保留、合法完整/部分/UNKNOWN、控制披露、未完成及费用。
4. 只胜未配额全局、不胜普通配额原句，或只靠更多调用/更长记忆取胜，均否掉C1的独有优势主张。
5. 只有存在稳定的残缺但受支持现象，才加入C2；由独立源标签评分，不让核验器同时充当真值。
6. 小规模先判断是否值得扩大，随后按独立故事划分新检查集。重复同一故事、增加测试项或提高模型预算不增加独立证据。

当前新颖性和增益量级都缺实证，按手册应记“无法判断”，不以一个总分推断SCI分区或录用。只有具体机制差异经公平对照仍成立，才形成论文主张；否则保留负结果并继续收窄。
