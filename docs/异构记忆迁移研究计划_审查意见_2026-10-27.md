# 异构智能体记忆迁移研究计划审查意见

审查日期：2026-10-27。

**结论：这份计划适合作为新的可行性研究候选，暂不适合直接按“两周开发新算法”执行。** 它仍属于 Agent 记忆安全迁移主线，但研究焦点改为“目标资源受限时，在不新增未授权读取的前提下，尽量保住完整任务所需的信息”。这不会自动修复上一条敏感检测路线的漏检和模型误拒。

文档对既有成果、负结果和论文创新的表述总体克制，主要引用的核心内容可以核实。当前最需要补的不是再接一个模型，而是：证明资源限制确实存在，修正与旧工程不同的评价语义，并补上更贴近任务组合目标的成熟算法。

本次只读核查正文、源码和公开来源，未运行模型、第三方算法或原生实验，未修改原 DOCX 或工程代码，未恢复自动研究。审查不包含 Word 排版验收。本文为独立审查记录。

## 3. 必须先处理的五个问题

### 3.1 K 的现实依据尚未成立

K 是“最多能使用多少个授权分组”，不是模型上下文长度，也不是搜索算法能走多少步。

当前代码中的两数据集限制来自研究夹具：

- [Cognee worker](https://github.com/Caixianseng/memory-migration-permission-pilot/blob/ff49beab15b3e2fbb873b3c0a897e4652a9d680e/scripts/native_cognee_projection_worker.py#L155)在创建前自行检查 `len(self.datasets) < 2`。
- [WebUI worker](https://github.com/Caixianseng/memory-migration-permission-pilot/blob/ff49beab15b3e2fbb873b3c0a897e4652a9d680e/scripts/native_webui_projection_worker.py#L305)使用固定逻辑数据集和事实数量。

这不证明 Cognee 或 Open WebUI 只能支持两个分组。组织管理预算可以构成研究约束，但需要说明预算的来源、计算单位及成本依据。若目标逐条 ACL 已能低成本完整表达原授权，就应先采用完整映射，不能人为收紧 K 来制造算法收益。

建议增加一页“目标能力与成本证据表”：实际权限粒度、隐式读者、是否可建主体专属组、对象是否可跨组引用、复制是否产生物理副本、创建/维护成本、约束是产品规定还是组织约定。仿真参数与真实限制分列。

### 3.2 原 A/B/C/D 例子缺少不可合并依据

文档将其标成“互不兼容分组的模拟实例”，因此不能直接判为数学错误；问题在于没有给出这些分组为何不能合并。

静态反例：如果同一主体 p 对 A、B、C、D 都有权，目标允许建立只含 p 的组，组内容量无限，也没有额外复制限制，那么四条记忆可以放进同一个组。此时 K=2 并不会迫使系统只选 A/B 或 A/C。

现有 [role_cover.py](https://github.com/Caixianseng/memory-migration-permission-pilot/blob/ff49beab15b3e2fbb873b3c0a897e4652a9d680e/memory_migration_study/role_cover.py#L74)的小主体域包含单主体组，随后可以把该主体有权的多个对象放入同一组。

进一步，在对象可复制、每主体专属组可表达、组容量无限、隐式读者也获准的条件下，至多主体数量个专属组即可保留全部合法读取关系。K 小于主体数才可能造成此类压力，且兼容主体可共组时仍可能无损完成。这是条件性论证，不是产品测量。

应改成包含明确主体—记忆矩阵、全部允许候选及真实限制的实例。不能删除合法的单主体组，或只给新方法有利的候选池。说明例只能展示目标函数差异，不能当实际优势。

### 3.3 旧 role_cover 不是新目标的现成基线

[原算法接口](https://github.com/Caixianseng/memory-migration-permission-pilot/blob/ff49beab15b3e2fbb873b3c0a897e4652a9d680e/memory_migration_study/role_cover.py#L17)没有 K、任务权重或任务需求集合。它在完整保留可部署对象合法关系的前提下，最小化容器和放置成本。

`max_search_states`是计算预算；搜索用完后仍保留完整覆盖方案，不会为减少容器而丢掉合法关系。相关语义在[算法注释](https://github.com/Caixianseng/memory-migration-permission-pilot/blob/ff49beab15b3e2fbb873b3c0a897e4652a9d680e/memory_migration_study/role_cover.py#L111)及对应测试中明确。

比较时至少区分：
1. 原版完整覆盖成本优化，报告是否满足 K。
2. 同 K 的任务无关部分覆盖适配版，明确适配内容。
3. 同 K、同任务信息的标准任务感知方法。
4. 待提出的方法。

不能简单截取旧计划前 K 个容器来充当主要强基线；也不能把完整映射超预算后的“未执行”模型任务写成实测答错。

### 3.4 新旧“合法关系损失”分母不同

旧 [plan_verifier.py](https://github.com/Caixianseng/memory-migration-permission-pilot/blob/ff49beab15b3e2fbb873b3c0a897e4652a9d680e/memory_migration_study/plan_verifier.py#L27)依据源、接收方、目标三组读取规则建立 expected；导出许可在实际放置时另查。因而一条禁止导出的记忆仍可能出现在旧口径的 missing 中。

新文档将 E 定义为满足迁移限制的合法关系。如果直接复用旧 missing 指标，会把遵守“禁止导出”的结果误解释为优化器造成的可迁移关系损失。

建议版本化并同时保留：
- 原始读取关系。
- 经独立策略判定可迁移的关系。
- 导出禁止、授权未知、身份映射失败等不可执行原因。
- 已具备迁移资格、但因预算或算法选择丢失的关系。

E 必须在算法运行前独立冻结。不能再把因 K 不够、候选生成漏掉或算法失败而没有保留的关系从分母删掉。旧实验和真值保持原样，新合同单独编号。

### 3.5 “不可复制”与“不得缩小受众”不能混用

当前完整覆盖规划中，`copy_allowed=False`时只接受与完整合法读者集合相等的组，见 [role_cover.py:88](https://github.com/Caixianseng/memory-migration-permission-pilot/blob/ff49beab15b3e2fbb873b3c0a897e4652a9d680e/memory_migration_study/role_cover.py#L88)。独立检查器实际禁止的是同一来源出现多个目标副本，见 [plan_verifier.py:72](https://github.com/Caixianseng/memory-migration-permission-pilot/blob/ff49beab15b3e2fbb873b3c0a897e4652a9d680e/memory_migration_study/plan_verifier.py#L72)。

在旧完整覆盖目标下，这种规划限制合理；在允许部分保留的新目标下，“只保存一份，供部分合法读者读取”可能完全安全。继续强制完整读者集合，会人为排除安全可行解。

需要分别表达：最多目标副本数、是否允许缩小接收群体、是否要求完整保留受众。不能借一个 copy_allowed 字段同时表达三种约束。这是新任务接口适配问题，不应据此宣称旧算法有越权漏洞。

更重要的遗漏在传统组合优化，而非又一个 Agent 框架：

- **集合并背包 SUKP**：任务有收益，完成任务需要若干资源，共享资源只计一次成本。在需求由唯一候选提供、每任务只有一组充分需求等简化条件下，与本计划很接近。[原始论文](https://onlinelibrary.wiley.com/doi/abs/10.1002/1520-6750%28199410%2941%3A6%3C833%3A%3AAID-NAV3220410611%3E3.0.CO%3B2-Q)
- **Densest k-Subhypergraph**：再将成本和收益设为单位值，选择 K 个资源使最多任务需求集合被完整包含，对应选 K 个顶点保留最多完整超边的结构。[正式论文](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.APPROX-RANDOM.2016.6)
- **I2PLS / E2LS**：已有集合并背包方法采用成组选择、增量共享成本、局部搜索与扰动。文档的“补齐任务收益／新增资源＋局部替换”尚不足以与这些机制区分。[I2PLS](https://arxiv.org/abs/1903.04966)、[E2LS](https://arxiv.org/abs/2207.00749)

一般授权角色存在替代覆盖、不同目标表达能力和复制约束，因此不能把整个项目直接等同于 SUKP；但必须交代上述特例关系，并加入相应强基线。本次没有确认 I2PLS/E2LS 作者代码可直接运行，不应预先写成已完成复现。

当前检索未证明有人已经完整解决文档中的一般模型，也未证明该模型具备首创性。

## 6. 建议把研究问题写成可验证的合同

设 E 为迁移前独立冻结的可迁移合法读取关系，S 为所选分组及条目放置方案，T(S) 为该方案在目标端产生的有效读取关系，包括隐式读者。

硬约束为：T(S) ⊆ E；实际分组数不超过 K；副本、接收者和目标表达能力均满足独立合同。未知和执行失败单列，不能默认允许。

任务 q 可以有多个独立充分需求集合 D。只有至少一个 D 的关系全部包含在 T(S) 中，才算该任务的信息被完整保留。目标为：

```text
F(S) = Σq wq · 1[存在 D∈Dq，使 D⊆T(S)]
```

wq 是迁移前合法可得的任务权重，不是根据测试结果调出来的权重。以上是任务信息保留目标，实际Agent任务正确率须另测。

不能直接套普通最大覆盖的贪心保证：任务必须同时得到 A、B 时，在空集加入 B 的收益为0，而已经得到 A 后加入 B 的收益为1，边际收益反而上升。存在多组替代充分信息时，也不能笼统认定整个目标一定属于另一种简单函数类别。

建议把三层信息隔开：

1. **规划可见信息**：明确授权、公开目标能力、迁移前任务描述或历史工作负载估计。
2. **仅评分信息**：测试答案、人工充分集、泄漏标记、完整裁定。
3. **理想信息上界**：允许看真实需求的离线求解结果，单独标注，不能与普通方法不公平比较。

GateMem的[评价协议](https://github.com/rzhub/GateMem/blob/a983828b3bb7565e16e25ac8cdc2fc1982633b0b/docs/evaluation_protocol.md)将 query_type、expected_action、judge_spec、leak_targets 等作为评分信息。把这些字段直接转成依赖再交给优化器，只能用于理想上界。

现有 [tasks.py](https://github.com/Caixianseng/memory-migration-permission-pilot/blob/ff49beab15b3e2fbb873b3c0a897e4652a9d680e/memory_migration_study/tasks.py#L154)的 required_fact_source_ids 也处在评价标签侧，不能直接改名后变成无泄漏的规划输入。

## 7. 建议调整基线和推进顺序

至少保留以下对照，候选空间、任务信息、时间和资源口径一致：

1. 原生逐条精确ACL映射；可信当前源网关另列部署条件。
2. 现有完整覆盖成本优化；预算不可行如实报告。
3. 同K的普通关系覆盖，以及使用相同任务统计的加权关系覆盖。
4. 标准任务成组贪心、同预算局部搜索，及可适配的SUKP强方法。
5. 小实例OR-Tools或独立穷举参考。
6. 只有存在明确不同机制时，才新增“本方法”一组。

同一固定候选池比较用于隔离选择算法；额外比较候选生成器时，要计入候选生成耗时、候选缺失与资源开销。精确参考若已在预期规模快速解决问题，就应认真考虑采用它，而非人为放大规模来制造启发式优势。

不建议直接照两周表启动全部模块。改为按证据过门槛：

- **先确认问题成立**：K/成本约束有依据；完整ACL、单主体组或现有网关不能以相同条件直接无损完成；示例没有人为缺候选。
- **再确认模型和评价正确**：冻结新E、复制和受众语义、任务输入来源；证明小实例检查器与独立最优参考一致。
- **最后才比较新机制**：成熟任务感知方法仍有稳定不足，才考虑新算法。随后才加入更多独立故事、原生接口与模型实验。

这些是审查建议，不是已启动的执行任务。两周可作为可行性排查的时间盒，不是论文完成承诺。

## 8. 立项与论文判断

当前最合适的定位是：

> 研究受限目标环境中的安全授权投影与任务信息保留，先检验真实资源约束及成熟优化方法的适用性，再判断是否需要新的算法机制。

仍然是 Agent 记忆安全迁移；但要形成 Agent 场景的研究价值，需要真实任务依赖、异构权限表达和原生执行证据。仅在普通授权矩阵上人为添加任务，再把“权限”改称“记忆”，贡献可能仍只是传统角色挖掘的场景包装。

只有在上述门槛成立后，才值得检验诸如多种充分信息路径与受限放置的联合选择、需求估计偏差下的稳定任务保留等更具体假设。这些也只是待查新、待比较的候选，不是已确认创新。
