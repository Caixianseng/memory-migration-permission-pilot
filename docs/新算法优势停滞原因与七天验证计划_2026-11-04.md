# 新算法优势停滞原因与七天验证计划

日期：2026-11-04。本文回应“为什么一直没有新算法优势，说明理由并给出计划”。本轮只核对证据、文献和制定方案，没有新增模型调用，没有改动已冻结的实验或评分。

## 1. 先纠正结论口径

11月4日这轮没有实施D1新算法对照，执行的是B0—B3基线和客户端资格。因此，当前准确结论是“拟议新算法尚未接受直接检验；简单基线在当前两个开发故事上已表现良好”，不能写成“D1已经失败”。历史上确实有算法移植和候选筛选，但不能把不同故事、不同模型和不同指标拼成某个统一D1的失败次数。

此前执行把方法试验入口收窄得过度。11月2日完整方案已允许两种贡献：修复强基线的缺陷；或者在相当安全与任务质量下减少完整资源。后续又要求“确需提前生成且逐来源缓存存在跨来源关系损失”，使部分可能的成本研究一直无法进入试验。应恢复原来的成本—效用研究口径，同时保留公平比较。

本计划的改变是：在有明确应用工作负载和候选机制的条件下，可以进行有上限的探索性新方法试验。进入试验不等于宣布创新成立。无须先等到安全基线越权，亦不能以平均效用抵消一次已证实的非法交付。

## 2. 五个可核实原因

| 原因 | 当前证据 | 对研究的含义 |
|---|---|---|
| 主要投入仍在实现与核验 | 本轮先完成SDK加载、真实源生成、宿主撤权、跨客户端资格；正式矩阵仅两故事 | 工程基础有用，但需要开始直接检验候选机制 |
| 当前任务出现正确率上限 | B1/B2/B3的合法完成度主判均16/16；B3有一题措辞保留 | 新方法在这些题上无法再提高正确率，只能检查成本、时延或其他事先定义的指标 |
| 原文短，摘要没有形成足够收益 | B1六次目标总输入4042 tokens，平均约674 tokens（含提示和问题）；B2为3838，B3为4276 | 当前不支持“原文放不下”或“摘要明显省传输”的说法；B3甚至更长 |
| 原文完整生命周期费用最低 | B1上界0.010852元、B2为0.041752、B3为0.028236；B2/B3目标侧费用本身也未低于B1 | 差异约为B1的3.85倍、2.60倍；当前观察没有支持用更多复用次数即可摊薄出优势 |
| 工作负载过于单一 | 两故事均四来源；固定S01支持Q3、S04无关；三反事实权限视图、共享一次生成 | 没有测真实连续交接、权限事件频率、成组变化、冷热来源和源端重建成本的交叉影响 |

前期也有类似证据：11月2日容量测量中，完整SDK请求最大8068字节，低于代码保护上限24000字节。这里的字节上限不是模型token窗口。该结果否定当时四个短故事存在已证实的输入压力，不能据此否定其他规模，也不能擅自缩小上限来制造算法优势。

历史上并非完全没有试算法。例如10月29日LTT与原top1在有限检查中同为8/8，B/F状态正确但比索引队列重算慢；10月30日补回标题使合法题改善，但候选与普通完整授权上下文实际等价。这些结果分别说明“原简单决策已经足够”“复杂维护开销偏大”“补回原始信息”，都不是同一个D1多次失败。依据：[算法逐项移植评估](算法逐项移植与效果评估_2026-10-29.md)、[来源上下文优化结果](期刊方法适配与来源上下文优化结果_2026-10-30.md)。

依据：[本轮主实验报告](阶段收尾_记忆撤权安全交付_2026-11-04.md)、[既有创新筛选与容量实测](创新点筛选_按手册重新核查_2026-11-02.md)、[11月2日完整执行方案](权限变化记忆迁移_创新验证与落地执行方案_2026-11-02.md)。

## 3. 新方向只保留一个

**问题：在权限会连续变化、记忆会被多次交接的过程中，怎样选择记忆的分组方式，在合法任务质量相当时降低初建、重建和交付的总成本？**

候选暂称D1“撤权变化与语义关联共同决定的初始记忆分组”。它延续现有授权边界分组与局部重建方向，当前只是待检验假设。第一版每个生命周期只规划初始分组一次，不声称实现在线动态重分组；事件后仅检查原组的当前合法子集、失效并按需重建。

通俗例子：八份资料中，A、B经常共同用于解释一个流程，且通常一起获得或失去迁出许可；C虽与A主题接近，却经常单独撤权。把A、B放在一组可能减少重复信息，把C单独放置可能减少它撤权时连带失效的范围。但是，普通按权限分组或按撤权风险分组也可能已足够，必须实际比较。

暂不修改授权规则。共同看过多份业务来源的黑盒输出，仍继承实际输入全集的约束。撤权后先禁止受影响产物交付，只有合法来源可进入重建；已经发出的明文不属于可追回范围。

### 3.1 最小算法，先能被否证

第一版只改变“如何分组”，所有分组方法共用同一按需重建器和相同宿主核权流程。按需重建指：产物失效后先停止交付，直到有合法任务需要该组时，才从当前允许来源重建；同一权限与来源版本下可以复用合法缓存。

规划器输入：来源ID、长度、当前许可、开发材料中的权限变化统计，以及当前有权使用的来源特征。不能读取封存问题答案、未来权限事件或任何撤权来源的旧摘要来补充新组提示。

候选操作：

1. 从每来源单独一组开始。
2. 估计合并两组后，初建、重复交付、可能重建的费用变化，以及跨来源关系保留的收益或损失。
3. 使用开发集固定的权重，贪心合并预计能降低总成本、且未违反质量与容量要求的组；同时允许拆开不稳定大组。
4. 运行时只依据已发生的事件失效缓存；重建输入只包含该组当时有权迁出的来源，封存后再次核权。
5. 无足够信息或收益预测不成立时，保留单源/普通分组或合法原文路径，并计入实际成本。

目标可写为：最小化完整初建成本、所有实际重建成本、所有实际交付成本与规划开销之和；同时满足当前授权和预登记的合法任务质量要求。首版不声称全局最优或理论近似保证。八来源的4140种集合分区可用于小规模代价模型枚举诊断；这种“模型内最优”不能冒充真实语义效用最优。

若规划器使用语义特征，这是相对旧元数据规划器的新输入，需登记。特征须逐来源提取并绑定权限；初始规划只用当时允许特征，事件后重建不重新引入已撤来源特征。任何全来源分析理由都不得写入单组生成提示，否则会重新引入全来源业务依赖。当前安全范围仍是显式业务载荷和授权执行，不声称已经证明控制流或分组结构无侧信道。

### 3.2 必须与已有研究区分

| 已有工作 | 已经覆盖的机制 | 对本项目的要求 |
|---|---|---|
| [Collaborative Memory，2025预印本](https://arxiv.org/html/2505.18279v1) | 动态权限、记忆来源、读写过滤 | “记忆带权限并在读取时核权”不构成新的算法主张 |
| [SISA / Machine Unlearning，IEEE S&P 2021](https://arxiv.org/html/1912.03817v3) | 分片限制影响范围，还讨论按撤回概率分片 | 按撤权频率分组必须作为强对照；记忆重建与模型参数遗忘的保证不能互换 |
| [MemoRepair，2026预印本](https://arxiv.org/html/2605.07242v1) | 先撤下后修复、保留支持重建、前驱闭包与最小割成本选择 | “增量修复”“成本感知修复”本身已不是空白；候选区别只能落在生成前分组的具体决策及实证价值 |
| [Maintaining Views Incrementally，SIGMOD 1993](https://doi.org/10.1145/170036.170066) | 数据库变化下的派生结果维护与删除后重推导 | 普通依赖失效与局部重算应复用，不包装成原创 |

本次只完成上述近邻的定向核查，不等于全面新颖性检索。特别是SISA与MemoRepair已经覆盖候选的大部分基础思想，D1能否形成方法贡献仍须看联合规则是否超过这些简单适配。

## 4. 公平对照和真正要改的实验

| 对照 | 作用 |
|---|---|
| 合法完整原文＋确定性复用 | 保留当前最强的低成本对照；允许缓存已获授权的原文 |
| 合法原文＋普通检索 | 当前权限过滤后使用BM25等普通检索；检索参数只在开发集调，完整计其开销 |
| 整体摘要＋同版缓存＋按需重建 | 避免把“每次都重建”的低效实现当唯一基线 |
| 单源卡＋缓存 | 对应已实现B3，保留初始构建和无效卡的历史成本 |
| 固定大小分组＋按需重建 | 使用相同组数或长度上限，检查收益是否只来自选择了更合适的组大小 |
| 普通授权组＋按需重建 | 按当前授权集合/业务分区分组；检查常规工程是否已经足够 |
| 撤权风险分组＋按需重建 | SISA思想的文本侧适配，明确不是原SISA训练算法的完整复现 |
| 语义分组＋按需重建 | 检查改善是否仅来自主题或关系聚合 |
| D1联合分组＋按需重建 | 同时使用语义关联与权限变化结构，除此之外尽量保持相同 |

B0整块阻断保留作机制展示，不作为新算法胜出的主要对象。MemoRepair式修复选择若实际纳入，须保持相同已生成图和候选收益定义；在固定图固定目标上，不能以启发式优于其精确最小割为预设结论。本轮优先隔离分组因素，后处理重建策略对各组相同。

必须从“一次生成、几个反事实状态”改成“真实事件序列”：每故事八个来源，五个状态时点，至少包含不变、单来源撤销、组内共同撤销、重新授权等已登记事件。每个评分点使用新的接收上下文；旧产物与缓存按时间真实存在，失效与重建费用按实际发生记录，不能用三状态均摊代替真正复用。

权限事件是可信宿主的受控模拟，需要明确标注；公开对话本身不带真实企业授权。主工作负载来自许可已核实的公开对话或项目材料，另外保留受控合成机制案例。来源规模与任务需求在看到算法结果前确定。完整原文始终作为可用对照；人工设置的小交付上限只作为资源压力实验，并与未限额结果分开。

工作负载至少覆盖三种情况：短输入/少次使用、较长输入/多次使用、权限变化频繁。必须保留候选可能更差的第一种情况。共同撤销、随机独立撤销和与开发分布不一致的事件，分别报告，不能只选正好符合规划器预测的序列。

## 5. 七天内的具体交付

七天目标是给候选一个明确裁决，不是保证完成投稿或得到正结果。人工复核与技术工作并行；未回收的人工结果保持未测，不用AI代填，也不把等待人工作为停止所有机制实验的理由。

| 时间 | 实际任务 | 交付与验收 |
|---|---|---|
| 第1天 | 冻结服务合同、计费口径、工作负载与近邻差异；从现有来源池登记6个新开发故事 | contract.json、cases.jsonl、events.jsonl；来源/许可/时间/接收者/版本完整；明确哪些是真实材料、哪些是受控事件 |
| 第2天 | 实现可插拔group planner、共享lazy rebuild、按版本缓存；完成D1最小原型与风险/语义/授权分组 | 只改规划与重建触发接口，复用现有Host和SDK；合并/拆分后真实输入绑定正确；不再重复整轮客户端资格 |
| 第3天 | 在6个新开发故事上跑有上限的真实模型筛选；记录五时点实际生命周期，在三个预定时点评分 | 9方法×6故事×3评分点，最多162次目标请求，每次3题；源生成按预登记规则发生并逐项计费 |
| 第4天 | 归因和一次有限修正；比较完整原文、检索、最强分组与D1，固定权重/提示/阈值 | 至多一个候选修订版本；保留初版结果。不能根据封存结果再选基线或改D1 |
| 第5天 | 方法冻结后，准备12个独立检查故事并先核任务参考；启动固定对照 | D1、开发集选出的最强分组/重建基线、完整原文、原文检索四臂；12×3×4=144次目标请求上限，源费用另计；避免只选一种原文方法隐藏成本与质量取舍 |
| 第6天 | 配对结果和关键消融；在预算允许时选预登记子集做HY3源端外部验证 | 去语义项、去权限变化项、静态分组、统一缓存的效果；HY3与Flash源结果单独报告 |
| 第7天 | 结合回收的人工评分与费用重算，形成继续/降级/停止裁决 | effect_report.md、原始响应、可复算表、每故事差值、失败和范围。人审未完成则明确“探索性”，不宣布终验 |

6和12是排程规模，不是发表门槛。三题、多个时点和重复调用均属于同一个故事簇。根据开发阶段差值方差和最终区间宽度决定后续是否扩大；12个检查故事不足以支持宽泛可靠性保证。相似模板、同一公开会话的拆分必须保持在同一分区，不能分别充当开发与独立检查故事。

源模型仍先用同一Flash配置保持可比，目标使用固定Flash版本/设置；HY3是外部有效性补充。先验提示、模型设置、源端可见问题范围对所有方法相同；共同source制品只在完全同一合法输入和版本下复用，费用归属预声明。方法顺序按故事与状态分块随机，失败不擅自补成功。

## 6. 费用与样本计划

执行前沿用账本查询当前余额，扣除待结预约和已发生费用；每个实际请求通过长度及预算预检。个人账户余额保留本机。此次计划本身没有消耗模型额度。

建议分段最高额度：调用长度与成本标定0.5元、开发比较3元、封存检查4元、重复与必要故障排查1元，总计最多8.5元，并以届时可用余额减未结预约为更低硬限。其余用于风险余量；这是阶段上限，不是必须花完的金额。HY3费用接口未知时保持空值，单独限制逻辑任务数，不将其成本换算成Harness免费额度。

162/144是目标请求计划位置，源端生成和重建不可忽略。先用真实长度预检完整调用表；这些数量不承诺全部能在8.5元内完成。若预计超预算，优先采用预登记的小试：2个开发故事筛选、4个新故事机制检查，后者按4臂×3评分点共48次目标请求，所有五时点维护费用仍计入；其余新故事留待方法值得扩样时使用。该小试只支持探索裁决。不能先跑完偏向某方法的臂；资格已通过的SDK与HY3路径直接复用，不因希望得到正结果自动追加调用。

## 7. 怎样判定值得继续

硬安全项沿用现有合同：任何实际交付不得包含当前禁止来源依赖，旧包与版本变化必须正确处理。若出现违反，先定位修复并单独保留失败；该次结果不能靠更高问答分数抵消。

研究主指标为每故事完整生命周期费用与合法任务完成度的配对关系；辅助报请求数、输入输出tokens、交付字节、重建次数、规划耗时、时延分布、误拒、无依据回答和处理失败。既有54/54属于AI复核开发结果，不作新实验的金标。

探索性继续条件建议预登记为：相对最强公平基线，总成本至少下降20%，同时合法完成度下降不超过5个百分点，且在至少两类工作负载上出现同方向差异；或者同预算下显著改善合法完成度。20%和5个百分点是工程筛选阈值，后续应由应用要求和不确定性论证，不是统计显著性或SCI录用条件。报告原始差值与按故事配对的区间，不用“多数点赢了”替代统计证据。

新算法是否有独有价值，还要看：去掉语义项或权限变化项是否削弱效果；SISA式风险分组、普通授权组或合法原文检索是否已达到同样效果。若简单方法表现相当，选择简单方法并撤回D1贡献主张。

止损规则：七天后若优势只来自更长记忆、更多调用、额外参考答案、人为过小预算、单一挑选的权限序列，或仍被合法原文/检索完整支配，则停止该候选扩展。保留可复核的工程与负结果，与导师讨论评价研究或另一个明确研究问题，不再用新增客户端和更多工程测试代替候选裁决。

## 8. 实施位置

当前冻结目录 `experiments/revocation_rebuild_controlled_20261104` 保留作基线证据。新建 `experiments/revocation_grouping_v1`，主要文件拟为：

- `workload_contract.json`：来源类型、五时点事件、三个评分点、单位和预算；
- `group_planner.py`：统一接口 `plan(allowed_sources, past_event_stats, config)`，不传未来事件、问题答案；
- `rebuild_cache.py`：正文、源版本、许可状态和转换配置绑定的缓存与按需重建；
- `lifecycle_runner.py`：真实顺序事件、独立接收上下文、实际模型回执与费用；
- `evaluate.py`：独立授权参照、人工字段与配对成本—效用表。

这五个文件在本文交付时尚未实现。第一版的目标是迅速完成可反驳的真实对照。只有结果支持具体差异后，才把候选上升为论文方法。
